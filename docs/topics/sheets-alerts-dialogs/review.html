The simple idea

Think of it like this

Imagine reading a book at your desk.

When you need to look up a word, you pull out a small dictionary card. It sits on top of your page.

When you finish reading the definition, you slide the card away. Your book is right where you left it.

That card is a sheet.

If someone rings the fire alarm, you stop everything. You must make a choice immediately before doing anything else.

That emergency prompt is an alert.

In SwiftUI, modal views slide or pop over current screen content to complete a focused task.

Unlike navigation links that push new pages into a stack, modals temporarily interrupt the user.

  1. Sheets:
    • Slide up as card overlays from the bottom of the screen.
    • Users can swipe down to dismiss them.
    • Support custom heights using .presentationDetents.
  2. Full-screen covers:
    • Cover the entire screen without card margins.
    • Ideal for modal flows like onboarding or camera capture.
  3. Alerts & Dialogs:
    • Alerts display urgent messages in the center of the display.
    • Confirmation dialogs present a list of choices sliding up from the bottom.

Interview traps

Trap Attaching multiple sheets to one view

Do not attach two .sheet(isPresented:) modifiers to the same VStack or container.

Only one sheet can be active at a time, and SwiftUI will fail to show one or both.

Use a single .sheet(item:) driven by an enum to display different modal sheets cleanly.

Trap Using optional data with sheet(isPresented:)

If a sheet relies on an optional model variable, using sheet(isPresented:) can cause crashes.

When the sheet begins closing, the parent may set the model to nil while the view is still animating.

Use .sheet(item: $model) instead. SwiftUI guarantees the item stays valid during dismissal.

Trap Missing navigation bar inside sheets

A presented sheet does not inherit the navigation bar of the parent view.

Modals exist in their own separate presentation window context.

If you want a title bar or Done button inside a sheet, embed a NavigationStack inside the sheet.

Trap Preventing accidental sheet dismissal

Users can swipe down to dismiss sheets on iOS.

If your sheet contains unsaved form data, the user can accidentally lose progress.

Attach .interactiveDismissDisabled(hasUnsavedChanges) to block the swipe gesture when needed.

How to answer in the interview

Fresh answer

"In SwiftUI, sheets slide up from the bottom of the screen for tasks like forms or settings. Alerts show popups in the middle of the screen for confirmations. We trigger them using @State boolean or item variables, and dismiss them with @Environment(\.dismiss)."

Junior answer

"We choose modal styles based on user intent. We use .sheet for secondary tasks with presentation detents, .fullScreenCover for camera flows, and .alert for critical prompts. Using .sheet(item:) is safer than .sheet(isPresented:) because it safely unwraps data payloads and prevents dismissal crashes."

Senior answer

"Modal presentations introduce isolated view trees. We manage modal routing using enum coordinators and Identifiable state objects. We embed a NavigationStack inside sheets when deep subflows are required. For sensitive forms, we pair .interactiveDismissDisabled with dirty-state checks to prevent accidental swipe dismissals."

Recap

  • Present card overlays using .sheet and full-display overlays using .fullScreenCover.
  • Prefer .sheet(item:) over .sheet(isPresented:) for data-driven modal views.
  • Control sheet heights on iOS 16+ using .presentationDetents([.medium, .large]).
  • Present popups using .alert and action menus using .confirmationDialog.
  • Assign button roles like .destructive and .cancel for native system styling.
  • Dismiss any modal view from inside using @Environment(\.dismiss).
