1. Hardcoded Dependency (Anti-Pattern)

The consumer instantiates a concrete network service directly inside its own initializer or methods. This tightly couples the consumer to network hardware and makes isolated unit testing impossible.

// Anti-pattern: tightly coupled\nclass WeatherViewModel {\n let service = LiveWeatherService()\n}
Step 1: Hardcoded Dependency: Without dependency injection, an object creates its collaborators internally, preventing test doubles.
Step 2: Protocol Contract: A protocol defines the public operations required by the consumer, breaking the hard dependency.
Step 3: Initializer Injection in Production: The composition root passes the real LiveWeatherService into the consumer initializer.
Step 4: Mock Injection in Testing: Unit tests pass MockWeatherService through the exact same initializer without network side effects.
