Interview question

When you change a view frame or Auto Layout constraint in UIKit, why does layoutSubviews not run immediately?

The simple idea

Think of it like this

Think of a postal worker collecting outgoing mail from office desks.

If the worker ran to the post office every time one person finished a letter, they would waste all day running back and forth.

Instead, workers drop outgoing letters into a collection box.

At three in the afternoon, the postal worker collects all letters in the box and delivers them in one efficient trip.

In UIKit, setNeedsLayout() is dropping a letter into the collection box.

It marks the view dirty but does not move views right away.

At the end of the run loop cycle, UIKit processes the whole box during one single layout pass.

UIKit avoids calculating positions on every property change.

Recalculating positions repeatedly would freeze animations and waste battery power.

Instead, UIKit groups layout requests together using the main run loop.

The update cycle splits into three distinct phases: updating constraints, arranging subviews in the layout pass, and drawing pixels in the display pass.

Understanding this cycle lets you write smooth custom views and animate constraints correctly.

Building a custom view subclass

To build a custom view, subclass UIView.

Implement both init(frame:) for programmatic use and init?(coder:) for storyboards.

Override intrinsicContentSize when your view has a natural size based on its contents.

import UIKit

class CustomBadgeView: UIView {
    var title: String = "" {
        didSet {
            setNeedsLayout()
        }
    }

    override var intrinsicContentSize: CGSize {
        CGSize(width: 120, height: 40)
    }

    override func layoutSubviews() {
        super.layoutSubviews()
    }
}

let badge = CustomBadgeView(frame: CGRect(x: 0, y: 0, width: 120, height: 40))
badge.title = "Verified"
print("Intrinsic width: \(badge.intrinsicContentSize.width), height: \(badge.intrinsicContentSize.height)")

OutputIntrinsic width: 120.0, height: 40.0

When internal content changes, call invalidateIntrinsicContentSize() so Auto Layout recalculates container constraints.

Controlling the layout pass with setNeedsLayout and layoutIfNeeded

UIKit provides two complementary methods to request layout updates.

Call setNeedsLayout() to flag a view as dirty.

This call returns immediately and waits for the next run loop cycle.

Call layoutIfNeeded() to force an immediate synchronous layout pass if the view is marked dirty.

import UIKit

class LayoutCycleSimulator {
    var isDirty = false
    var layoutPassCount = 0

    func setNeedsLayout() {
        isDirty = true
    }

    func layoutIfNeeded() {
        if isDirty {
            layoutPassCount += 1
            isDirty = false
        }
    }
}

let sim = LayoutCycleSimulator()
sim.setNeedsLayout()
sim.setNeedsLayout()
sim.layoutIfNeeded()
print("Executed layout passes: \(sim.layoutPassCount), Dirty: \(sim.isDirty)")

OutputExecuted layout passes: 1, Dirty: false

Multiple calls to setNeedsLayout() coalesce into a single layout pass.

When animating constraint changes, update the constraint constant, then call view.layoutIfNeeded() inside UIView.animate.

Quick check (not scored)

Why should you never call layoutSubviews() directly in your code?

layoutSubviews is invoked by the UIKit layout engine. Use setNeedsLayout for deferred updates or layoutIfNeeded for immediate layout.

Interview traps

Trap

Never call layoutSubviews() directly. Call setNeedsLayout() to schedule a pass or layoutIfNeeded() to force an immediate update.

Trap

When overriding layoutSubviews(), always call super.layoutSubviews(). Omitting this call prevents Auto Layout from positioning subviews properly.

Trap

Mutating constraints inside layoutSubviews() triggers another layout pass. Without careful guards, this mistake leads to infinite layout loops and app freezes.

Quick check (not scored)

How do you smoothly animate an Auto Layout constraint change in UIKit?

Updating the constraint and calling layoutIfNeeded() inside the animation closure forces UIKit to animate the resulting frame changes.

How to answer in the interview

Mid answer

In UIKit, layout occurs in three phases: constraints update, layout pass, and render pass. When view properties change, we call setNeedsLayout() to mark the view dirty. UIKit coalesces these requests and calls layoutSubviews() at the end of the run loop. If we need an immediate layout, such as inside a UIView.animate block, we call layoutIfNeeded(). When creating custom views, we implement init(frame:) and init?(coder:), override intrinsicContentSize, and call super.layoutSubviews() when overriding subview layouts.

Senior answer

UIKit optimizes performance through a run loop coalescing mechanism. The update cycle consists of constraint resolution via updateConstraints(), frame calculation via layoutSubviews(), and drawing via draw(_:). Calling setNeedsLayout() is asynchronous and sets a dirty flag, allowing multiple layout invalidations to batch into a single pass. Conversely, layoutIfNeeded() is synchronous, immediately executing layoutSubviews() if the dirty bit is set. This distinction is critical for Auto Layout animations: we alter constraint constants outside the animation block and call parentView.layoutIfNeeded() inside UIView.animate to interpolate frame geometries. When subclassing UIView, we guard against mutating constraints inside layoutSubviews to prevent recursive re-entrancy. We also override intrinsicContentSize and call invalidateIntrinsicContentSize() to participate cleanly in parent Auto Layout passes.

Recap

UIKit groups layout passes at the end of the run loop to avoid redundant calculations. Call setNeedsLayout() to flag views dirty and layoutIfNeeded() to force immediate layout. Override layoutSubviews() for custom frame positioning and always call super.layoutSubviews(). Never call layoutSubviews() directly. To animate constraints, update constants and invoke layoutIfNeeded() inside UIView.animate. Use intrinsicContentSize to define natural dimensions for custom views.
