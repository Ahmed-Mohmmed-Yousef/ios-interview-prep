Interview question

Can a parent view in SwiftUI force a child view to have a specific size?

Your guess first (not scored). We come back to it in the recap.

The simple idea

Think of it like this

Imagine a tailor offering clothes to a customer.

The tailor offers a coat of a certain size. The customer tries on the coat and decides whether it fits. Finally, the tailor positions the coat onto the customer shoulders.

In SwiftUI, the parent view is the tailor, and the child view is the customer. The parent proposes, but the child decides.

SwiftUI builds layouts using a clear three-step negotiation process:

  1. Step 1: Parent Proposes a Size:
    • The parent view offers an available width and height to its child view.
  2. Step 2: Child Chooses Its Size:
    • The child inspects its own content, images, or constraints.
    • The child tells the parent its final chosen size.
    • A parent cannot force a size on a child against its will.
  3. Step 3: Parent Positions the Child:
    • The parent places the child inside its coordinate space.

To compose layouts, SwiftUI provides three fundamental stack containers:

  • VStack: Arranges views vertically from top to bottom.
  • HStack: Arranges views horizontally from left to right.
  • ZStack: Layers views on top of each other from back to front.

You can also use a Spacer view. A Spacer is a flexible view that expands to consume all empty space along the primary axis of a stack.

Interview traps

Trap Assuming .frame() clips child content automatically

Applying .frame(width: 50, height: 50) on a view does not clip content that overflows the frame.

The frame defines proposed dimensions and layout boundaries. Any text or graphics larger than the frame will bleed outside.

To cut off overflowing graphics, always chain the .clipped() modifier right after the frame.

Trap Expecting Spacer to have a fixed size

A Spacer is greedy. It will expand to consume all available remaining space along its stack axis.

If an interview task asks for a fixed gap between two views, do not use an empty Spacer.

Use the spacing parameter on the stack, or apply .padding() to create exact point distances.

Trap Misunderstanding ZStack drawing order

In a ZStack, views declared earlier appear behind views declared later.

If you place an interactive button first and a solid background color second, the color covers the button completely.

Always declare background layers first and foreground content last.

Trap Confusing frame alignment with stack alignment

Stack alignment positions children relative to each other along the cross axis.

Frame alignment positions a child within the bounds of its own proposed container box.

Confusing the two leads to unexpected view positions when building custom layouts.

How to answer in the interview

Fresh answer

"SwiftUI layout follows a three-step process: the parent proposes a size, the child determines its own final size, and the parent positions the child. To place views, we use stacks: VStack for vertical layouts, HStack for horizontal layouts, and ZStack for layering views back to front. A Spacer expands along the stack axis to push neighboring views apart."

Junior answer

"SwiftUI avoids layout loops by guaranteeing a single layout pass. In an HStack or VStack, SwiftUI divides space by offering it to the least flexible children first. Once unconstrained views take their required size, remaining space is offered to flexible views like Spacer or flexible text. We can influence this space distribution using .layoutPriority(_:), which allocates space to high-priority children first."

Senior answer

"Unlike UIKit Auto Layout, which resolves systems of linear equality and inequality equations via the Cassowary solver, SwiftUI uses a purely functional layout tree. Sizing proposals flow downward, and resolved sizes flow upward in $O(n)$ linear time. When building complex responsive screens, we combine stacks with .frame(maxWidth: .infinity) and custom alignment guides. For multi-element grids requiring cross-axis geometry synchronization, we implement custom layout engines conforming to the Layout protocol."

Recap

  • SwiftUI layout has 3 steps: parent proposes size, child decides size, parent positions child.
  • VStack arranges views vertically; HStack arranges views horizontally.
  • ZStack layers views back-to-front in the order they are declared in code.
  • Spacer expands to consume all available space along the primary axis of a stack.
  • Frames do not clip content by default; use .clipped() to cut off overflowing graphics.
  • Modifying .layoutPriority allows specific views to claim space before sibling views.
