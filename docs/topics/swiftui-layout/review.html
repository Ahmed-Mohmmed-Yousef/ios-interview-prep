Interview question

Can a parent view in SwiftUI force a child view to have a specific size?

Your guess first (not scored). We come back to it in the recap.

The simple idea

Think of it like this

Imagine a tailor offering a coat to a customer.

The tailor offers a coat of a certain size. The customer tries on the coat and decides if it fits. Finally, the tailor places the coat on the customer.

In SwiftUI, the parent view is the tailor, and the child view is the customer. The parent proposes a size, and the child decides its own final size.

SwiftUI builds layouts using a clear three-step process:

  1. Step 1: Parent proposes a size:
    • The parent view offers an available width and height to its child view.
  2. Step 2: Child chooses its size:
    • The child checks its own content or rules and chooses its final size.
    • A parent cannot force a size on a child against its will.
  3. Step 3: Parent positions the child:
    • The parent places the child inside its space.

To group views, SwiftUI gives you three main stack containers:

  • VStack: Stacks views vertically from top to bottom. Use VStack(alignment: .leading) to align children to the leading edge, and omit spacing to use the platform default gap.
  • HStack: Places views side by side from left to right.
  • ZStack: Layers views on top of each other from back to front.

You also have two helpful layout views:

  • Spacer: Expands to fill all empty space along the main direction of a stack.
  • Divider: Draws a thin separating line across a stack (horizontal inside a VStack, vertical inside an HStack).

Here are three more layout tools you will use often:

  • Fill available width: Apply .frame(maxWidth: .infinity) to let a view stretch across all width its parent offers.
  • Align text lines: Use HStack(alignment: .firstTextBaseline) to line up text views of different font sizes along the bottom of their first text line.
  • Control tight space: Stacks offer space to the least flexible views first, then share what is left among flexible views. Use .layoutPriority(_:) (higher than the default 0) when one child must claim space before its siblings.

Interview traps

Trap Assuming .frame() clips child content automatically

Calling .frame(width: 50, height: 50) on a view does not cut off content that is larger than the frame.

The frame sets a proposed size and layout box. Any text or shape bigger than the frame will spill outside the edges.

To cut off overflowing content, chain .clipped() after .frame(...).

Trap Expecting Spacer to have a fixed size

A Spacer is greedy. It expands to take all empty space left along the stack's main direction.

If you need an exact fixed gap between two views, do not use an empty Spacer.

Use the spacing parameter on the stack, or use .padding(), to set exact point gaps.

Trap Misunderstanding ZStack drawing order

In a ZStack, views written earlier sit behind views written later.

If you write a button first and a solid background color second, the color hides the button and blocks taps.

Always put background layers first and foreground controls last.

Trap Confusing frame alignment with stack alignment

Stack alignment lines up sibling views with each other across the stack.

Frame alignment places one child view inside its own frame box.

Mixing up the two causes views to land in the wrong spot when you combine frames and stacks.

How to answer in the interview

Fresh answer

"SwiftUI layout works in three steps: the parent proposes a size, the child picks its own final size, and the parent places the child. We arrange views using VStack for vertical layouts, HStack for horizontal layouts, and ZStack to layer views back to front. A Spacer expands along the stack's main direction to push nearby views apart."

Junior answer

"SwiftUI avoids layout loops by computing layout in a single pass: proposals go down and chosen sizes come back up. Inside an HStack or VStack, SwiftUI offers space to the least flexible children first. After rigid views take what they need, flexible views like Spacer or wrapping text share the rest. We can use .layoutPriority(_:) to let important views claim space first."

Senior answer

"Unlike UIKit Auto Layout, which uses a constraint solver to balance equations, SwiftUI uses a single-pass functional layout tree. Size proposals flow downward and resolved sizes flow upward in linear time. For responsive layouts, we combine stacks, .frame(maxWidth: .infinity), and custom alignment guides. When a screen needs custom geometry across multiple axes, we can build a custom Layout type."

Recap

  • SwiftUI layout has 3 steps: parent proposes size, child decides size, parent positions child.
  • VStack arranges views vertically; HStack arranges views horizontally.
  • ZStack layers views back to front in code order.
  • Spacer expands along the stack's main direction; Divider draws a thin separating line.
  • Frames do not clip overflowing views by default; add .clipped() when you need clipping.
  • Use .layoutPriority(_:) to let a view claim space before sibling views.
