Trees: BFS and DFS

You need to find the shortest path from the root node to a leaf in a binary tree. Which traversal should you pick?

Your guess first (not scored). We come back to it in the recap.

The simple idea

A tree organizes data in a parent-and-child hierarchy. The top node is the root. Every other node has one parent and zero or more children.

Think of it like this

Think of an organization chart. The company chief is the root. Managers report to the chief. Team members report to managers.

In coding interviews, you often need to visit every node in a tree. You have two main search tools:

  1. Depth-first search (DFS) walks deep down one branch before it backtracks.
  2. Breadth-first search (BFS) walks wide, checking all nodes on one level before moving down.

DFS uses a stack. In Swift, recursion uses the system call stack. You can also make your own stack with an array.

BFS uses a queue. It explores nodes in first-in, first-out order.

DFS comes in three standard orders:

  • Pre-order (Root, Left, Right): Visit the parent before its children. Good for copying or serializing a tree.
  • In-order (Left, Root, Right): Visit the left child, then the parent, then the right child. In a binary search tree, this visits values in sorted order.
  • Post-order (Left, Right, Root): Visit children first, then the parent. Good for bottom-up tasks like calculating subtree height.

See it

In code

Here is a standard binary tree node class in Swift. We implement pre-order and in-order depth-first search.

final class TreeNode {
    var val: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ val: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.val = val
        self.left = left
        self.right = right
    }
}

func preOrder(_ node: TreeNode?) -> [Int] {
    guard let node = node else { return [] }
    return [node.val] + preOrder(node.left) + preOrder(node.right)
}

func inOrder(_ node: TreeNode?) -> [Int] {
    guard let node = node else { return [] }
    return inOrder(node.left) + [node.val] + inOrder(node.right)
}

let root = TreeNode(4,
    left: TreeNode(2, left: TreeNode(1), right: TreeNode(3)),
    right: TreeNode(5)
)

print("Pre-order: \(preOrder(root))")
print("In-order: \(inOrder(root))")

OutputPre-order: [4, 2, 1, 3, 5]
In-order: [1, 2, 3, 4, 5]

Next, here is breadth-first search. We visit the tree level by level using a queue.

final class TreeNode {
    var val: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ val: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.val = val
        self.left = left
        self.right = right
    }
}

func levelOrder(_ root: TreeNode?) -> [[Int]] {
    guard let root = root else { return [] }
    var levels: [[Int]] = []
    var queue: [TreeNode] = [root]

    while !queue.isEmpty {
        let count = queue.count
        var current: [Int] = []

        for _ in 0..<count {
            let node = queue.removeFirst()
            current.append(node.val)
            if let left = node.left { queue.append(left) }
            if let right = node.right { queue.append(right) }
        }

        levels.append(current)
    }

    return levels
}

let root = TreeNode(1,
    left: TreeNode(2, left: TreeNode(4), right: TreeNode(5)),
    right: TreeNode(3, right: TreeNode(6))
)

print(levelOrder(root))

Output[[1], [2, 3], [4, 5, 6]]

Quick check (not scored)

Which traversal order visits values in ascending order when used on a valid binary search tree?

In-order visits left child, root, then right child. Because all left values are smaller and right values are larger, in-order yields sorted order.

Quick check (not scored)

What is the space complexity of recursive depth-first search on a balanced binary tree with N nodes?

The call stack holds at most the height of the tree. A balanced tree of N nodes has height log N.

Interview traps

Trap

If every node has only a right child, the tree looks like a linked list. Recursive DFS takes O(N) space. In production, deep recursion can cause a stack overflow crash.

Trap

Calling removeFirst() on a Swift Array shifts all remaining elements. This makes your BFS algorithm O(N squared) in total time. In an interview, explain this trade-off. Mention that an index pointer or a real double-ended queue keeps queue operations O(1).

How to answer in the interview

Mid answer

I pick BFS when I need the shortest path or need to group nodes level by level. I use a queue and snapshot its count before processing each tier. I pick DFS when I need to explore complete branches or compute subtree metrics bottom-up. In-order traversal on a binary search tree visits nodes in sorted order.

Senior answer

I evaluate tree width versus depth when choosing space trade-offs. For very wide trees, BFS memory grows to O(N) at the leaf level, whereas DFS memory is capped at tree height O(H). For deep or unbalanced trees, I write an iterative DFS with an explicit array stack to prevent stack overflow crashes. In Swift, I also note that Array removeFirst is O(K), so high-throughput BFS should use an index pointer or Deque.

Recap

Use DFS (pre-order, in-order, post-order) to walk deep branches with a stack. Use BFS to explore level by level with a queue. In-order DFS on a binary search tree yields sorted keys. BFS finds shortest paths in unweighted trees. Remember that recursive DFS takes O(H) stack space and BFS takes O(W) queue space.
