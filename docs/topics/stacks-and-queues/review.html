The simple idea

Think of it like this

Imagine a stack of cafeteria trays next to a cafeteria line.

When a clean tray arrives, workers place it on the top of the pile. When a customer takes a tray, they pick the top one. This is a stack (Last In, First Out).

Now imagine customers waiting in line at the cash register. The first customer to join the line is the first one served. This is a queue (First In, First Out).

Both stacks and queues are linear collections with restricted access points:

  1. Stack (LIFO):
    • Elements are added and removed from the exact same end (the top).
    • In Swift, standard Array acts as an efficient stack with append(_:) and popLast().
    • Used in bracket validation, browser history, navigation stacks, and depth-first searches.
  2. Queue (FIFO):
    • Elements are inserted at the back and removed from the front.
    • Used in breadth-first search, background task dispatching, and printer queues.
  3. Complexity Requirements:
    • Both data structures require $O(1)$ constant time for insertion, deletion, and peeking.
    • Removing the first element of an Array shifts all elements left, taking $O(n)$ time.
    • Production apps use ring buffers, two stacks, or Apple's official Deque package to achieve true $O(1)$ queues.

In code

In this classic interview problem, opening brackets are pushed onto the stack.

When a closing bracket arrives, we pop the most recent opening bracket. If the bracket types do not match or the stack is empty, the string is invalid.

At the end of the loop, stack.isEmpty ensures no unclosed opening brackets remain.

This two-stack queue achieves amortized $O(1)$ dequeuing.

Elements enter inbox in $O(1)$ time. When outbox is empty, elements are popped from inbox and pushed into outbox.

This reverses their order, aligning the oldest element with outbox.last. Each element moves between stacks at most once, guaranteeing amortized $O(1)$ operations.

Interview traps

Trap Using Array.removeFirst() as a queue in interview questions

Calling removeFirst() on an Array shifts all subsequent elements by one index to the left.

This operation runs in $O(n)$ linear time. Dequeuing $n$ items creates an accidental $O(n^2)$ quadratic bottleneck.

Always mention this performance issue in interviews and use a two-stack queue, ring buffer, or Deque.

Trap Calling removeLast() on an empty stack

Calling removeLast() on an empty Array causes a runtime fatal error.

Instead, use popLast(), which returns an optional Element?.

This allows safe unwrapping without risking unexpected application crashes on empty collections.

Trap Forgetting to check stack.isEmpty at the end of bracket validation

Input strings containing only opening brackets, like "(((", never trigger mismatches during iteration.

If you return true immediately after the loop, invalid unclosed strings will pass as valid.

Always verify that stack.isEmpty returns true before confirming full validation success.

Trap Confusing monotonic increasing and decreasing stack conditions

Monotonic stacks store elements in strictly sorted order to find next greater or smaller elements.

To find the next greater element, maintain a decreasing stack. Smaller items are popped when a greater item arrives.

Reversing this comparison condition breaks the monotonic property and produces incorrect indices.

How to answer in the interview

Fresh answer

"A stack follows LIFO (Last In, First Out) semantics, while a queue follows FIFO (First In, First Out). In Swift, we use standard Array with append and popLast for an $O(1)$ stack. For queues, calling removeFirst() takes $O(n)$ time because elements shift in memory. To achieve $O(1)$ queues, we use two stacks or Apple's Deque collection."

Junior answer

"I choose a stack for problems requiring backtracking or matching, such as Valid Parentheses or DFS navigation. For breadth-first search and order-preserving pipelines, I use a queue. To avoid the $O(n)$ cost of Array.removeFirst(), I implement queues using two stacks or a ring buffer. The two-stack queue provides amortized $O(1)$ operations because each element transfers between arrays only once. In production, I import Apple's official swift-collections package for Deque."

Senior answer

"Stacks and queues are fundamental to iOS system architecture, from the UINavigationController view controller stack to GCD serial dispatch queues. In performance-critical streaming pipelines, using Array.removeFirst() ruins throughput due to repeated memmove operations. I evaluate memory layout and cache locality: contiguous ring buffers prevent cache misses, while node-based linked queues introduce pointer indirection and ARC overhead. For high-volume production apps, Apple's Deque provides ring-buffered contiguous chunks with $O(1)$ mutations at both ends."

Recap

  • Stacks operate on LIFO order; Array.append and Array.popLast run in $O(1)$ time.
  • Queues operate on FIFO order; Array.removeFirst takes $O(n)$ time due to memory shifts.
  • Two-stack queues achieve amortized $O(1)$ dequeue performance by reversing inbox elements into outbox.
  • Bracket matching requires checking stack.isEmpty after scanning to catch unclosed brackets.
  • Apple's official Deque from swift-collections provides production-grade $O(1)$ queue operations.
