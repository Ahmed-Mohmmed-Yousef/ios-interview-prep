1. Real Production Dependency

In production, the System Under Test connects to real network APIs or disk storage. Running tests against live services causes network flakiness, latency, and unpredictable failures.

// Production: slow and non-deterministic\nlet sut = ProfilePresenter(repo: LiveAPIRepository())
Step 1: Production Service: Real network clients introduce latency and test flakiness.
Step 2: Stub Double: Returns pre-programmed canned data immediately for state verification.
Step 3: Spy Double: Records call counts and passed parameters for behavior verification.
Step 4: Fake Double: Provides a working in-memory shortcut that behaves like a database without disk I/O.
