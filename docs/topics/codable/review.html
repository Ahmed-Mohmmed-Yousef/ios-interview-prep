The simple idea

Think of it like this

Think of shipping luggage on an airplane. When you pack your suitcase, you fold your clothes into flat boxes that fit onto cargo belts. When you arrive at your destination, you unpack those boxes back into clothes in your closet. Codable works the same way: it folds Swift objects into portable JSON data, and unpacks JSON data back into Swift objects.

In Swift, Codable is a typealias combining two protocols: Encodable and Decodable.

Encodable types can serialize themselves into external representations like JSON. Decodable types can deserialize external data into Swift types.

When all stored properties inside a struct conform to Codable, the Swift compiler synthesizes the decoding and encoding code automatically.

Real-world API data often uses snake_case keys like first_name, while Swift style uses camelCase like firstName.

You bridge this gap with CodingKeys. A nested CodingKeys enum maps external JSON string keys directly to Swift property names.

For advanced formats, you can implement custom decoding with init(from decoder: Decoder) to provide default fallbacks for missing fields.

Interview traps

Trap Omitting properties from custom CodingKeys

When you write a custom CodingKeys enum, you must include every stored property you want encoded or decoded. If you omit a property, the compiler will not synthesize decoding for it.

Trap Mixing convertFromSnakeCase with explicit snake_case raw values

If you set keyDecodingStrategy = .convertFromSnakeCase and also write case fullName = "full_name" in CodingKeys, the decoder applies conversion twice. Choose either automated strategy conversion or explicit CodingKeys, not both.

Trap Failing to handle dates with proper dateDecodingStrategy

By default, JSONDecoder expects dates as floating point numbers representing seconds since 2001. If your API sends ISO8601 date strings, you must configure decoder.dateDecodingStrategy = .iso8601.

How to answer in the interview

Fresh answer

Codable is a Swift protocol that combines Encodable and Decodable. We use it with JSONDecoder and JSONEncoder to convert Swift structs to and from JSON. If JSON keys do not match our property names, we use CodingKeys to map them.

Junior answer

Codable is a typealias for Encodable and Decodable. When all stored properties conform to Codable, Swift automatically synthesizes serialization and deserialization methods. We can customize key mappings with a nested CodingKeys enum, or set keyDecodingStrategy to convertFromSnakeCase on the decoder. For custom logic or default values on missing fields, we implement custom init(from decoder:) using decodeIfPresent.

Senior answer

Codable provides compile-time type-safe serialization without reflection overhead. It decouples domain models from external serialization formats like JSON, Plist, or Protobuf. In production networking layers, we configure JSONDecoder with ISO8601 date strategies and snake_case strategies. To build resilient apps, we implement custom decoding containers and handle DecodingError cases gracefully so unexpected remote payload changes do not crash client flows.

Recap

  • Codable is a typealias combining Encodable and Decodable.
  • The compiler automatically synthesizes conformance when all stored properties conform to Codable.
  • A nested CodingKeys enum maps external JSON keys to Swift property names.
  • JSONDecoder and JSONEncoder parse and serialize data with strict type checking.
  • decodeIfPresent allows safe fallbacks for optional or missing JSON fields.
  • keyDecodingStrategy and dateDecodingStrategy automate common formatting conventions.
