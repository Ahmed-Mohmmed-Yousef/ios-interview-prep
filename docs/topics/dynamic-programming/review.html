The simple idea

Dynamic programming is an optimization technique. It solves problems by combining answers to smaller subproblems.

Think of it like this

Write 1 + 1 + 1 + 1 on a notepad. What does that equal? Four. Now add another "+ 1" to the end. You do not recount from zero. You remember four and add one to get five.

Dynamic programming requires two key properties:

  • Optimal Substructure: The best solution to the main problem comes from optimal solutions to smaller subproblems.
  • Overlapping Subproblems: The recursive solution computes the same smaller answers repeatedly.

There are two common ways to write dynamic programming solutions:

  • Top-Down with Memoization: Start with the final goal and recurse down. Store answers in a dictionary or array so each subproblem is computed once.
  • Bottom-Up with Tabulation: Start from the base cases. Build a table iteratively until you reach the target answer.

Bottom-up tabulation avoids recursion call stack overhead. Often, you only need the previous one or two values. This lets you reduce memory from $O(N)$ to $O(1)$ space.

In iOS apps, dynamic programming appears in collection diffing, text layout measurement, and caching expensive data computations.

See it

In code

Here is how to solve the classic climbing stairs problem using bottom-up dynamic programming with $O(1)$ memory.

func climbStairs(_ n: Int) -> Int {
    guard n > 2 else { return n }
    var prev2 = 1
    var prev1 = 2

    for _ in 3...n {
        let current = prev1 + prev2
        prev2 = prev1
        prev1 = current
    }
    return prev1
}

print("Ways to climb 4 steps: \(climbStairs(4))")
print("Ways to climb 5 steps: \(climbStairs(5))")

OutputWays to climb 4 steps: 5
Ways to climb 5 steps: 8

Next, here is the coin change problem. We find the fewest coins needed to make a target amount using an array table.

func coinChange(_ coins: [Int], _ amount: Int) -> Int {
    guard amount > 0 else { return 0 }
    let maxVal = amount + 1
    var dp = Array(repeating: maxVal, count: amount + 1)
    dp[0] = 0

    for i in 1...amount {
        for coin in coins {
            if i - coin >= 0 {
                dp[i] = min(dp[i], dp[i - coin] + 1)
            }
        }
    }

    return dp[amount] > amount ? -1 : dp[amount]
}

let coins = [1, 2, 5]
print("Fewest coins for 11: \(coinChange(coins, 11))")

OutputFewest coins for 11: 3

Quick check (not scored)

What distinguishes dynamic programming from standard divide-and-conquer algorithms like merge sort?

In merge sort, the two halves never overlap. In dynamic programming, recursive branches evaluate the exact same subproblems repeatedly.

Quick check (not scored)

Why is bottom-up tabulation often preferred over top-down recursion with memoization in production code?

Deep recursion can exhaust thread stack space on iOS devices. Tabulation uses an iterative loop with predictable memory usage.

Interview traps

Trap

When solving for an amount or target N, indices run from 0 to N. If you create an array of count N, accessing dp[N] crashes with index out of range.

Trap

In problems like Fibonacci, Climbing Stairs, and House Robber, you only need the previous two states. Storing the entire array wastes memory. Keep two rolling variables for O(1) space.

How to answer in the interview

Mid answer

I use dynamic programming when a problem has optimal substructure and overlapping subproblems. I start by defining the state representation, like what dp[i] represents. Then I write the recurrence relation and identify the base cases. I prefer bottom-up tabulation to avoid stack overflow risks, and I optimize space to O(1) when states only depend on the previous two entries.

Senior answer

I evaluate whether top-down or bottom-up is better suited for the state space. Top-down memoization computes only reachable states, which helps when the state space is sparse. Bottom-up tabulation offers better CPU cache locality and zero stack overhead. For 2D grids, I compress memory from O(M times N) down to O(N) using rolling arrays. In iOS, this relates directly to collection diffing algorithms like Myers diff in CollectionDifference.

Recap

Dynamic programming caches answers to overlapping subproblems to eliminate redundant calculations. Identify optimal substructure, define base cases, and establish the recurrence relation. Choose bottom-up tabulation for iterative safety, and roll state variables to achieve O(1) space whenever possible.
