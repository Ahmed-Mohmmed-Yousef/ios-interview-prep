The simple idea

Think of it like this

Imagine a captain steering a cargo ship across the ocean.

If the captain writes down notes on loose paper napkins and throws them on the floor, the bridge becomes a mess. The napkins have no dates, no categories, and anyone can read confidential customer names. Cleaning up the paper napkins takes time and distracts the crew. Using print() statements in code is like throwing loose napkins on the floor.

Instead, the captain maintains an official ship logbook. Every entry has a timestamp, an exact department tag, and a severity level. Routine notes stay in daily records, while emergency alerts trigger sirens. Confidential passenger details are hidden from view. Apple's OSLog is your official ship logbook.

In iOS development, OSLog replaces print() and legacy NSLog:

  1. Subsystems and Categories: Group logs by app feature (such as com.prepstops.app and network) for easy filtering.
  2. Log Levels: Categorize messages as debug, info, notice, error, or fault.
  3. Privacy by Default: OSLog automatically hides sensitive strings as <private> in production release builds.
  4. High Performance: String interpolation is deferred. If a log level is disabled, the code never formats the string.

Interview traps

Trap Leaving print statements in production

Calling print() does synchronous disk and console writing on the caller thread. In tight loops or scroll handlers, this causes frame drops and stutters. Furthermore, print() outputs personal user data in plaintext. Always use Logger for production telemetry.

Trap Using NSLog in modern Swift

NSLog is a legacy Objective-C function. It writes synchronously to standard error and adds timestamp overhead. In modern iOS apps, always prefer os.Logger.

Trap Marking sensitive user data as public

Writing \(userPassword, privacy: .public) exposes secrets in device logs. Anyone with device access can view plaintext logs in Console.app. Keep sensitive data private or use hash masking with privacy: .private(mask: .hash).

Trap Choosing the wrong log level

Logging everything at the error level clutters diagnostic reports. Reserving fault for true critical bugs keeps telemetry actionable. Use debug for high-volume logs, info for milestones, and error for handled failures.

How to answer in the interview

Fresh answer

OSLog is Apple's modern logging system for iOS. Unlike print(), which writes plaintext and slows down the app, OSLog is fast and organized. It organizes messages by subsystem and category. It also protects user privacy by hiding sensitive strings as <private> in release builds. We use levels like debug, info, error, and fault.

Junior answer

I use os.Logger for all production logging instead of print(). I organize logs with reverse-DNS subsystems and categories, like com.app.network, so we can filter messages in Xcode and Console.app. OSLog is fast because string formatting is deferred until needed. I choose levels carefully: debug for local diagnostics, info for app milestones, and error or fault for failures. I also use privacy annotations to prevent sensitive customer data from leaking into device logs.

Senior answer

os.Logger provides zero-overhead telemetry because string interpolation is skipped if a log level is disabled. In Swift 6, Logger is Sendable, making it safe across concurrent actor boundaries. By annotating values with privacy: .private(mask: .hash), we maintain auditability without exposing personal identifiable information. For production diagnostics, we also use OSLogStore to extract recent logs in memory and attach them to crash reports and user feedback tickets.

Recap

  • OSLog replaces print() with high-performance, structured telemetry.
  • Organize logs by subsystem (e.g. com.company.app) and category (e.g. auth).
  • The 5 log levels are debug, info, notice, error, and fault.
  • Dynamic strings are private by default in release builds to protect personal information.
  • Annotate values with privacy: .public only when data is safe to view.
  • Filter and stream live logs easily in Xcode Console and macOS Console.app.
