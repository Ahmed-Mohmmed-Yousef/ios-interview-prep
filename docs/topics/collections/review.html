The simple idea

Think of it like this

Think of the three collection types like organizing items in an office. An array is like a numbered list where every line has a fixed order. A set is like a badge reader at a door that checks if a badge exists, with no duplicates and no order. A dictionary is like a coat check where each ticket has a unique name pointing to one coat.

Swift has three main collection types to store groups of values:

  • Array: An ordered list of values. Arrays allow duplicates and look up items by integer index starting at 0.
  • Set: An unordered group of unique values. Sets drop duplicates and check if an item exists in fast O(1) time.
  • Dictionary: An unordered group of key-value pairs. You look up each value by its unique key.

All three collections are value types in Swift. When you declare a collection with let, you cannot add, remove, or replace items in it. Declaring a collection with var lets you change it.

Behind the scenes, Swift uses Copy-on-Write (COW). Assigning a collection to a new variable does not copy all items right away. Copies share the same memory buffer until one copy changes, which saves memory and time.

To store items in a Set or use them as keys in a Dictionary, the type must conform to Hashable. Hashable gives each value an integer hash so Swift can place it in a hash table bucket. Hashable also builds on Equatable (==), so Swift can tell two items apart if their hash numbers ever match. Standard types like String, Int, and Double already conform to Hashable.

Why does subscripting a Dictionary with a key return an optional value?

In code

This example shows key array and set tools:

  • Array indexing and insert(_:at:): Arrays start at index 0. Calling insert(95, at: 1) puts 95 at index 1 and shifts later items right.
  • Safe access: scores.first returns an optional value, so it safely returns nil if the array is empty.
  • Set uniqueness: Building a Set from an array removes duplicate items like "Alex".
  • Set operations and contains(_:): contains(_:) checks if an item exists in O(1) time. intersection(_:) keeps shared items, and union(_:) joins both sets. subtracting(_:) removes items in the other set, and symmetricDifference(_:) keeps items in one set but not both.

This example shows how to work with key-value pairs safely:

  • Optional lookup: Missing keys like "Bananas" return nil without crashing.
  • Default value subscript: inventory[key, default: 0] returns a non-optional value, so you can update counts in one line with +=.
  • Removing entries: Setting inventory["Apples"] = nil removes that key and its value from the dictionary.

Which protocol must a type conform to before it can be stored inside a Set?

Sets use hash values to find items fast, so elements must conform to the Hashable protocol.

Interview traps

Trap Assuming array subscripting returns nil when out of bounds

Unlike dictionaries, reading array[index] with an invalid index causes a fatal crash at runtime. Check array.indices.contains(index) or use .first and .last when an index might not exist.

Trap Relying on Set or Dictionary order

Sets and dictionaries do not keep a fixed order. Looping over a set or dictionary can return items in an order you cannot rely on. When order matters, use an Array or sort the items first.

Trap Searching large arrays with contains instead of sets

Calling array.contains(item) checks items one by one in O(n) time. For large groups with frequent lookups, use a Set so contains(_:) runs in O(1) time.

How to answer in the interview

Fresh answer

Swift has three core collection types: Array, Set, and Dictionary. An Array is an ordered list accessed by integer index and allows duplicates. A Set is an unordered group of unique Hashable items for fast membership checks. A Dictionary stores key-value pairs where keys must be Hashable. Reading a dictionary key returns an optional, while reading an invalid array index crashes at runtime.

Junior answer

All standard Swift collections are value types with Copy-on-Write, so copies stay independent without extra memory copying until one changes. Choosing between them depends on order, uniqueness, and lookup speed. Arrays give O(1) index lookup but O(n) search time. Sets and Dictionaries give amortized O(1) lookups using hash tables. For dictionaries, dict[key, default: value] gives a non-optional value for clean in-place updates.

Recap

  • Arrays store ordered items by zero-based index and allow duplicate values.
  • Sets store unordered unique items and require Hashable (which builds on Equatable).
  • Dictionaries store unordered key-value pairs where keys must conform to Hashable.
  • Reading an invalid array index crashes at runtime; check indices.contains(_:) or .first to stay safe.
  • Subscripting a dictionary returns an optional (nil if missing), and setting a key to nil removes it.
  • Swift collections are value types that use Copy-on-Write (COW) to delay copying until a write happens.
  • Set membership lookup with contains(_:) runs in fast O(1) time.
