The simple idea

Think of it like this

Think of the three collection types like organizing items in an office. An array is like a numbered checklist where every line has a fixed order. A set is like a badge reader at an entrance that only cares if a badge exists, with no duplicates and no order. A dictionary is like a labeled coat check where each ticket has a unique name tag pointing to a specific coat.

Swift provides three primary collection types to store groups of values:

  • Array: An ordered list of elements. Arrays allow duplicate values and access elements using zero-based integer indices.
  • Set: An unordered group of unique elements. Sets reject duplicates and provide fast lookup to test whether an item exists.
  • Dictionary: An unordered collection of key-value pairs. Each value is found by searching for its unique key.

All three collections are value types in Swift. When you declare a collection with let, it is completely immutable. You cannot add, remove, or modify items inside it. Declaring a collection with var makes it mutable.

Behind the scenes, Swift uses Copy-on-Write. Assigning a collection to a new variable does not copy all items immediately. It shares memory until one copy modifies its contents.

To store items in a Set or use them as keys in a Dictionary, the type must conform to the Hashable protocol. Standard types like String, Int, and Double already conform to Hashable.

In code

This example highlights core differences between ordered lists and sets:

  • Array indexing: Arrays use zero-based indices. Accessing scores[1] retrieves the second score.
  • Safe boundary access: The first property returns an optional Element?, which safely returns nil if the array is empty.
  • Set deduplication: Initializing a Set from an array automatically removes duplicate elements like "Alex".
  • Fast membership: Calling contains(_:) on a Set checks for existence in constant $O(1)$ time.

This example shows how to manage key-value pairs safely:

  • Optional lookup: Missing keys like "Bananas" return nil without crashing.
  • Default value subscript: Using inventory[key, default: 0] returns a non-optional value and initializes missing keys directly.
  • Removing entries: Setting a key to nil removes that key-value pair from the dictionary.

Interview traps

Trap Assuming array subscripting returns nil when out of bounds

Unlike dictionaries, accessing array[index] with an invalid index triggers a fatal runtime crash. If you are unsure whether an index exists, check array.indices.contains(index) or use .first and .last.

Trap Relying on Set or Dictionary order

Sets and dictionaries are unordered collections. Iterating through a set or dictionary produces elements in arbitrary order. If order matters, use an array or sort the collection explicitly.

Trap Searching large arrays with contains instead of sets

Checking array.contains(item) scans elements sequentially in $O(n)$ time. For large collections with frequent lookups, use a Set which checks membership in $O(1)$ time.

How to answer in the interview

Fresh answer

Swift offers three core collection types: Arrays, Sets, and Dictionaries. An Array is an ordered list accessed by integer index, allowing duplicates. A Set is an unordered collection of unique elements requiring Hashable conformance, optimized for fast membership tests. A Dictionary stores key-value pairs where keys must be Hashable. Subscripting a dictionary returns an optional because the key might be missing, whereas reading an invalid array index causes a fatal crash.

Junior answer

All standard Swift collections are value types with Copy-on-Write optimization, ensuring thread safety and minimal memory copying overhead. When choosing between collections, we balance ordering, uniqueness, and lookup complexity. Arrays offer $O(1)$ indexed access but $O(n)$ search time. Sets and Dictionaries provide amortized $O(1)$ lookups through hash table bucketing. For dictionaries, Swift offers the default subscript syntax dict[key, default: value] which simplifies in-place mutation and avoids manual nil checks.

Recap

  • Arrays store ordered elements with zero-based indices and allow duplicate items.
  • Sets store unordered unique elements and require Hashable conformance.
  • Dictionaries store unordered key-value pairs, where keys must conform to Hashable.
  • Reading an invalid array index causes a fatal runtime crash.
  • Subscripting a dictionary returns an optional value that is nil if the key is missing.
  • Swift collections are value types that use Copy-on-Write for high performance.
  • Set membership lookup with contains(_:) runs in fast $O(1)$ constant time.
