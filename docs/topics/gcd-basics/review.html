Interview question

What is the difference between a serial queue and a concurrent queue in Grand Central Dispatch?

Your guess first (not scored). We come back to it in the recap.

The simple idea

Think of it like this

Imagine a single toll booth lane on a bridge.

Cars line up in single file. Each car must pay and pass before the next car moves. This is a serial queue.

Now imagine a toll plaza with four open lanes side by side.

Cars enter the plaza in order, but they pay and drive through at the same time. This is a concurrent queue.

Grand Central Dispatch (GCD) is Apple's low-level framework for managing concurrent tasks.

It uses queues (DispatchQueue) to organize work closures across worker threads.

  1. Serial queues:
    • Executes one task at a time.
    • Tasks execute strictly in First-In-First-Out (FIFO) order.
    • A new task waits until the previous task finishes.
    • Ideal for protecting shared data from data races.
  2. Concurrent queues:
    • Starts tasks in FIFO order, but runs multiple tasks simultaneously.
    • The completion order depends on how long each task takes.
  3. Async versus Sync:
    • async schedules a task and returns immediately without waiting.
    • sync schedules a task and pauses the calling thread until the task finishes.
  4. Modern replacement:
    • In modern Swift, Swift Concurrency (async/await and actors) replaces GCD for new code.

Interview traps

Trap Confusing sync with serial

Many candidates think calling sync makes a queue serial.

sync and async control whether the caller waits.

serial and concurrent control whether the queue runs multiple tasks together.

You can call async on a serial queue or sync on a concurrent queue.

Trap Calling sync on the same serial queue

Calling queue.sync from inside a block already running on queue causes an instant deadlock.

The running block cannot finish until the inner block finishes.

The inner block cannot start until the running block finishes. The thread freezes forever.

Trap Thread explosion with too many queues

Creating dozens of concurrent queues can lead to thread explosion.

When many threads block on disk or network locks, GCD spawns new threads to compensate.

Each thread consumes memory and causes CPU context-switching overhead.

Trap Assuming GCD is preferred in new code

Modern iOS codebases prefer Swift Concurrency (async/await and actors) over GCD.

Swift Concurrency uses a cooperative thread pool that avoids thread explosion.

It also provides compile-time data race safety under Swift 6.

How to answer in the interview

Fresh answer

"Grand Central Dispatch uses queues to manage multithreaded work. Serial queues run tasks one after another, while concurrent queues run multiple tasks at the same time. Async schedules work and returns immediately, while sync waits for work to complete. We use background queues for heavy work and dispatch to the main queue to update the UI."

Junior answer

"GCD abstracts thread management using dispatch queues with Quality of Service classes like userInitiated and background. Serial queues are useful for synchronizing access to shared state without manual locks. Calling sync on the current serial queue causes a deadlock. In modern Swift, async/await and actors have largely replaced GCD because they eliminate callback nesting."

Senior answer

"GCD was Apple's foundational concurrency tool, but it suffers from thread explosion when tasks block threads on I/O. In contrast, Swift Concurrency uses a fixed-size cooperative thread pool limited to CPU cores, where tasks suspend rather than block. While GCD requires manual weak self captures to avoid leaks, Swift 6 actors provide compile-time data-race safety. I maintain legacy GCD code when necessary, but migrate new features to structured concurrency."

Recap

  • GCD manages work through serial and concurrent dispatch queues.
  • Serial queues run tasks one at a time in FIFO order.
  • Concurrent queues run multiple tasks simultaneously across worker threads.
  • async returns immediately; sync waits for the task to finish.
  • Calling sync on the current serial queue creates a fatal deadlock.
  • Quality of Service (QoS) priorities guide CPU scheduling and energy use.
  • Swift Concurrency (async/await and actors) replaces GCD for modern development.
