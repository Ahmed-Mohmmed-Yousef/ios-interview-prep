The simple idea

Think of it like this

Think of a security badge holder. The badge inside holds your employee card. When you show your badge, people see your photo. But the plastic holder also has a clip on the back for a lanyard. A property wrapper works like that holder: it protects your data and adds extra features to it.

In Swift, a property wrapper is a layer of code that manages how a property is stored and accessed. You write the storage logic once in a wrapper type. Then you can apply that wrapper to any property with an attribute like @Clamped.

Every property wrapper must declare a wrappedValue property. When you read or write the wrapped property, Swift forwards the call to wrappedValue.

Behind the scenes, the compiler synthesizes a private backing instance. If your property is named score, the compiler creates _score to hold the wrapper instance.

A property wrapper can also declare an optional projectedValue. You access the projected value by adding a dollar sign ($) before the property name.

In SwiftUI, @State uses wrappedValue to give you the data, and uses projectedValue to give you a Binding via the dollar sign.

Interview traps

Trap Using property wrappers on global variables or computed properties

You cannot apply property wrappers to global variables, local top-level script variables, or computed properties. Property wrappers require stored backing properties inside a type declaration.

Trap Confusing the underscore prefix with standard private properties

When you declare @State var count = 0, the compiler creates _count. Accessing count calls the wrapped value, while accessing _count gives you the wrapper struct itself. Do not name other properties with underscores to avoid compiler naming conflicts.

How to answer in the interview

Fresh answer

A property wrapper in Swift is a type marked with @propertyWrapper that manages how a property is stored and accessed. It must have a wrappedValue property. It can also have an optional projectedValue accessed using a dollar sign prefix.

Junior answer

Property wrappers encapsulate reusable property logic, like validation or persistence. The compiler synthesizes a private backing property with an underscore prefix, such as _score. Reading the property accesses wrappedValue. Property wrappers can also define a projectedValue, which is accessed using the dollar sign prefix. This is how SwiftUI provides bindings from @State properties.

Senior answer

Property wrappers allow declarative property behavior through compiler synthesis. They replace repetitive getter and setter boilerplate. By defining init(wrappedValue:), wrappers support inline initial values. Projected values allow types to project auxiliary capabilities, such as SwiftUI projecting Binding from State. Architecturally, we use them for user defaults, clamping, and dependency injection, while watching out for thread safety and memory footprint in value types.

Recap

  • Property wrappers encapsulate reusable property storage and access logic.
  • Defined with the @propertyWrapper attribute on a struct, class, or enum.
  • Every property wrapper must implement wrappedValue.
  • The compiler synthesizes a private backing property prefixed with an underscore (_name).
  • Optional projectedValue is accessed using the dollar sign ($name).
  • SwiftUI relies heavily on property wrappers, including @State, @Binding, and @AppStorage.
