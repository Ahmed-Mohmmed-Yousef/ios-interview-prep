What is the difference between a function and a closure in Swift?

The simple idea

Think of it like this

Think of a function like a printed recipe card with a title written at the top. A closure is like a handwritten recipe instruction written on a sticky note. You can hand that sticky note to a friend to cook right away. Even though it has no formal title, it carries the exact same steps.

In Swift, a closure is a self-contained block of functionality that can be passed around and executed later.

In fact, functions are simply special named closures:

  • Global functions are closures that have a name and do not capture any values.
  • Nested functions are closures that have a name and can capture values from their enclosing function.
  • Closure expressions are unnamed blocks of code written with a clean, inline syntax.

Closures are reference types. When you assign a closure to two different constants, both constants point to the same underlying closure and its captured values.

The standard closure syntax uses curly braces with the in keyword: { (parameters) -> ReturnType in statements }

The in keyword marks where the parameter list ends and where the closure body begins. Swift allows you to shorten this syntax when types can be inferred from context.

  1. Full syntax: names.sorted(by: { (s1: String, s2: String) -> Bool in return s1 < s2 }) declares all types explicitly.
  2. Inferred types: names.sorted(by: { s1, s2 in s1 < s2 }) drops type annotations and the return keyword.
  3. Shorthand arguments: names.sorted(by: { $0 < $1 }) drops named parameters and the in keyword using $0 and $1.
  4. Trailing closure: names.sorted { $0 < $1 } moves the closure outside parentheses for maximum readability.

Quick check (not scored)

What does the in keyword signify in a Swift closure expression?

The in keyword tells the compiler that the parameter and return type definitions are complete, and the execution body begins.

In code

This example shows how Swift simplifies closure syntax step by step:

  • Type inference: Because sorted(by:) expects (String, String) -> Bool, Swift already knows the parameter and return types.
  • Shorthand argument names: $0 and $1 refer to the first and second parameters. When using shorthand names, the in keyword is omitted.
  • Trailing closure syntax: When a closure is the final argument, you can place it outside the function call parentheses.

This example highlights two fundamental behaviors:

  • Value capturing: The returned closure captures the variable count. Even after makeTracker() finishes, count remains alive in memory.
  • Reference types: When counterA is assigned to counterB, both refer to the exact same closure and share the same running count.

Quick check (not scored)

Are closures in Swift value types or reference types?

Closures and functions are reference types in Swift. Multiple variables assigned to the same closure share its captured state.

Interview traps

Trap Mixing shorthand argument names with explicit parameter lists

You cannot mix $0 with explicit parameter names. If you write { name in print($0) }, the compiler produces an error. Use either explicit parameter names or shorthand $0, never both.

Trap Assuming closures are value types like structs

Because closures look like clean functional expressions, candidates often assume they are value types. Closures are reference types. Modifying a captured variable inside one closure reference affects all other references to it.

Trap Unnecessary parentheses when using trailing closures

When a closure is the only argument to a function, you do not need empty parentheses (). Writing names.map() { $0.uppercased() } works, but names.map { $0.uppercased() } is the idiomatic Swift style.

How to answer in the interview

Fresh answer

A closure in Swift is a self-contained block of code that can be stored and passed around. Named functions are actually special cases of closures. Closures use the in keyword to separate parameters from body logic. Swift allows concise syntax using type inference, shorthand argument names like $0 and $1, and trailing closure syntax.

Junior answer

Closures are first-class reference types that can capture and store references to variables from their surrounding context. Swift provides expressive syntax optimizations: type inference eliminates redundant annotations, single-expression closures omit return, and trailing closures allow placing blocks outside parentheses. Because closures are reference types, assigning a closure to multiple variables shares the identical closure instance and captured state.

Recap

  • Functions are named closures; closures can also be written anonymously inline.
  • Standard syntax: { (params) -> ReturnType in statements }.
  • The in keyword separates parameter definitions from the closure body.
  • Swift infers parameter and return types from context when possible.
  • Shorthand arguments $0, $1, and $2 refer to arguments by position.
  • If a closure is the final argument, write it as a trailing closure outside parentheses.
  • Closures are reference types that capture and retain surrounding variables.
