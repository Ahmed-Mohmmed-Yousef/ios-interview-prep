Copy-on-Write and Value Semantics

Interview question

When you assign an array with one million items to a new variable in Swift, does it duplicate the memory immediately?

Your guess first (not scored). We come back to it in the recap.

The simple idea

Think of it like this

Think of sharing a document blueprint with a teammate. You both look at the exact same printed sheet of paper. As long as you only read it, nobody needs another copy. But the moment your teammate wants to sketch new notes, they make a photocopy first. They draw on their copy, leaving your original sheet unchanged.

In Swift, structs are value types. Value types have value semantics, meaning each instance keeps its own independent state. Mutating one variable never alters another.

However, copying a huge array with thousands of items on every assignment would be very slow. It would waste memory and CPU time.

To solve this, Swift uses an optimization called Copy-on-Write (COW).

When you copy a collection, Swift does not duplicate the underlying data in memory. Instead, both variables share the same storage buffer behind the scenes.

The actual duplicate copy happens only when one variable modifies the data. If neither variable mutates the collection, no memory copy ever happens.

Interview traps

Trap Assuming custom structs have Copy-on-Write by default

A common interview mistake is believing that all Swift structs have copy-on-write. They do not. When you assign a custom struct, Swift copies all its stored properties immediately. Only standard collections like Array, Dictionary, Set, and String have COW built in.

Trap Wrapping reference types inside structs without COW logic

If a struct contains a class property and you do not implement COW, assigning the struct copies only the class pointer. Both struct copies will point to the same class instance. Mutating the class will mutate both structs, accidentally breaking value semantics!

How to answer in the interview

Fresh answer

Copy-on-write is an optimization in Swift where collections share the same memory buffer after an assignment. The data is only copied when one of the variables modifies it. This saves memory while keeping value semantics.

Junior answer

Copy-on-write gives value types the performance of reference types while keeping value semantics. Standard library collections like Array and Dictionary use COW. When you assign an array, only the pointer is copied. When you mutate the array, Swift checks if the buffer is uniquely referenced. If shared, it copies the buffer first. Custom structs do not get COW automatically.

Senior answer

Copy-on-write combines value semantics with reference-counted heap buffers for performance. Standard collections manage a private storage class behind a struct wrapper. During mutation, isKnownUniquelyReferenced checks the reference count. If the reference count is one, the mutation occurs in place in O(1) time. Otherwise, a deep copy is allocated. When designing large custom value types, we wrap a private class and use isKnownUniquelyReferenced to prevent unnecessary allocations.

Recap

  • Copy-on-write delays deep memory copying until a shared value type mutates.
  • Value semantics are preserved: modifying one variable never affects another.
  • Standard collections like Array, Dictionary, Set, and String use COW.
  • Custom structs do not have COW automatically.
  • Custom COW is built by wrapping a private class and checking isKnownUniquelyReferenced.
  • Passing collections as inout parameters avoids triggering COW copies during function calls.
