The simple idea

Think of it like this

Imagine a spreadsheet grid of rows and columns.

Each cell has an address like row 2, column 3.

You can move up, down, left, or right to visit neighboring cells.

If you step outside the sheet boundaries, you fall off the page.

A matrix is a two-dimensional grid of rows and columns.

In Swift, a matrix is commonly stored as an array of arrays: [[Element]].

  1. Coordinates and Indexing:
    • matrix[row][col] accesses the element at row index row and column index col.
    • row moves vertically from top 0 to bottom rows - 1.
    • col moves horizontally from left 0 to right cols - 1.
  2. Bounds Checking:
    • Always confirm coordinates are valid before accessing a cell.
    • A valid cell satisfies r >= 0 && r < rows && c >= 0 && c < cols.
  3. Direction Vectors:
    • Moving in 4 directions uses row and column offsets: [(-1, 0), (0, 1), (1, 0), (0, -1)].
    • Direction vectors keep navigation loops clean and readable.

In code

In this example, numIslands scans every cell in the grid.

When it finds an unvisited land cell '1', it increments the island count and calls dfs.

The recursive dfs helper uses direction vectors to visit all four adjacent neighbors.

It marks visited cells as '0' in place to prevent infinite recursion cycles.

This algorithm visits every cell a constant number of times, giving $O(m \cdot n)$ time complexity.

To rotate an $n \times n$ matrix 90 degrees clockwise in place, we use two simple steps.

First, we transpose the matrix along the main diagonal by swapping matrix[r][c] with matrix[c][r].

Second, we reverse each row horizontally.

This achieves a 90-degree clockwise rotation with $O(1)$ auxiliary space.

Interview traps

Trap Swapping row and column coordinates

Writing matrix[col][row] instead of matrix[row][col] is a very common bug.

When the matrix has different row and column counts, this error causes index out of range crashes.

Always remember that the first index selects the row and the second index selects the column.

Trap Accessing empty matrices without guarding

Calling matrix[0].count on an empty array [] crashes your app immediately.

Always check guard !matrix.isEmpty && !matrix[0].isEmpty else { return } at the start of your function.

Handling empty matrices prevents unexpected runtime aborts during edge case tests.

Trap Infinite loops from missing visited marks

During depth-first search or breadth-first search, forgetting to mark visited cells causes infinite cycles.

The algorithm will bounce back and forth between adjacent cells indefinitely.

Always mark a cell as visited before exploring its neighbors.

Trap Transposing non-square matrices in place

Transposing in place by swapping matrix[r][c] and matrix[c][r] only works on square matrices where rows equal columns.

For rectangular matrices where $m \neq n$, in-place transposition changes dimensions and requires a new matrix allocation.

Always ask the interviewer if the matrix is guaranteed to be square.

How to answer in the interview

Fresh answer

"A matrix is a two-dimensional grid of rows and columns, stored as an array of arrays in Swift. I access cells using matrix[row][col]. Before accessing any cell, I always verify that row and column indices stay inside bounds. For grid searches, I use direction vectors to move between adjacent cells cleanly."

Junior answer

"I solve matrix problems using depth-first search or breadth-first search. For problems like Number of Islands, I scan the grid and trigger DFS to sink connected components. I mark visited cells in place to save memory, or use a boolean array. I use direction tuples for 4-directional moves and always guard against empty matrices at the start."

Senior answer

"In production Swift, matrix layout impacts cache locality. Traversing row by row accesses contiguous array buffers, which maximizes CPU cache hits. Column-by-column traversal causes frequent cache misses across separate heap buffers. For graph traversals, I guard against deep recursion stack overflows by switching to iterative BFS with an explicit queue. When performance is critical, I represent matrices as flat 1D arrays with index calculations to eliminate multiple heap pointer indirection."

Recap

  • A matrix in Swift is commonly represented as an array of arrays: [[Element]].
  • Access elements using matrix[row][col], where row is vertical and column is horizontal.
  • Always guard against empty matrices before reading matrix[0].count.
  • Use direction vectors like [(-1, 0), (0, 1), (1, 0), (0, -1)] to navigate neighbors cleanly.
  • Rotate square matrices 90 degrees clockwise by transposing along the diagonal and reversing each row.
  • Mark visited cells during DFS or BFS traversals to prevent infinite cycles.
