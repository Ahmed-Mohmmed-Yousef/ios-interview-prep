The simple idea

Think of it like this

Imagine dining at a busy restaurant.

You speak with a waiter who acts as your messenger to the kitchen.

When you want to see the menu, you make a request. The waiter brings back the food choices without changing the kitchen pantry.

When you place an order for a new sandwich, the kitchen cooks fresh food and adds it to your bill.

If you ask for a table without an invitation badge, the host turns you away because your identity is unknown.

If you have a badge but try to walk into the manager office, the staff stops you because you lack permission.

HTTP is the primary network protocol your iOS app uses to communicate with backend servers.

The client app sends an HTTP Request to the server:

  1. HTTP Method (Verb):
    • GET: Reads data without modifying the server.
    • POST: Creates a new record on the server.
    • PUT: Replaces an entire existing resource with new data.
    • PATCH: Modifies specific fields of an existing resource.
    • DELETE: Removes a resource from the server.
  2. URL and Path: The address of the resource, like /api/v1/users/42.
  3. Headers: Key-value pairs providing metadata, like Content-Type: application/json or auth tokens.
  4. Body: The payload data sent to the server (for example, encoded JSON).

The server processes the request and sends back an HTTP Response:

  • Status Code: A three-digit number describing the result.
  • Headers: Metadata describing the response size, date, and content format.
  • Body: The returned data, such as requested user details or error explanations.

REST is an architectural style for building clean web services.

In REST, URLs use nouns instead of verbs (/articles instead of /getArticles).

REST is stateless. Each request contains all information needed to complete the task.

Interview traps

Trap Confusing 401 Unauthorized with 403 Forbidden

Developers often mix up these two status codes.

401 Unauthorized means the user is not authenticated. The auth token is missing, expired, or invalid.

403 Forbidden means the server knows who the user is, but the user lacks permission to access the resource.

Trap Using verbs instead of nouns in REST URLs

A common design mistake is writing endpoints like /createArticle or /deleteUser.

RESTful design uses nouns for resource paths (/articles, /users/42).

The HTTP method specifies the action (POST, DELETE), keeping URLs clean and predictable.

Trap Returning HTTP 200 OK for errors

Some poorly designed backend APIs return 200 OK with a JSON body saying {"error": "User not found"}.

This breaks standard HTTP caching and prevents network layers from detecting failures automatically.

Always insist that APIs return standard 4xx and 5xx status codes for error conditions.

Trap Assuming PUT preserves missing fields

PUT represents a complete replacement of a resource.

If you send a PUT request with only an updated title, the backend may erase the author and timestamp.

Use PATCH when you want to update only specific fields without touching the rest of the object.

How to answer in the interview

Fresh answer

"HTTP is how our app talks to a server. We send a request with a method, URL, headers, and an optional body. The server replies with a status code, headers, and data. In REST, URLs use nouns like /users, and HTTP methods define the actions. Status codes in the 200s indicate success, 400s are client errors, and 500s are server failures."

Junior answer

"REST relies on stateless communication where each request holds all necessary context. We use HTTP semantics: safe methods like GET never alter server state, while idempotent methods produce identical side-effects when repeated. I also distinguish 401 Unauthorized from 403 Forbidden. I verify that APIs use real HTTP error status codes rather than masking failures in 200 OK responses."

Senior answer

"We design network architectures around HTTP semantics and idempotence. Understanding idempotence allows our app to safely retry failed PUT or DELETE requests across unreliable cellular connections. For POST requests, we attach idempotency keys to avoid duplicate charges. We also handle conditional caching using ETag headers for 304 responses, and apply exponential backoff on 429 rate limit or 503 service unavailable codes."

Recap

  • HTTP requests consist of a Method, URL, Headers, and an optional Body.
  • HTTP responses return a three-digit Status Code, Headers, and a Body.
  • Common methods include GET (read), POST (create), PUT (replace), PATCH (update), and DELETE (remove).
  • Safe methods like GET do not alter server state.
  • Idempotent methods like GET, PUT, and DELETE produce identical server state when repeated.
  • Status codes: 2xx success, 3xx redirection, 4xx client error, 5xx server error.
  • Status 401 means unauthenticated; status 403 means unauthorized (forbidden).
  • REST APIs use nouns for resource endpoints and remain stateless.
