How does SwiftUI allow you to list child views inside a closure without commas or return statements?

The simple idea

Think of it like this

Think of a result builder like an assembly line conveyor belt. Workers place parts on the belt one by one without boxing them up. At the end of the line, a robot picks up all parts and welds them into a single finished car.

In standard Swift code, a function returning an array or combined object requires punctuation. You must insert commas or call an append method repeatedly. You also need an explicit return keyword at the end.

Result builders remove this ceremony. You mark a type with the @resultBuilder attribute. The Swift compiler then rewrites each statement in a closure. It passes every expression into static methods on your builder type. The builder collects the pieces and combines them into one final value.

SwiftUI uses this exact feature for @ViewBuilder. When you write view hierarchies, you list child views line by line. The compiler gathers them into a tuple view behind the scenes.

struct MenuItem {
    let title: String
}

@resultBuilder
struct MenuBuilder {
    static func buildBlock(_ items: MenuItem...) -> [MenuItem] {
        return items
    }
}

func makeMenu(@MenuBuilder content: () -> [MenuItem]) -> [MenuItem] {
    return content()
}

let menu = makeMenu {
    MenuItem(title: "Home")
    MenuItem(title: "Settings")
}

A basic buildBlock handles straight lists of values. Real code often needs control flow like if conditions and for loops. To support if statements, you provide buildOptional and buildEither. To support for loops, you provide buildArray.

Interview traps

Trap Assuming control flow works automatically

Developers often assume standard Swift if conditions or for loops work in any result builder closure by default. A result builder cannot handle branching unless you explicitly implement buildOptional, buildEither, and buildArray. Without them, the compiler rejects the code.

Trap Confusing result builders with Swift macros

Candidates sometimes state that result builders inspect the abstract syntax tree and generate arbitrary code like macros. Result builders are restricted to closure transformation. They only translate expressions into builder method chains. They cannot create new properties or inspect types like macros do.

How to answer in the interview

Fresh answer

A result builder is a Swift feature marked with @resultBuilder. It lets you build complex values by writing items line by line inside a closure. SwiftUI uses it for @ViewBuilder so you can lay out views without commas.

Junior answer

A result builder collects statements inside a closure and combines them into one value. The compiler rewrites the statements into static calls like buildBlock. To support if statements or loops, the builder must also implement buildOptional, buildEither, and buildArray.

Senior answer

Result builders were standardized in SE-0289 in Swift 5.4 to power embedded domain-specific languages. The compiler desugars closure expressions into typed builder method calls like buildExpression, buildBlock, and buildFinalResult. They enable expressive declarative APIs in SwiftUI and custom domain languages with full static type safety.

Recap

  • @resultBuilder marks a type as an embedded domain-specific language builder.
  • The Swift compiler transforms statements inside annotated closures into static builder calls.
  • buildBlock is the primary required method that merges sequential components.
  • buildOptional and buildEither enable conditional logic like if and switch.
  • buildArray enables iteration through for...in loops.
  • buildExpression and buildFinalResult convert inputs and outputs to customized types.
  • SwiftUI relies heavily on @ViewBuilder to construct declarative view hierarchies.
