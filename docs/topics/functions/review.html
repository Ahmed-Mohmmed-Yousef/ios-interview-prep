Why does Swift use separate argument labels and parameter names for function inputs?

Your guess first (not scored). We come back to it in the recap.

The simple idea

Think of it like this

Think of a function like a kitchen blender. It has an opening where you drop food, a button you press, and a spout where the drink pours out. The label on the outside tells the cook what to put in. Inside the machine, the motor uses those parts to make the drink.

In Swift, a function is a named block of code that does one task. You define a function with the func keyword.

Swift functions have several helpful features:

  • Argument labels and parameter names: You write the argument label when calling a function, so calls read like clear English. You use the parameter name inside the function body. Write _ before a parameter name to omit its argument label when calling.
  • Default values: A parameter can have a fallback value, so callers can leave that argument out.
  • Return values and Void: Use -> Type to return a value, or return a tuple like (min: Int, max: Int) to return several values at once. A function with no -> still returns Void, which is an empty tuple ().
  • Variadic parameters: Adding ... after a type (such as Int...) lets a parameter accept zero or more values as an array inside the function.
  • Constant parameters: Function parameters are let constants by default, so you cannot reassign them inside the body.
  • inout parameters: Mark a parameter with inout and pass a var with & to change the caller's variable. Swift uses copy-in copy-out: it copies the value in, changes it, and copies it back out when the function returns.

Functions in Swift are first-class citizens. Every function has a function type such as (Int, Int) -> Int (notice function types do not include argument labels or parameter names). You can store functions in variables, pass them to other functions, or return a nested function from inside another function. Functions that take or return other functions are called higher-order functions.

Interview traps

Trap Assuming parameters are mutable local variables

In languages like C, parameters act like local variables you can change. In Swift, parameters are let constants. To change one, make a local var copy = parameter or use inout.

Trap Passing a let constant into an inout parameter

You cannot pass a let constant into an inout parameter. Because inout copies the updated value back out, the argument must be a var variable.

Trap Omitting required argument labels at the call site

Argument labels are part of the function signature in Swift. Calling buildGreeting("Sarah") fails to compile when for: is part of the signature. Write _ before the parameter name if you want callers to omit the label.

How to answer in the interview

Fresh answer

Functions in Swift start with func and can take parameters and return values, tuples, or Void. Swift separates argument labels (used when calling) from parameter names (used inside the body), so calls read like clear English. Parameters are let constants by default. To change a caller's var, mark the parameter with inout and pass & when calling.

Junior answer

Swift treats functions as first-class citizens with types like (Int, Int) -> Int, without labels in the type. You can store them, pass them into higher-order functions, or return nested functions. Argument labels improve call-site clarity while parameter names keep internal code clean. For inout parameters, Swift uses copy-in copy-out semantics: the value is copied in, updated, and copied back on exit. Single-expression functions can omit return, while multi-statement functions still need it.

Recap

  • Functions start with func, and functions with no -> return Void (()).
  • Argument labels are used when calling; parameter names are used inside the body; _ omits the label.
  • Parameters can have default values, or use ... as variadic parameters to accept zero or more values.
  • Functions can return multiple values with a tuple, and single-expression functions can omit return.
  • Parameters are let constants by default; use inout and & on a var for copy-in copy-out updates.
  • Functions are first-class citizens with types like (Int, Int) -> Int and can be stored, passed, or nested.
