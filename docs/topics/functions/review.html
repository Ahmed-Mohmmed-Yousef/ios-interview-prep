Why does Swift provide separate argument labels and parameter names for function parameters?

The simple idea

Think of it like this

Think of a function like a kitchen blender. It has an input chute where you drop ingredients, a recipe button that you press, and a spout where the blended smoothie pours out. The label on the outside of the chute tells the cook what to put in. Inside the machine, the motor uses those ingredients to make the drink.

In Swift, a function is a self-contained block of code that performs a specific task. You define a function using the func keyword.

Swift functions have unique design features that improve readability and safety:

  • Argument labels vs parameter names: The argument label is used when calling the function to create readable, conversational code. The parameter name is used inside the function body.
  • Default values: Parameters can provide fallback values, allowing callers to omit them.
  • Immutable parameters: By default, function parameters are constant let values. You cannot reassign or modify a parameter inside the function body.
  • In-out parameters: If a function needs to modify an external variable, mark the parameter with inout. When calling, pass the variable with an ampersand &.

Functions in Swift are first-class citizens. This means a function has a type, such as (Int, Int) -> Int. You can store functions in constants, pass them into other functions, or return them as results.

Interview traps

Trap Assuming parameters are mutable local variables

In some languages like C, parameters act as mutable local variables. In Swift, parameters are constants. If you need to modify a parameter, declare a local var copy = parameter or use inout.

Trap Passing an immutable constant into an inout parameter

You cannot pass a let constant into an inout parameter. Because inout modifies the original variable, the argument must be declared with var.

Trap Omitting required argument labels at the call site

Argument labels are part of the function signature in Swift. Calling buildGreeting("Sarah") fails to compile if the label for: was declared. To allow omitting labels, write an underscore _ before the parameter name.

How to answer in the interview

Fresh answer

Functions in Swift are defined with the func keyword and can accept parameters and return values. A distinctive feature is the separation of argument labels from parameter names, making call sites readable like clear English sentences. By default, function parameters are immutable constants. If a function needs to modify an external variable, we declare it with inout and pass the argument with an ampersand.

Junior answer

Swift treats functions as first-class citizens with distinct types like (Int, Int) -> Int. They can be passed as arguments or returned from other functions. Parameter names provide internal clarity, while argument labels optimize call-site expressiveness following the Swift API Design Guidelines. For inout parameters, Swift uses copy-in copy-out semantics: the value is copied in on entry, mutated, and copied back on exit. Single-expression functions benefit from implicit returns.

Recap

  • Functions are declared with func and can return values using ->.
  • Argument labels are used when calling; parameter names are used inside the body.
  • Write an underscore _ to omit an argument label at the call site.
  • Parameters can have default values, making them optional to provide when called.
  • Single-expression functions can omit the return keyword.
  • Function parameters are constant let values by default and cannot be reassigned.
  • Use inout and prefix arguments with & to modify caller variables in place.
  • Functions are first-class citizens with distinct function types.
