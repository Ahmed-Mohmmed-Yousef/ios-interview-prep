The simple idea

Think of it like this

Imagine water flowing from a mountain reservoir through a garden hose to a sprinkler. The reservoir is the Publisher: it produces streams of water over time. The sprinkler is the Subscriber: it receives the water and waters the lawn. The valve on the hose is the Subscription: it controls how much water flows. If you let go of the hose, the spring-loaded nozzle snaps shut at once. That spring-loaded nozzle is AnyCancellable: you must anchor it down, or it shuts off the water immediately.

Combine is Apple framework for processing asynchronous values over time. Introduced in iOS 13, it provides a unified reactive pattern for handling notification events, network responses, and user interface inputs. While newer projects often choose Swift Concurrency, many large production codebases rely heavily on Combine.

Combine rests upon three core concepts:

  1. Publisher: A protocol that emits a sequence of values over time, finishing either successfully or with an error.
  2. Subscriber: A protocol that attaches to a publisher to receive incoming values and completion signals.
  3. Subscription: The active connection between a publisher and a subscriber that manages demand and backpressure.

Managing subscription lifecycles with AnyCancellable

When you attach a subscriber using the .sink operator, Combine returns an AnyCancellable token. This token represents the active lifetime of your subscription:

  • If you do not store the AnyCancellable, it deallocates as soon as your local function scope exits.
  • Deallocating the token calls cancel(), terminating the subscription before values arrive.
  • Always store cancellables in a persistent container like var cancellables = Set<AnyCancellable>().
  • When your view model deallocates, the set cleans up all subscriptions automatically, preventing memory leaks.

Subjects: Imperative bridges to publishers

Sometimes you need to inject values into a stream manually. Combine provides Subjects:

  • PassthroughSubject: Broadcasts elements to active subscribers without caching past values. Late subscribers miss past events.
  • CurrentValueSubject: Stores a current value. It replays its latest value immediately to any new subscriber upon connection.

Transforming streams with operators

Combine provides dozens of functional operators:

  • map: Transforms each incoming element into a new format.
  • filter: Passes only elements that meet a boolean condition.
  • compactMap: Unwraps optionals and discards any nil values.
  • removeDuplicates: Ignores sequential duplicate elements in the stream.
  • debounce: Waits for a quiet pause in rapid events (like typing in a search bar) before emitting the latest value.
  • Just: Emits a single value immediately and completes.

Combine organizes asynchronous events into clear, declarative pipelines managed by explicit cancellation tokens.

In code

Creating a publisher pipeline with filter and map

Create a PassthroughSubject, transform numbers with operators, and subscribe using sink.

import Combine
import Foundation

var bag = Set<AnyCancellable>()
let numbers = PassthroughSubject<Int, Never>()

var squaredEvenNumbers: [Int] = []

numbers
    .filter { $0 % 2 == 0 }
    .map { $0 * $0 }
    .sink { value in
        squaredEvenNumbers.append(value)
    }
    .store(in: &bag)

numbers.send(1)
numbers.send(2)
numbers.send(3)
numbers.send(4)

print("Result: \(squaredEvenNumbers)")

OutputResult: [4, 16]

Storing the cancellable inside bag keeps the pipeline alive so it can receive all four values.

Observing state with CurrentValueSubject

Use CurrentValueSubject to manage reactive state that delivers initial values to subscribers.

import Combine
import Foundation

var bag = Set<AnyCancellable>()
let score = CurrentValueSubject<Int, Never>(10)

var log: [Int] = []

score
    .sink { value in
        log.append(value)
    }
    .store(in: &bag)

score.send(20)
score.value = 30

print("Scores: \(log)")

OutputScores: [10, 20, 30]

Notice that 10 is logged immediately upon subscription because CurrentValueSubject replays its current value.

Interview traps

Trap Discarding the AnyCancellable return value

The most common mistake when starting with Combine is ignoring the returned AnyCancellable. Writing publisher.sink { ... } without storing the return value causes the cancellable to deallocate at the end of the line. Its deinitializer runs immediately, cancelling the subscription before any asynchronous events can arrive. Always chain .store(in: &cancellables) to retain the active connection.

Trap Creating retain cycles with assign(to:on: self)

The assign(to: \.property, on: self) operator creates a strong reference to the target object self. If self also holds the returned AnyCancellable in its properties, you form a retain cycle (self -> cancellable -> self). Neither object can ever deallocate, creating a silent memory leak. To avoid this leak, use sink { [weak self] in self?.property = $0 } or the newer assign(to: &$property) on @Published properties.

Trap Confusing PassthroughSubject with CurrentValueSubject

If a screen component subscribes after initial values were sent, a PassthroughSubject will not replay anything. The view will appear empty until a brand new event is triggered. If your UI needs the current or latest state upon appearance, always choose CurrentValueSubject.

How to answer in the interview

Fresh answer

Combine is Apple framework for reactive event programming over time. It connects Publishers that emit values with Subscribers that receive them, using operators like map, filter, and debounce to transform the data. When we subscribe with .sink, it returns an AnyCancellable token that we must store in a set to keep the stream alive. When our view model deallocates, the set cleans up all subscriptions automatically, preventing memory leaks.

Senior answer

Combine provides a structured reactive architecture based on functional reactive streams and backpressure management. I use PassthroughSubject for transient actions like button taps, and CurrentValueSubject for stateful models requiring immediate replay on subscription. For memory safety, I avoid the retain cycle risk of assign(to:on: self) by using [weak self] closures or binding directly to @Published properties. While modern Swift applications prioritize AsyncStream and Swift Concurrency, Combine remains a critical tool for legacy UIKit view models and complex stream debouncing.

Recap

  • Combine standardizes asynchronous event processing using declarative pipelines.
  • Publisher emits values over time; Subscriber receives them.
  • Subscription connects publisher to subscriber and handles backpressure demand.
  • .sink attaches a closure subscriber and returns an AnyCancellable token.
  • You must store AnyCancellable in a set or property; otherwise, it cancels immediately.
  • PassthroughSubject broadcasts events without buffering past elements.
  • CurrentValueSubject buffers its latest value and replays it to new subscribers.
  • assign(to:on: self) causes retain cycles; prefer sink with [weak self].
  • Operators like map, filter, and debounce transform event streams cleanly.
