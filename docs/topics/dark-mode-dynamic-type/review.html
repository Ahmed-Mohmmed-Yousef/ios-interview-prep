Dark Mode and Dynamic Type

Interview question

Why should you use semantic system colors instead of hardcoded hex colors like pure white or pure black?

Your guess first (not scored). We come back to it in the recap.

The simple idea

Think of it like this

Imagine a digital wristwatch with two backlight settings.

In bright daylight, the watch shows black numbers on a clear white screen.

At night, the watch turns on a dark background with bright numbers.

The numbers and the screen adapt to the light around you.

If you painted black ink directly on the screen, you could not read the time in the dark.

Semantic colors work like that adaptive watch. They change shades automatically when the environment changes.

iOS users can change two major visual preferences:

  1. Dark Mode:
    • Shifts the interface from a light background to a darker palette.
    • Saves battery life on OLED displays and reduces eye strain in dark rooms.
    • Uses semantic colors like UIColor.systemBackground and UIColor.label.
  2. Dynamic Type:
    • Lets users choose their preferred text size in iOS Settings.
    • Scales fonts across standard styles like .headline, .body, and .caption.
    • Requires flexible layouts so larger text does not get clipped.

When you use semantic colors and scalable text styles, iOS handles theme and size changes for you.

Which UIKit property must you enable on a UILabel so text scales when users change font size in Control Center?

In code

First, observe how dynamic colors resolve differently based on the active trait collection.

You can create custom dynamic colors in code or inside your Asset Catalog.

In modern iOS 17 and later, views use registerForTraitChanges to observe appearance changes without retain cycles.

Next, see how to configure a UILabel for Dynamic Type.

Always set adjustsFontForContentSizeCategory to true and numberOfLines to 0.

Setting numberOfLines = 0 allows the label to wrap text onto multiple rows when the font scales up.

In SwiftUI, text automatically scales when you use standard font styles like .font(.body).

You can also use @ScaledMetric to scale icons and padding proportionally with text.

Interview traps

Trap Hardcoding black and white colors

Setting background color to UIColor.white and text color to UIColor.black breaks Dark Mode.

When the user turns on Dark Mode, your background stays bright white or your text vanishes against dark surfaces.

Always use semantic colors like UIColor.systemBackground and UIColor.label.

Trap Forgetting adjustsFontForContentSizeCategory

Setting label.font = UIFont.preferredFont(forTextStyle: .body) only sets the font size once at launch.

If the user changes text size in Settings while your app is running, your label will not update.

Always set label.adjustsFontForContentSizeCategory = true in UIKit to enable live updates.

Trap Fixed label height constraints

Pinning label heights with Auto Layout constraints prevents views from expanding when text scales up.

The text gets truncated or clipped at accessibility sizes.

Rely on intrinsic content size, set numberOfLines = 0, and avoid fixed height anchors.

Trap Overriding deprecated traitCollectionDidChange

Overriding traitCollectionDidChange is deprecated starting in iOS 17.

It triggers on every trait change and forces manual checking of trait differences.

Use registerForTraitChanges with specific trait arrays instead.

How to answer in the interview

Fresh answer

"I support Dark Mode by using semantic colors like systemBackground and label instead of hardcoded hex values. For Dynamic Type, I use standard text styles like .body and .headline. In UIKit, I set adjustsFontForContentSizeCategory = true and numberOfLines = 0 so text scales and wraps properly."

Junior answer

"We support Dark Mode by defining color assets in the Asset Catalog with Any and Dark appearance variants. For Dynamic Type, we use UIFont.preferredFont and UIFontMetrics for custom fonts. We never set fixed label heights. In SwiftUI, we use standard font styles and @ScaledMetric so icons scale alongside text."

Senior answer

"We treat appearance and typography as core accessibility requirements. We build interfaces with semantic color tokens and materials that respect elevation hierarchies. For Dynamic Type, we switch horizontal stacks to vertical stacks at accessibility sizes using ViewThatFits or dynamicTypeSize.isAccessibilitySize. In modern UIKit, we monitor appearance changes using registerForTraitChanges."

Recap

  • Semantic colors like systemBackground and label adapt automatically to Dark Mode.
  • Define custom dynamic colors in Asset Catalogs with Light and Dark variants.
  • Dynamic Type lets users scale text sizes across iOS for improved accessibility.
  • In UIKit, set adjustsFontForContentSizeCategory = true and numberOfLines = 0.
  • In SwiftUI, use standard text styles and @ScaledMetric for scalable icons and padding.
  • Avoid fixed label height constraints so text can wrap freely at large sizes.
  • In iOS 17+, observe trait changes using registerForTraitChanges.
