Interview question

Why does Swift emphasize protocol-oriented programming instead of deep class inheritance?

The simple idea

Think of it like this

Think of job skills on a resume. A person can have skills like driving, cooking, and speaking French. You do not force everyone into a single family tree to share skills. Instead, each person collects the skills they need. Protocols work the same way. Types collect capabilities by conforming to protocols instead of inheriting from one giant parent class.

In object-oriented programming, classes share code through inheritance. This creates tight coupling. Every subclass inherits all properties and behaviors from its superclass, even things it does not need. Classes also force reference semantics, which can lead to shared mutable state bugs.

Protocol-oriented programming focuses on what types can do rather than what they are.

Protocols define a set of requirements. Structs, enums, and classes can all conform to protocols. Because value types can conform to protocols, you can write safe, decoupled code without class inheritance.

Protocol extensions let you give default implementations to protocol requirements. When a type conforms to a protocol, it gets those default methods automatically. Conforming types can keep the default behavior or provide their own custom version.

Interview traps

Trap Declaring a method only in a protocol extension

If you do not declare a method in the protocol header, Swift uses static dispatch. Calling that method through a protocol type runs the extension version. Conforming types cannot override it dynamically. Always declare methods in the protocol definition if conforming types need to customize them.

Trap Creating giant monolithic protocols

Do not put twenty requirements into one protocol. This recreates the exact problem of deep class inheritance. Instead, create small, focused protocols with one or two requirements. Combine them with protocol composition when needed.

How to answer in the interview

Fresh answer

Protocol-oriented programming in Swift means designing systems around protocols instead of class inheritance. Protocols let structs, enums, and classes share behaviors. Protocol extensions provide default implementations so types do not need to repeat common code.

Junior answer

Swift is protocol-oriented because it prefers composition over inheritance. Structs and enums cannot inherit from superclasses, but they can adopt multiple protocols. We use protocol extensions to provide default implementations. Conforming types can override these defaults. If a method is declared in the protocol, Swift uses dynamic dispatch. If a method is only in the extension, Swift uses static dispatch.

Senior answer

Protocol-oriented programming decouples interfaces from concrete implementations while avoiding the fragile base class problem. By favoring value types and protocol composition, we prevent shared mutable state bugs. Architecturally, we keep protocols small and focused. Protocol requirements use witness table dynamic dispatch. Extension-only methods use static dispatch resolved at compile time.

Recap

  • Protocol-oriented programming favors composition over class inheritance.
  • Structs, enums, and classes can all conform to multiple protocols.
  • Protocol extensions provide default method implementations for conforming types.
  • Methods declared in the protocol definition use dynamic dispatch through witness tables.
  • Methods declared only in protocol extensions use static dispatch based on compile-time type.
  • Keep protocols small and combine them using composition with the ampersand operator.
