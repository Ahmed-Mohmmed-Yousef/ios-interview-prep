AsyncSequence and AsyncStream

After this topic, you can use async sequences to handle values over time.

Interview question

You receive location updates or streaming network bytes one by one. How do you consume these values using Swift concurrency?

The simple idea

A standard Swift Sequence gives you all its items right away. You loop through an array or set, and the program never pauses between elements.

An AsyncSequence works similarly, but values arrive over time.

Think of it like this

Think of an automated package conveyor belt. A worker waits next to the belt. When a package arrives, the worker picks it up and processes it. The belt pauses between packages. When the truck finishes unloading, the belt stops.

In an AsyncSequence, your loop suspends using await until the next value is ready. When the sequence ends, its iterator returns nil, and the loop exits.

Apple provides built-in async sequences like URLSession.shared.bytes(from:) and NotificationCenter notifications.

When you need to turn your own callback or delegate code into an async sequence, use AsyncStream.

AsyncStream provides a continuation. You call continuation.yield(value) to emit data, and continuation.finish() to close the stream.

See it

In code

Here is how you create an AsyncStream and consume its values with a for await loop.

func generateNumbers() -> AsyncStream<Int> {
    AsyncStream { continuation in
        for i in 1...3 {
            continuation.yield(i * 10)
        }
        continuation.finish()
    }
}

func readStream() async {
    for await number in generateNumbers() {
        print("Received: \(number)")
    }
    print("Stream complete")
}

await readStream()

OutputReceived: 10
Received: 20
Received: 30
Stream complete

The producer yields three numbers and signals completion with continuation.finish(). The for await loop prints each value and exits cleanly.

You can also make a custom struct conform to AsyncSequence and AsyncIteratorProtocol.

struct Counter: AsyncSequence, AsyncIteratorProtocol {
    typealias Element = Int
    var current = 1
    let limit: Int

    mutating func next() async -> Int? {
        guard current <= limit else { return nil }
        defer { current += 1 }
        return current
    }

    func makeAsyncIterator() -> Counter {
        self
    }
}

func countUp() async {
    let counter = Counter(limit: 3)
    for await value in counter {
        print("Count: \(value)")
    }
}

await countUp()

OutputCount: 1
Count: 2
Count: 3

Returning nil from next() signals the end of the sequence.

Quick check (not scored)

What does an AsyncIteratorProtocol next() method return when the sequence has no more values?

Returning nil from next() signals to the for-await-in loop that the sequence has finished.

Quick check (not scored)

Why is continuation.onTermination essential when creating an AsyncStream that wraps a hardware sensor?

continuation.onTermination runs when the consumer task is cancelled, allowing you to stop sensor updates and prevent battery drains.

Interview traps

Trap

If you omit continuation.finish(), the consumer loop waits forever for more elements. The task never finishes, leaking memory and leaving user interface screens stuck in loading states.

Trap

By default, AsyncStream uses an unbounded buffer. If a producer yields thousands of values per second and the consumer processes slowly, unread values accumulate in memory. Use a bounded buffering policy like .bufferingNewest(50) for fast data streams.

How to answer in the interview

Mid answer

An AsyncSequence represents a stream of values delivered over time, consumed using a for await in loop. Its iterator returns values asynchronously until returning nil to finish. I use AsyncStream to bridge closure and delegate APIs into modern concurrency. Inside the stream, I call yield to push data and finish() to close the sequence.

Senior answer

I design streaming pipelines with AsyncSequence to gain native structured concurrency and automatic cancellation. When wrapping high-frequency producers like sensors, I set a bounded buffering policy to avoid memory exhaustion from unconsumed elements. I always implement continuation.onTermination to deregister listeners and release system resources when the consumer cancels.

Recap

AsyncSequence delivers values over time, consumed with for-await loops. The sequence ends when next() returns nil. Use AsyncStream to adapt callbacks, delegates, or notifications into async sequences. Call continuation.finish() to avoid hanging loops, and use continuation.onTermination for clean teardown.
