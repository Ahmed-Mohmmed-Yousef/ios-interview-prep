The simple idea

Think of it like this

Think of an address on an envelope. The address tells the mail carrier which house to visit. It is not the house itself, but a set of directions to reach the house. In Swift, a key path is that address. It points to a specific property on a type without reading or changing the value immediately.

In Swift, a key path is a first-class reference to a property. You write a key path using a backslash followed by the property path, such as \Person.name. When the compiler can infer the type, you can use the short syntax \.name.

Unlike Objective-C string-based keys, Swift key paths are strongly typed at compile time. If you rename a property or misspell its name, the compiler catches the error immediately.

You read or write properties through key paths using a special subscript: person[keyPath: \.name].

Swift organizes key paths into a type hierarchy:

  • KeyPath<Root, Value>: Provides read-only access to a property.
  • WritableKeyPath<Root, Value>: Provides read and write access to mutable properties on value types.
  • ReferenceWritableKeyPath<Root, Value>: Provides read and write access to properties on reference classes.

You can also pass key paths directly to functions like map and filter wherever a matching closure is expected.

Quick check (not scored)

What character starts a Swift key path literal?

Swift key path literals always start with a backslash, like \Person.name or .name.

In code

This example shows how key path types work:

  • KeyPath<Player, Int>: Refers to the constant id. It only supports reading.
  • WritableKeyPath<Player, Int>: Refers to score. It supports both reading and writing via subscript.

This example highlights key paths as functions:

  • filter(\.isCompleted): \.isCompleted acts like { $0.isCompleted }.
  • map(\.title): \.title acts like { $0.title }. This syntax is clean and concise.

Interview traps

Trap Confusing Swift KeyPaths with Objective-C string-based KVC

In Objective-C, Key-Value Coding (KVC) uses raw strings like valueForKey:@"name". If you make a typo, your app crashes at runtime. Swift key paths are checked by the compiler. If a property does not exist or has the wrong type, the code will not compile.

Trap Using WritableKeyPath on a constant let property

You cannot create a WritableKeyPath for a property declared with let. The compiler only creates a read-only KeyPath for constants because their values cannot be changed after initialization.

How to answer in the interview

Fresh answer

A key path in Swift is a way to refer to a property on a type without reading it immediately. It starts with a backslash, like \Person.name. We can use key paths to read or modify properties, and we can pass them to functions like map and filter.

Junior answer

Swift key paths are strongly typed property references. KeyPath provides read-only access, while WritableKeyPath allows modifying mutable properties on value types. ReferenceWritableKeyPath is used for classes. Because Swift treats key paths as closures, we can write concise operations like array.map(.name). The compiler verifies key paths at compile time, eliminating runtime string typos.

Senior answer

Key paths provide type-safe property abstraction with zero string overhead. They support composition, nesting, and dynamic member lookup via the @dynamicMemberLookup attribute. In SwiftUI, key paths drive bindings and identifiable list loops. Architecturally, key paths enable powerful, decoupled patterns like state store lensing and observation pipelines without sacrificing compile-time type safety.

Recap

  • Key paths refer to properties as first-class values using backslash syntax.
  • Swift key paths are fully type-safe and checked at compile time.
  • KeyPath provides read-only access; WritableKeyPath provides read-write access for value types.
  • ReferenceWritableKeyPath provides read-write access for reference classes.
  • Key paths can be passed directly to higher-order functions like map and filter.
  • @dynamicMemberLookup uses key paths to build flexible, type-safe wrapper types.
