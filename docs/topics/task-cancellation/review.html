Task Cancellation

About 10 minutesThen a 10-question examPass mark 70%Version 1

Goal
After this topic, you can cancel tasks and write code that stops when you cancel it.

Interview question

You call task.cancel() on a running task that executes a heavy loop. Does the loop stop executing immediately?

Your guess first (not scored). We come back to it in the recap.

The simple idea

Calling task.cancel() does not pull the power cord on your code. Swift does not kill threads or force running code to stop.

Instead, cancellation in Swift is cooperative.

Think of it like this

Think of a chef in a restaurant kitchen. The manager walks in and asks the chef to cancel an order. The chef finishes the current knife cut, turns off the stove, and throws away the unfinished prep. The manager does not knock the knife out of the chef's hand.

When you cancel a task, Swift sets a flag on that task. In structured concurrency, this flag also flows down to all child tasks.

Your code must inspect this flag to stop doing work. You have two primary tools to check cancellation:

  1. Task.isCancelled: A simple Boolean check. Use it inside loops or before starting expensive steps to return early.
  2. try Task.checkCancellation(): Throws a CancellationError immediately if the task is cancelled. Use it in throwing functions.

Built-in asynchronous APIs like Task.sleep(for:) and URLSession already check cancellation for you. They throw CancellationError immediately when cancelled.

See it

In code

Here is how you check Task.isCancelled inside a loop to stop work early.

func processWork() async {
    let task = Task {
        var count = 0
        for i in 1...5 {
            if Task.isCancelled {
                print("Cancelled at step \(i)")
                return
            }
            count += 1
        }
        print("Finished all: \(count)")
    }

    task.cancel()
    await task.value
}

await processWork()

OutputCancelled at step 1

Because task.cancel() was called before the first step finished, Task.isCancelled was true. The task printed the cancellation message and exited immediately.

Next, here is how to use try Task.checkCancellation() in a throwing workflow.

func downloadFile() async throws {
    let task = Task {
        print("Starting download")
        try Task.checkCancellation()
        return "File data"
    }

    task.cancel()
    do {
        _ = try await task.value
    } catch is CancellationError {
        print("Caught CancellationError")
    }
}

try await downloadFile()

OutputStarting download
Caught CancellationError

When try Task.checkCancellation() detects that the task was cancelled, it throws CancellationError. The caller catches the error cleanly.

Interview traps

Trap

A loop that performs image filtering or encryption will keep running even after calling cancel(). Always place if Task.isCancelled or try Task.checkCancellation() inside long loops to avoid burning battery and CPU.

Trap

When a user leaves a screen, ongoing network requests cancel. If your catch block shows an alert for every error, the user sees an alert saying request cancelled. Check for is CancellationError and ignore expected cancellations.

How to answer in the interview

Mid answer

Swift task cancellation is cooperative. Calling task.cancel() sets a cancellation flag on the task and all its children, but does not kill threads. My code checks Task.isCancelled in non-throwing loops or calls try Task.checkCancellation() in throwing pipelines. Standard APIs like Task.sleep check cancellation automatically and throw CancellationError.

Senior answer

I design cancellation handling with clear resource cleanup using defer blocks. For bridging non-async APIs, I use withTaskCancellationHandler to forward cancellation to legacy network tasks or file handles. In SwiftUI, I use .task(id:) so parameter changes cancel in-flight requests automatically. When catching errors, I distinguish CancellationError from operational failures to avoid showing bogus alert popups to users.

Recap

Task cancellation in Swift is cooperative. Calling cancel sets a flag that flows down the task tree. Check Task.isCancelled to exit loops early or call try Task.checkCancellation() to throw CancellationError. Remember to clean up resources with defer, and do not show error alerts for intentional cancellations.
