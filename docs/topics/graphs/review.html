The simple idea

A graph stores items called vertices (or nodes) and the connections between them called edges.

Think of it like this

Think of a subway map. Each train station is a vertex. The train tracks between stations are edges. Some tracks run both ways, while others are one-way tracks.

Graphs come in several variations:

  • Directed or Undirected: Directed edges point one way, like a package dependency. Undirected edges connect both ways, like a mutual friend link.
  • Cyclic or Acyclic: A cycle exists if you can follow edges back to your starting point. A directed graph without cycles is called a DAG.
  • Weighted or Unweighted: Weighted edges hold a cost, such as network latency or travel distance.

Unlike a tree, a graph has no single root. A graph can have cycles. When you search a graph, you must remember visited nodes. A Set of visited IDs stops infinite loops.

In Swift, you usually store a graph as an adjacency list. A dictionary maps each vertex to an array of its neighboring nodes: [Int: [Int]].

In code

Here is how to find the shortest path between two nodes in an unweighted graph using breadth-first search.

func shortestPath(edges: [[Int]], start: Int, target: Int) -> Int {
    var adj: [Int: [Int]] = [:]
    for edge in edges {
        adj[edge[0], default: []].append(edge[1])
        adj[edge[1], default: []].append(edge[0])
    }

    var queue: [Int] = [start]
    var visited: Set<Int> = [start]
    var distance = 0

    while !queue.isEmpty {
        let count = queue.count
        for _ in 0..<count {
            let curr = queue.removeFirst()
            if curr == target { return distance }
            for neighbor in adj[curr, default: []] {
                if !visited.contains(neighbor) {
                    visited.insert(neighbor)
                    queue.append(neighbor)
                }
            }
        }
        distance += 1
    }
    return -1
}

let connections = [[0, 1], [0, 2], [1, 3], [2, 3], [3, 4]]
print("Shortest path from 0 to 4: \(shortestPath(edges: connections, start: 0, target: 4))")

OutputShortest path from 0 to 4: 3

Next, here is topological sort using Kahn's algorithm. We compute in-degrees to order build tasks.

func buildOrder(numTasks: Int, dependencies: [[Int]]) -> [Int] {
    var adj: [Int: [Int]] = [:]
    var inDegree = Array(repeating: 0, count: numTasks)

    for dep in dependencies {
        let before = dep[1]
        let after = dep[0]
        adj[before, default: []].append(after)
        inDegree[after] += 1
    }

    var queue: [Int] = []
    for i in 0..<numTasks where inDegree[i] == 0 {
        queue.append(i)
    }

    var order: [Int] = []
    while !queue.isEmpty {
        let current = queue.removeFirst()
        order.append(current)
        for next in adj[current, default: []] {
            inDegree[next] -= 1
            if inDegree[next] == 0 {
                queue.append(next)
            }
        }
    }

    return order.count == numTasks ? order : []
}

let deps = [[0, 1], [2, 1], [3, 2]]
print("Task build order: \(buildOrder(numTasks: 4, dependencies: deps))")

OutputTask build order: [1, 0, 2, 3]

Quick check (not scored)

Why does graph search require a visited set while standard tree search does not?

Trees have a single root and no cycles. Graphs can have loops that cause infinite search cycles without a visited set.

Quick check (not scored)

What happens in Kahn's topological sort algorithm when the graph contains a directed cycle?

Every node in a cycle depends on another node in the cycle. Their in-degrees never reach zero, so the output count is less than the total node count.

Interview traps

Trap

In an undirected graph, an edge between A and B means A connects to B AND B connects to A. If you only append to one list, your search misses paths.

Trap

A graph can have separate clusters of nodes. If you only start BFS or DFS from node 0, you miss unreached components. Loop through all vertices from 0 to V minus 1.

How to answer in the interview

Mid answer

I model graph problems using an adjacency list dictionary. For shortest path in unweighted graphs, I choose BFS with a queue and a visited Set. For cycle detection or ordering build steps, I pick topological sort with in-degrees. I always add a visited Set to avoid infinite loops from graph cycles.

Senior answer

I evaluate graph density before choosing a data structure. Sparse graphs use an adjacency list taking O(V plus E) space. Dense graphs benefit from an adjacency matrix taking O(V squared) space with O(1) edge lookups. For dependency resolution, I use Kahn's algorithm or three-color DFS to detect cycles. I also account for disconnected components by iterating over all vertices in an outer loop.

Recap

Graphs connect vertices with directed or undirected edges. Use an adjacency list dictionary in Swift for fast neighbor lookups. Always maintain a visited Set to stop cycle loops. BFS finds the shortest path in unweighted graphs. Topological sort orders tasks in a directed acyclic graph.
