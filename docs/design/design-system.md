After any change: `node scripts/build-design-system.mjs` and `node scripts/check-brand.mjs`. The build lists every color pair that fails WCAG AA.

## How the app uses the tokens (Phase 5)

- `globals.css` imports `config/generated/tokens.css` after `@import "tailwindcss"`. Then utilities like `bg-primary`, `text-muted-foreground`, `rounded-lg`, `text-success` and `bg-level-mid` work.
- The variable names follow [shadcn/ui theming](https://ui.shadcn.com/docs/theming) (`--background`, `--primary`, `--border` …), so shadcn components work without changes.
- **Theme:** with no class on `<html>`, the app follows the device. The `.light` or `.dark` class forces a mode, and the Settings switch sets it.

## Rules

- **Color is never the only signal.** Right and wrong answers also show a word. Each path-stop state has its own shape: check mark (passed), double arrow (skipped), lock (locked), dot (updated), star (bonus).
- **Wrong is amber, not red.** It is friendly and still clear. Red (`destructive`) is only for real danger, like resetting progress.
- **Every tap target is at least 44px.** Focus rings are 3px in the `ring` color.
- **Reading width is at most 66 characters.** Body text is 16px with a 26px line height.
- **Motion:** calm easing and 150 / 250 / 450ms durations. All durations become 0 with reduced motion.

## Contrast

Every text pair passes **WCAG AA (4.5:1)** in light and dark mode, including the stage colors used as text. The first build found 4 failures, and all were fixed:
- The light amber (`warn`) went from `#a76a12` (4.46:1) to `#9c6210` (5.04:1).
- Text on green and amber in dark mode now uses near-black instead of white.
- Step 3.8 (2026-10-24): light `success` went from `#0f7f63` to `#0c765c`, and light `warn` from `#9c6210` to `#915b0e`, so both pass 4.5:1 on their soft backgrounds. Stage signs use the new `--level-<id>-foreground` tokens. `check-brand.mjs` now checks 17 pairs per mode. See [a11y-check.md](a11y-check.md).
