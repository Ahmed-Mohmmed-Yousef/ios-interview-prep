# Research rule — always verify on the web

Training data is out of date. Before stating or writing any fact, verify it with a web search or by fetching the official page.

Applies to:
- Swift / iOS / Xcode APIs, behavior, availability and deprecations
- Version numbers (Swift, Xcode, iOS, npm packages)
- Tool and library recommendations
- Free-tier limits, pricing, licenses
- Official documentation URLs (fetch them — don't guess paths)

How:
- Prefer official sources: swift.org, docs.swift.org, github.com/swiftlang, developer.apple.com (docs, WWDC, HIG, forums), package docs/changelogs.
- Third-party blogs are only hints. Confirm against an official page before relying on them.
- Cite the URL you used. Record the verification date when it goes into a file.
- If something can't be verified, say so plainly and mark it `UNVERIFIED` in files.
