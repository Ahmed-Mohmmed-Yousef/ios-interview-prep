## The simple idea

<Analogy>
Think of a function like a printed recipe card with a title at the top. A closure is like a recipe note written on a sticky note. You can hand that sticky note to a friend to use right away. Even without a title, it carries the exact same steps.
</Analogy>

In Swift, a **closure** is a block of code that you can store, pass around, and run later.

Functions are special named closures:
- **Global functions** have a name and do not capture any values.
- **Nested functions** have a name and can capture values from the function around them.
- **Closure expressions** have no name and are written inline with short syntax.

Closures are **reference types**. When you assign one closure to two constants, both constants point to the same closure and its captured values.

The full closure syntax uses curly braces and the **`in`** keyword:
`{ (parameters) -> ReturnType in statements }`

The `in` keyword marks where the parameter list ends and where the body begins.

Swift can also shorten closures using context:
- **Type inference**: Swift guesses parameter and return types from the function expecting the closure.
- **Implicit return**: If a closure body has only one expression, you can leave out the `return` keyword.
- **Shorthand argument names**: `$0`, `$1`, and `$2` stand for the first, second, and third arguments. When you use them, leave out the parameter list and `in`.
- **Trailing closures**: When a closure is the final argument, write it after the closing parenthesis `)`.

## In code

<CodeExample title="Shortening closure syntax step by step">

```swift
let names = ["Dana", "Alex", "Jordan"]

let sortedFull = names.sorted(by: { (s1: String, s2: String) -> Bool in
    return s1 < s2
})
print("Full syntax: \(sortedFull)")

let sortedShort = names.sorted { $0 < $1 }
print("Shorthand: \(sortedShort)")
```

```output
Full syntax: ["Alex", "Dana", "Jordan"]
Shorthand: ["Alex", "Dana", "Jordan"]
```

</CodeExample>

This example shows four shortcuts together:
- **Type inference**: Because `sorted(by:)` expects `(String, String) -> Bool`, Swift already knows the types.
- **Single-expression return**: A closure body with only one expression does not need `return`.
- **Shorthand names**: `$0` and `$1` refer to the first and second strings, so you do not need `in`.
- **Trailing closure**: Because the closure is the last argument, you can write it after `sorted` with no parentheses.

Collection methods like `map` and `filter` often use trailing closures:
- `map` transforms each item into a new value.
- `filter` keeps only the items where the closure returns `true`.

<CodeExample title="Using trailing closures with map and filter">

```swift
let numbers = [1, 2, 3, 4]
let doubled = numbers.map { $0 * 2 }
let evens = numbers.filter { $0 % 2 == 0 }

print("Doubled: \(doubled)")
print("Evens: \(evens)")
```

```output
Doubled: [2, 4, 6, 8]
Evens: [2, 4]
```

</CodeExample>

<CodeExample title="Capturing values and reference types">

```swift
func makeTracker() -> () -> Int {
    var count = 0
    return {
        count += 1
        return count
    }
}

let counterA = makeTracker()
print("Counter A: \(counterA())")
print("Counter A: \(counterA())")

let counterB = counterA
print("Counter B: \(counterB())")
```

```output
Counter A: 1
Counter A: 2
Counter B: 3
```

</CodeExample>

This example shows two key rules:
- **Value capturing**: The closure captures `count` from `makeTracker()`. Even after `makeTracker()` finishes, `count` stays alive.
- **Reference types**: When you assign `counterA` to `counterB`, both point to the same closure and share the same `count`.

## Interview traps

<Trap title="Mixing shorthand names with parameter names">
You cannot mix `$0` with named parameters. Writing `{ name in print($0) }` fails to compile. Use either named parameters with `in`, or shorthand names like `$0`.
</Trap>

<Trap title="Thinking closures are value types">
Closures look lightweight, so candidates sometimes guess they are value types like structs. Closures are reference types. Changing a captured variable through one closure variable also changes it for every other variable pointing to that closure.
</Trap>

<Trap title="Extra parentheses on a trailing closure">
When a closure is the only argument to a function, you can leave out the empty parentheses `()`. Both `names.map() { $0.uppercased() }` and `names.map { $0.uppercased() }` compile, but `names.map { $0.uppercased() }` is the clean Swift style.
</Trap>

## How to answer in the interview

<InterviewAnswer level="fresh">
A closure in Swift is a block of code you can save in a variable or pass to a function. Named functions are special closures. Closures use the in keyword to separate parameters from the code body. You can shorten them with type inference, implicit return for one expression, shorthand names like $0 and $1, and trailing closure syntax.
</InterviewAnswer>

<InterviewAnswer level="junior">
Closures and functions in Swift are reference types that can capture variables from the scope around them. Swift can infer parameter and return types from context, omit return in single-expression closures, and place the final closure outside parentheses as a trailing closure. Because closures are reference types, assigning a closure to another variable shares the same closure and the same captured values.
</InterviewAnswer>

## Recap

<Recap>
- Functions are named closures; closure expressions are unnamed inline blocks of code.
- Full syntax: `{ (params) -> ReturnType in statements }`.
- `in` separates the parameters and return type from the closure body.
- Swift can infer types and omit `return` in single-expression closures.
- Shorthand names `$0`, `$1`, and `$2` stand for arguments by position without `in`.
- Write a final closure argument outside `()` as a trailing closure, and omit `()` if it is the only argument.
- Closures are reference types that capture and keep surrounding variables alive.
</Recap>
