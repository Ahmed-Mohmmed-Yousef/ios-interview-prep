## The simple idea

A heap is a tree-based data structure that keeps the smallest or largest element at the top.

<Analogy>
  Think of an emergency room triage desk. The patient with the most urgent condition is always treated first. Doctors do not sort all patients.
</Analogy>

In a **min-heap**, every parent node is smaller than or equal to its children. The smallest value sits at the root.

In a **max-heap**, every parent node is larger than or equal to its children. The largest value sits at the root.

A binary heap is a **complete binary tree**. Every level is completely filled, except possibly the last level. The last level fills from left to right.

Because of this shape, you do not need node objects or pointers. You can store a binary heap inside a standard array:

- For any element at index `i`, its left child is at `2 * i + 1`.
- Its right child is at `2 * i + 2`.
- Its parent is at `(i - 1) / 2`.

When you insert an item, you append it to the array. Then you **sift up** until the heap property is restored.

When you remove the root item, you swap it with the last element and remove it. Then you **sift down** the new root.

Both insert and remove take $O(\log n)$ time. Looking at the root takes $O(1)$ time.

The Swift standard library does not include a heap type. Apple provides `Heap` in the open-source `swift-collections` package. In technical interviews, you often write a simple struct.

## In code

Here is a generic `Heap` struct in Swift that supports custom comparators.

```swift
struct Heap<T> {
    var elements: [T] = []
    let areInIncreasingOrder: (T, T) -> Bool

    init(comparator: @escaping (T, T) -> Bool) {
        self.areInIncreasingOrder = comparator
    }

    var isEmpty: Bool { elements.isEmpty }
    var count: Int { elements.count }
    var peek: T? { elements.first }

    mutating func insert(_ value: T) {
        elements.append(value)
        siftUp(elements.count - 1)
    }

    mutating func pop() -> T? {
        guard !elements.isEmpty else { return nil }
        if elements.count == 1 { return elements.removeLast() }
        let top = elements[0]
        elements[0] = elements.removeLast()
        siftDown(0)
        return top
    }

    private mutating func siftUp(_ index: Int) {
        var child = index
        while child > 0 {
            let parent = (child - 1) / 2
            if areInIncreasingOrder(elements[child], elements[parent]) {
                elements.swapAt(child, parent)
                child = parent
            } else {
                break
            }
        }
    }

    private mutating func siftDown(_ index: Int) {
        var parent = index
        while true {
            let left = 2 * parent + 1
            let right = 2 * parent + 2
            var candidate = parent

            if left < elements.count && areInIncreasingOrder(elements[left], elements[candidate]) {
                candidate = left
            }
            if right < elements.count && areInIncreasingOrder(elements[right], elements[candidate]) {
                candidate = right
            }
            if candidate == parent { break }
            elements.swapAt(parent, candidate)
            parent = candidate
        }
    }
}

var minHeap = Heap<Int>(comparator: <)
minHeap.insert(10)
minHeap.insert(4)
minHeap.insert(15)
minHeap.insert(1)

print("Smallest element: \(minHeap.peek ?? -1)")
print("Popped smallest: \(minHeap.pop() ?? -1)")
print("Next smallest: \(minHeap.peek ?? -1)")
```
```output
Smallest element: 1
Popped smallest: 1
Next smallest: 4
```

Now here is how to solve the classic Kth largest element problem using a min-heap of size K.

```swift
struct MinHeap {
    var elements: [Int] = []
    var count: Int { elements.count }
    var peek: Int? { elements.first }

    mutating func insert(_ value: Int) {
        elements.append(value)
        var i = elements.count - 1
        while i > 0 {
            let parent = (i - 1) / 2
            if elements[i] < elements[parent] {
                elements.swapAt(i, parent)
                i = parent
            } else { break }
        }
    }

    mutating func pop() -> Int? {
        guard !elements.isEmpty else { return nil }
        if elements.count == 1 { return elements.removeLast() }
        let top = elements[0]
        elements[0] = elements.removeLast()
        var parent = 0
        while true {
            let left = 2 * parent + 1
            let right = 2 * parent + 2
            var candidate = parent
            if left < elements.count && elements[left] < elements[candidate] { candidate = left }
            if right < elements.count && elements[right] < elements[candidate] { candidate = right }
            if candidate == parent { break }
            elements.swapAt(parent, candidate)
            parent = candidate
        }
        return top
    }
}

func findKthLargest(_ nums: [Int], _ k: Int) -> Int {
    var minHeap = MinHeap()
    for num in nums {
        minHeap.insert(num)
        if minHeap.count > k {
            _ = minHeap.pop()
        }
    }
    return minHeap.peek ?? -1
}

let numbers = [3, 2, 1, 5, 6, 4]
print("2nd largest element: \(findKthLargest(numbers, 2))")
```
```output
2nd largest element: 5
```

## Interview traps

<Trap label="Using full sorting instead of a bounded heap">
  Sorting an entire array of size N takes O(N log N) time and O(N) memory. Using a min-heap of size K takes O(N log K) time and only O(K) memory.
</Trap>

<Trap label="Assuming Swift includes a built-in Heap type">
  The Swift standard library does not provide a Heap type. If you write code in an interview, be ready to implement a compact Heap struct.
</Trap>

## How to answer in the interview

<InterviewAnswer level="mid">
  I use a binary heap when I need repeated access to minimum or maximum values. For top K problems, I maintain a min-heap of size K. This achieves O(N log K) time and O(K) space. Since the Swift standard library lacks a Heap, I write a lightweight array-backed struct with sift-up and sift-down operations.
</InterviewAnswer>

<InterviewAnswer level="senior">
  I leverage binary heaps for priority queues and streaming algorithms. In Swift, I point out that Apple provides `Heap` in `swift-collections`. An array representation gives optimal cache locality with zero pointer overhead. For Kth largest elements, a bounded min-heap saves memory. For running medians, I balance a max-heap and min-heap in O(log N) time per insertion.
</InterviewAnswer>

## Recap

<Recap>
  A binary heap provides O(1) peek and O(log N) insert and extract operations. Store heaps in flat arrays using simple index math. Use a min-heap of size K to find top K elements efficiently. Remember that the Swift standard library requires an external package or a custom struct.
</Recap>
