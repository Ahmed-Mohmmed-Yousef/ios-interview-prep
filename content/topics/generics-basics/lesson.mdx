## The simple idea

<Analogy>
Think of a molded shipping container. The container structure is identical whether you load bicycles, books, or electronics. You do not need to build a new container design for every product. But once loaded with books, it holds books safely and predictably. Swift generics work the same way: you build one reusable structure that safely holds any specific type you provide.
</Analogy>

In Swift, **generics** allow you to write flexible, reusable functions and types that work with any type according to rules you define.

Generics prevent duplicated logic without discarding compile-time type safety. Built-in types like `Array` and `Dictionary` are generic types.

Key elements of generics:
- **Type parameters**: Placeholders written inside angle brackets, like `<T>` or `<Element>`, representing an actual type supplied at call time.
- **Generic types**: Custom structs, classes, or enums that adapt to any element type, such as `Stack<Element>`.
- **Type constraints**: Requirements dictating that a type parameter must inherit from a specific class or conform to a protocol, like `<T: Equatable>`.
- **Where clauses**: Additional conditional constraints specified with the `where` keyword.

## In code

<CodeExample title="Writing a generic function with type inference">

```swift
// 1. A generic swap function working with any matching type
func swapValues<T>(_ a: inout T, _ b: inout T) {
    let temporary = a
    a = b
    b = temporary
}

var firstInt = 10
var secondInt = 20
swapValues(&firstInt, &secondInt)
print("Ints: first is \(firstInt), second is \(secondInt)")

var firstString = "World"
var secondString = "Hello"
swapValues(&firstString, &secondString)
print("Strings: \(firstString) \(secondString)")
```

```output
Ints: first is 20, second is 10
Strings: Hello World
```

</CodeExample>

This code shows how generic functions operate:
- **Type parameter `<T>`**: `T` stands in for an actual type determined when the function is called.
- **Type matching**: Both `a` and `b` must share the exact same type `T`.
- **Automatic inference**: The compiler infers `T` as `Int` in the first call and `T` as `String` in the second call.

<CodeExample title="Building generic types and applying type constraints">

```swift
// 2. Generic custom type: Stack
struct Stack<Element> {
    private var items: [Element] = []
    
    mutating func push(_ item: Element) {
        items.append(item)
    }
    
    mutating func pop() -> Element? {
        return items.popLast()
    }
}

// Extending a generic type reuses the Element placeholder
extension Stack {
    var topItem: Element? {
        return items.last
    }
}

var intStack = Stack<Int>()
intStack.push(1)
intStack.push(2)
print("Top item: \(intStack.topItem ?? 0)")
print("Popped item: \(intStack.pop() ?? 0)")

// 3. Type constraint enforcing Equatable
func findIndex<T: Equatable>(of target: T, in list: [T]) -> Int? {
    for (index, item) in list.enumerated() {
        if item == target {
            return index
        }
    }
    return nil
}

let fruits = ["Apple", "Banana", "Orange"]
let index = findIndex(of: "Banana", in: fruits)
print("Banana index: \(index ?? -1)")
```

```output
Top item: 2
Popped item: 2
Banana index: 1
```

</CodeExample>

This example highlights generic types and constraints:
- **Generic struct**: `Stack<Element>` stores items of any specified type safely.
- **Generic extensions**: `extension Stack` reuses `Element` without writing angle brackets again.
- **Type constraint `<T: Equatable>`**: Enables the `==` comparison operator inside `findIndex`.

## Interview traps

<Trap title="Using Any instead of generics">
Candidates sometimes reach for `Any` when they want flexible functions. `Any` throws away type safety and requires risky runtime casting. Generics enforce strict type relationships while keeping code flexible.
</Trap>

<Trap title="Repeating angle brackets when extending generic types">
When extending `Stack<Element>`, candidates often write `extension Stack<Element>`. Swift forbids angle brackets in the extension signature. Write `extension Stack` and use `Element` directly.
</Trap>

<Trap title="Assuming Swift generics use Java-style type erasure">
In Java, generic types are erased at runtime to raw Objects. In Swift, generics preserve full type metadata. The compiler generates specialized machine code for concrete types.
</Trap>

## How to answer in the interview

<InterviewAnswer level="fresh">
Generics let you write functions and types that work with any type. We define placeholder names in angle brackets like `<T>`. Generics give us code reuse while maintaining Swift compile-time type safety.
</InterviewAnswer>

<InterviewAnswer level="junior">
Generics allow functions and custom types to operate on placeholder types like `<T>` or `<Element>`. Type constraints restrict placeholders to types conforming to specific protocols, such as `<T: Equatable>`. Unlike Any, generics maintain static type safety without runtime casting.
</InterviewAnswer>

<InterviewAnswer level="senior">
Swift generics are implemented through compiler specialization, known as monomorphization. When concrete types are known, the compiler generates specialized, non-generic machine code with direct dispatch and zero abstraction penalty. For unspecialized code, Swift uses metadata records and witness tables to pass types safely at runtime.
</InterviewAnswer>

## Recap

<Recap>
- Generics enable flexible, reusable functions and types without code duplication.
- Placeholder types are declared inside angle brackets, such as `<T>` or `<Element>`.
- The compiler infers type parameters from argument values at the call site.
- Extensions on generic types reuse existing type parameter names without angle brackets.
- Type constraints like `<T: Equatable>` unlock protocol-specific operations like `==`.
- Swift compiler monomorphization optimizes generic code into fast concrete implementations.
</Recap>
