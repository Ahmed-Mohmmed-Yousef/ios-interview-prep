## The simple idea

<Analogy>
Think of shipping luggage on an airplane. When you pack your suitcase, you fold your clothes into flat boxes that fit onto cargo belts. When you arrive at your destination, you unpack those boxes back into clothes in your closet. Codable works the same way: it folds Swift objects into portable JSON data, and unpacks JSON data back into Swift objects.
</Analogy>

In Swift, **`Codable`** is a typealias combining two protocols: `Encodable` and `Decodable`.

`Encodable` types can serialize themselves into external representations like JSON. `Decodable` types can deserialize external data into Swift types.

When all stored properties inside a struct conform to `Codable`, the Swift compiler synthesizes the decoding and encoding code automatically.

Real-world API data often uses `snake_case` keys like `first_name`, while Swift style uses `camelCase` like `firstName`.

You bridge this gap with **`CodingKeys`**. A nested `CodingKeys` enum maps external JSON string keys directly to Swift property names.

For advanced formats, you can implement custom decoding with `init(from decoder: Decoder)` to provide default fallbacks for missing fields.

## In code

<CodeExample title="Decoding and encoding with custom CodingKeys">

```swift
import Foundation

struct User: Codable {
    let id: Int
    let fullName: String
    let email: String
    
    // Mapping snake_case JSON keys to Swift camelCase properties
    enum CodingKeys: String, CodingKey {
        case id
        case fullName = "full_name"
        case email
    }
}

let json = """
{
    "id": 101,
    "full_name": "Taylor Swift",
    "email": "taylor@example.com"
}
""".data(using: .utf8)!

// Decoding JSON data into a strongly typed User struct
let user = try JSONDecoder().decode(User.self, from: json)
print("\(user.fullName) has ID \(user.id)")

// Encoding User struct back into JSON data
let encoder = JSONEncoder()
encoder.outputFormatting = .sortedKeys
let encodedData = try encoder.encode(user)
let encodedString = String(data: encodedData, encoding: .utf8)!
print(encodedString.contains("full_name"))
```

```output
Taylor Swift has ID 101
true
```

</CodeExample>

This example shows two key patterns:
- **`CodingKeys`**: The enum renames `full_name` from JSON to `fullName` in Swift.
- **`JSONDecoder` and `JSONEncoder`**: They handle parsing and serialization with strict type checking.

<CodeExample title="Custom decoding with decodeIfPresent and fallback values">

```swift
import Foundation

struct Product: Codable {
    let name: String
    let price: Double
    let description: String
    
    enum CodingKeys: String, CodingKey {
        case name
        case price
        case description
    }
    
    // Custom decoding initializer to handle missing optional fields safely
    init(from decoder: Decoder) throws {
        let container = try decoder.container(keyedBy: CodingKeys.self)
        self.name = try container.decode(String.self, forKey: .name)
        self.price = try container.decode(Double.self, forKey: .price)
        self.description = try container.decodeIfPresent(String.self, forKey: .description) ?? "No description"
    }
}

let jsonWithoutDescription = """
{
    "name": "Coffee Mug",
    "price": 12.50
}
""".data(using: .utf8)!

let product = try JSONDecoder().decode(Product.self, from: jsonWithoutDescription)
print("\(product.name): $\(product.price)")
print("Description: \(product.description)")
```

```output
Coffee Mug: $12.5
Description: No description
```

</CodeExample>

This example highlights custom decoding flexibility:
- **`container(keyedBy:)`**: Extracts a keyed container matching the `CodingKeys` enum.
- **`decodeIfPresent`**: Safely reads optional keys, allowing default fallback values when fields are absent.

## Interview traps

<Trap title="Omitting properties from custom CodingKeys">
When you write a custom `CodingKeys` enum, you must include every stored property you want encoded or decoded. If you omit a property, the compiler will not synthesize decoding for it.
</Trap>

<Trap title="Mixing convertFromSnakeCase with explicit snake_case raw values">
If you set `keyDecodingStrategy = .convertFromSnakeCase` and also write `case fullName = "full_name"` in `CodingKeys`, the decoder applies conversion twice. Choose either automated strategy conversion or explicit `CodingKeys`, not both.
</Trap>

<Trap title="Failing to handle dates with proper dateDecodingStrategy">
By default, `JSONDecoder` expects dates as floating point numbers representing seconds since 2001. If your API sends ISO8601 date strings, you must configure `decoder.dateDecodingStrategy = .iso8601`.
</Trap>
