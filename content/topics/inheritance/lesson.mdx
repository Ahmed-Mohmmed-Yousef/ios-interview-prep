## The simple idea

<Analogy>
Think of a family recipe book. A baker starts with their grandmother's classic bread recipe. They keep the core baking steps, but they add walnuts and honey on top. The new recipe inherits the foundation while adding a personalized touch. In Swift, inheritance allows a class to inherit methods and properties from an existing class.
</Analogy>

In Swift, **inheritance** allows one class to inherit the characteristics of another class.

The class that inherits is called a **subclass**, and the class it inherits from is called a **superclass**.

Inheritance is unique to **classes** in Swift. Structs and enumerations cannot inherit from other types.

Core principles of Swift inheritance:
- **No universal base class**: Swift classes do not inherit from a universal root object. Any class without a superclass is a base class.
- **The `override` keyword**: When changing inherited behavior, you must prefix declarations with `override`. The compiler validates that the method exists on the superclass.
- **Calling `super`**: A subclass can invoke its superclass implementation using `super.someMethod()` or `super.someProperty`.
- **The `final` modifier**: You can mark a method, property, or entire class as `final`. This prevents other classes from overriding or subclassing it.

## In code

<CodeExample title="Inheriting properties, overriding methods, and calling super">

```swift
class Vehicle {
    var speed = 0
    var description: String {
        return "Traveling at \(speed) km/h."
    }
    
    func makeNoise() {
        print("Generic vehicle noise.")
    }
}

class Train: Vehicle {
    override func makeNoise() {
        super.makeNoise()
        print("Choo Choo!")
    }
}

let train = Train()
train.speed = 120
print(train.description)
train.makeNoise()
```

```output
Traveling at 120 km/h.
Generic vehicle noise.
Choo Choo!
```

</CodeExample>

This example shows the foundations of subclassing:
- **Subclass syntax**: `class Train: Vehicle` states that `Train` inherits from `Vehicle`.
- **Inherited state**: `train` gains the `speed` property and `description` computed property directly.
- **Method overriding**: `Train` replaces `makeNoise()` using the mandatory `override` keyword.
- **Calling `super`**: `super.makeNoise()` executes the original implementation before adding custom behavior.

<CodeExample title="Overriding property observers and using the final keyword">

```swift
class Account {
    var balance: Double = 0 {
        didSet {
            print("Balance updated to: \(balance)")
        }
    }
    
    final func closeAccount() {
        print("Account closed.")
    }
}

class SavingsAccount: Account {
    var interestRate: Double
    
    init(interestRate: Double) {
        self.interestRate = interestRate
        super.init()
    }
    
    override var balance: Double {
        didSet {
            print("Savings notice: New balance is \(balance)")
        }
    }
}

let savings = SavingsAccount(interestRate: 0.04)
savings.balance = 500.0
savings.closeAccount()
```

```output
Balance updated to: 500.0
Savings notice: New balance is 500.0
Account closed.
```

</CodeExample>

This code shows two advanced inheritance features:
- **Chained property observers**: When `balance` updates, both the superclass and subclass `didSet` observers execute.
- **Preventing overrides with `final`**: Subclasses cannot override `closeAccount()`. This guarantees critical logic remains unchanged.

## Interview traps

<Trap title="Assuming Swift has a root object like NSObject or Object">
In Objective-C or Java, objects trace back to a common ancestor like `NSObject` or `Object`. In Swift, classes do not share a universal base class. A class without a superclass is an independent root class.
</Trap>

<Trap title="Replacing inherited stored properties with another stored property">
You cannot override an inherited stored property with another stored property. You can only provide custom getters and setters, or attach property observers (`didSet`, `willSet`).
</Trap>

<Trap title="Overusing inheritance instead of composition">
Deep class hierarchies create fragile code. A small change in a superclass can break subclasses unexpectedly. In modern Swift, prefer protocols and composition over deep class trees.
</Trap>

## How to answer in the interview

<InterviewAnswer level="fresh">
Inheritance allows one class to inherit properties and methods from another class. Subclasses use the override keyword to provide custom implementations and can call super to run the parent logic. Only classes support inheritance in Swift.
</InterviewAnswer>

<InterviewAnswer level="junior">
Swift classes support single inheritance. A subclass inherits stored properties, computed properties, and methods. Overriding requires the override keyword, which the compiler validates against the superclass. Marking declarations as final prevents overrides and allows the compiler to use direct static dispatch.
</InterviewAnswer>

<InterviewAnswer level="senior">
Swift avoids a universal base class, keeping class hierarchies lightweight. While inheritance enables polymorphism, it introduces tight coupling and fragile base class risks. Senior engineers prefer protocols, value types, and composition over deep class hierarchies, reserving inheritance mainly for framework integration like UIKit.
</InterviewAnswer>

## Recap

<Recap>
- Only classes support inheritance in Swift.
- Classes without a superclass are base classes; Swift has no universal root object.
- Subclasses use the `override` keyword to customize inherited methods and properties.
- Use `super` to call original superclass implementations.
- Subclasses can add property observers to inherited properties.
- The `final` keyword prevents subclassing and overriding, enabling static dispatch optimizations.
</Recap>
