## The simple idea

In Swift 5, concurrency checks were optional warnings. You could ship code with potential data races.

Swift 6 enables complete concurrency checking by default. The compiler turns those warnings into strict errors.

Code that compiles without errors in Swift 6 is proven free of data races.

<Analogy>
  Think of building a house. Swift 5 gave you helpful advice from building inspectors. You could ignore the advice and move in anyway. Swift 6 acts like a locked gate. You cannot open the door until every electrical connection passes strict inspection.
</Analogy>

Most Swift 6 errors fall into three common patterns:

First, passing a mutable class across task boundaries. You fix this by converting the class to a struct or an actor.

Second, calling a `@MainActor` function from background code without `await`. You fix this by adding `await` or marking the caller `@MainActor`.

Third, accessing a mutable global variable. You fix this by turning it into a `let` constant or protecting it with `@MainActor`.

When migrating legacy libraries, you can use `@preconcurrency import`. For classes that manage locks manually, you can use `nonisolated(unsafe)`.

## In code

Here is how you fix a non-isolated caller trying to use a `@MainActor` class. You write `await` to hop onto the actor safely.

```swift
@MainActor
final class StatusReporter {
    var status = "Idle"

    func update(to newStatus: String) {
        status = newStatus
    }
}

nonisolated func refresh() async {
    let reporter = await StatusReporter()
    await reporter.update(to: "Running")
    let current = await reporter.status
    print("Status: \(current)")
}

await refresh()
```
```output
Status: Running
```

Without the `await` keyword, Swift 6 stops the build because background code cannot access main actor state synchronously.

Next, here is how you protect shared static state using `@MainActor`.

```swift
enum AppState {
    @MainActor static var launchCount = 0
}

func recordLaunch() async {
    await MainActor.run {
        AppState.launchCount += 1
        print("Launch count: \(AppState.launchCount)")
    }
}

await recordLaunch()
```
```output
Launch count: 1
```

In Swift 5, unprotected static variables produced runtime crashes. In Swift 6, `@MainActor` makes mutations thread-safe.

## Interview traps

<Trap label="Do not sprinkle nonisolated(unsafe) everywhere">
  `nonisolated(unsafe)` bypasses compiler checks for that specific variable. If you use it without manual synchronization like locks, your app will still crash. Only use it when a variable is already protected by custom locks.
</Trap>

<Trap label="Avoid migrating an entire huge codebase at once">
  Turning on Swift 6 across hundreds of thousands of lines creates thousands of errors at once. Migrate module by module. Swift 5 and Swift 6 modules can interoperate smoothly.
</Trap>
