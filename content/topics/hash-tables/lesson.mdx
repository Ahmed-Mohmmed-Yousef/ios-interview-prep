## The simple idea

<Analogy>
Imagine a hotel with numbered mailboxes in the lobby.

When a letter arrives for room 402, the clerk does not check every mailbox one by one. The clerk walks straight to box 402 and drops the letter inside.

If two guests share the same box number, the clerk places both letters inside that same box. This shared box is a collision.
</Analogy>

A **hash table** is a data structure that stores key-value pairs.

In Swift, both `Dictionary` and `Set` use hash tables behind the scenes:
1. **The Hash Function**:
   - The key must conform to the `Hashable` protocol.
   - For structs and enums whose stored properties all conform to `Hashable`, Swift synthesizes conformance automatically.
   - For custom rules, implement `hash(into:)` with `hasher.combine(...)` to turn the key into a hash value.
2. **Buckets**:
   - Swift converts the hash value into an internal storage index called a bucket.
   - Finding the bucket takes $O(1)$ constant time.
3. **Collisions**:
   - When two different keys produce the same bucket index, a **collision** happens.
   - Swift uses **open addressing** with **linear probing** to step to the next open slot.
   - In the worst case, many collisions force Swift to check multiple slots, taking $O(n)$ linear time.

Because hash tables provide $O(1)$ average lookups, they are essential in coding interviews. They allow you to replace slow nested loops with instant dictionary checks.

## In code

<CodeExample title="Frequency counting and fast Set membership in Swift">

```swift
// 1. Frequency counter with default dictionary subscript
let phrase = "swift interview"
var counts: [Character: Int] = [:]

for char in phrase where char != " " {
    counts[char, default: 0] += 1
}

print("Count of i: \(counts["i"] ?? 0)")
print("Count of w: \(counts["w"] ?? 0)")

// 2. Set for fast membership testing
var visited = Set<String>()
visited.insert("home")
visited.insert("profile")

print("Visited home: \(visited.contains("home"))")
print("Visited settings: \(visited.contains("settings"))")
```

```output
Count of i: 3
Count of w: 2
Visited home: true
Visited settings: false
```

</CodeExample>

In the first example, the `default` subscript parameter simplifies counting. You do not need optional unwrapping to increment missing keys.

In the second example, `Set.contains` runs in $O(1)$ average time. Checking an `Array` would require $O(n)$ time.

<CodeExample title="Solving Two Sum with a hash table in O(n) time">

```swift
// Two Sum problem using a hash table in O(n) time
func twoSum(_ numbers: [Int], target: Int) -> [Int] {
    var seenIndices: [Int: Int] = [:]
    
    for (index, number) in numbers.enumerated() {
        let complement = target - number
        if let previousIndex = seenIndices[complement] {
            return [previousIndex, index]
        }
        seenIndices[number] = index
    }
    return []
}

let numbers = [2, 7, 11, 15]
let result = twoSum(numbers, target: 9)
print("Two Sum indices for 9: \(result)")

let resultTwo = twoSum([3, 2, 4], target: 6)
print("Two Sum indices for 6: \(resultTwo)")
```

```output
Two Sum indices for 9: [0, 1]
Two Sum indices for 6: [1, 2]
```

</CodeExample>

In Two Sum, a brute-force solution checks every pair with two nested loops. That takes $O(n^2)$ time.

By storing visited numbers in a dictionary, we check for the required complement in $O(1)$ time. This solves the problem in $O(n)$ time and $O(n)$ auxiliary space.

<CodeExample title="Useful Dictionary and Set methods in Swift">

```swift
// Dictionary capacity, updates, removal, and duplicate keys
var scores = ["Alice": 90, "Bob": 80]
scores.reserveCapacity(10)
let oldAlice = scores.updateValue(95, forKey: "Alice")
let removedMissing = scores.removeValue(forKey: "Cara")
print("Old Alice: \(oldAlice ?? 0), removed Cara: \(removedMissing == nil)")

let pairs = [("a", 1), ("b", 2), ("a", 3)]
let combined = Dictionary(pairs, uniquingKeysWith: { first, second in first + second })
print("Combined a: \(combined["a"] ?? 0)")

// Set insertion result and set intersection
var ids: Set<Int> = [1, 2]
let addedTwo = ids.insert(2).inserted
let addedThree = ids.insert(3).inserted
let common = ids.intersection([2, 3, 4])
print("Added 2: \(addedTwo), added 3: \(addedThree), common count: \(common.count)")
```

```output
Old Alice: 90, removed Cara: true
Combined a: 4
Added 2: false, added 3: true, common count: 2
```

</CodeExample>

Here is what each helper does in practice:
- **`reserveCapacity`** prepares bucket storage up front to avoid repeated rehashing, without changing `count`.
- **`updateValue(_:forKey:)`** and **`removeValue(forKey:)`** return the old value, or `nil` if the key was absent.
- **`Dictionary(_:uniquingKeysWith:)`** lets you merge duplicate keys with a closure instead of crashing.
- **`Set.insert(_:).inserted`** returns `true` only when the item is new, and **`intersection`** keeps items present in both sets.

## Interview traps

<Trap title="Assuming Dictionary maintains insertion order">
Swift `Dictionary` and `Set` are unordered collections.

When you loop over a dictionary, keys do not appear in the order you inserted them. Their order depends on bucket layout and hash seeds.

If an interview problem requires preserving insertion order, use an array alongside your dictionary or use an ordered collection.
</Trap>

<Trap title="Persisting hashValue to disk or network">
Swift uses **SipHash** with a random per-process seed to stop collision denial-of-service attacks, where crafted inputs force slow $O(n)$ collisions.

Because this random seed changes every time your app launches, an object's `hashValue` changes across runs.

Never save `hashValue` to UserDefaults, Core Data, SwiftData, or a server database.
</Trap>

<Trap title="Violating the Hashable contract">
If two instances are equal with `==`, they must feed the exact same properties into `hasher.combine(...)`.

If you check three properties in `==` but only hash one property in `hash(into:)`, or vice versa, the hash table will break.

Inconsistent hashing causes dictionaries and sets to lose elements or report wrong lookups.
</Trap>

<Trap title="Mutating an object while it is inside a Set">
If you store a reference type in a `Set` and change its properties later, its hash value can change.

The set will still search the original bucket. Because the object now lives in the wrong bucket, lookups and deletions will fail.

Always use immutable value types like structs for dictionary keys and set elements.
</Trap>

## How to answer in the interview

<InterviewAnswer level="fresh">
"A hash table is a data structure that stores key-value pairs with $O(1)$ average lookup, insertion, and deletion time. In Swift, `Dictionary` and `Set` use hash tables. Keys must conform to `Hashable`, which inherits from `Equatable`. In coding interviews, I use a dictionary to cache visited elements, such as in Two Sum. This reduces lookup time from $O(n^2)$ to $O(n)$."
</InterviewAnswer>

<InterviewAnswer level="junior">
"Swift implements `Dictionary` and `Set` using open-addressing hash tables with SipHash. Hashing maps keys to buckets, and `==` resolves collisions when two keys share a bucket. Swift randomizes hash seeds per process launch to protect against collision denial-of-service attacks. I make sure custom `Hashable` implementations hash the exact same properties used in `==`, and I use immutable keys so bucket positions remain valid."
</InterviewAnswer>

<InterviewAnswer level="senior">
"In production apps, hash table speed depends on load factor, bucket layout, and collision safety. Swift's standard library uses open addressing with linear probing and an inline bitmap tracking occupied buckets. Keys and values sit in contiguous arrays sized to powers of two, with no tombstones and resizing around 75% load. Because SipHash uses a random seed per launch, `hashValue` must never be saved. In hot paths, I use `reserveCapacity` to prevent costly rehashing passes."
</InterviewAnswer>

## Recap

<Recap>
- `Dictionary` and `Set` use hash tables for $O(1)$ average lookup, insertion, and deletion.
- Keys must conform to `Hashable`, which inherits from `Equatable` to resolve bucket collisions.
- Equal objects (`a == b`) must produce identical hash values by hashing the same properties.
- Swift uses SipHash with random per-process seeds; never save `hashValue` to disk or network.
- Hash tables solve interview problems like Two Sum and frequency counting by trading $O(n)$ space for $O(n)$ time.
</Recap>
