## The simple idea

In early Swift Concurrency, all code was non-isolated by default. You had to add `@MainActor` to almost every view model and controller.

This created endless boilerplate annotations. It also caused accidental threading errors when developers forgot an annotation.

Modern Swift introduces approachable concurrency. In app targets, code isolates to `@MainActor` by default.

<Analogy>
  Think of working in an office building. In the past, every door was locked. You had to swipe an access card for every single room. Now, the main office floor is open by default. You only need a keycard when entering the high-security server room.
</Analogy>

Your view models, views, and presentation state run on the main thread automatically. You do not need `@MainActor` on every class.

When you need to run heavy work off the main thread, you opt out.

You use `nonisolated` to mark methods or types that should not run on the main actor.

For heavy asynchronous background tasks, Swift uses `@concurrent` functions. Calling a `@concurrent` function hops off the main thread automatically.

This flips the mental model: stay on the main actor by default, and opt out for heavy background work.

## In code

Here is an example of a view model calling an off-actor background function. The UI state stays protected on the main thread.

```swift
@MainActor
final class FeedViewModel {
    var title = "Loading"

    func refresh() async {
        let result = await fetchFeedBackground()
        title = result
        print("Updated on main: \(title)")
    }
}

nonisolated func fetchFeedBackground() async -> String {
    "Latest Posts"
}

func testFeed() async {
    let model = await FeedViewModel()
    await model.refresh()
}

await testFeed()
```
```output
Updated on main: Latest Posts
```

Notice that `fetchFeedBackground` is `nonisolated`. It runs off the main actor, preventing UI freezes during data loading.

Next, here is how you use `nonisolated` on a synchronous helper method to keep heavy calculations off the actor.

```swift
@MainActor
final class ImageProcessor {
    var filterName = "Sepia"

    nonisolated func calculatePixelCount(width: Int, height: Int) -> Int {
        width * height
    }

    func applyFilter(width: Int, height: Int) {
        let pixels = calculatePixelCount(width: width, height: height)
        print("Filter \(filterName) applied to \(pixels) pixels")
    }
}

func execute() async {
    let processor = await ImageProcessor()
    await processor.applyFilter(width: 1920, height: 1080)
}

await execute()
```
```output
Filter Sepia applied to 2073600 pixels
```

Marking `calculatePixelCount` as `nonisolated` allows callers to run calculations independently without locking the actor state.

## Interview traps

<Trap label="Do not run heavy image or database decoding on the main actor">
  Because approachable concurrency defaults to the main actor, forgetting to opt out keeps heavy processing on the main thread. This causes UI hitches. Always move heavy JSON parsing and image decoding to nonisolated or concurrent functions.
</Trap>

<Trap label="Do not confuse app targets with shared framework packages">
  Default main actor isolation is designed for application targets. Shared utility packages and libraries still default to non-isolated code to remain versatile across server and client platforms.
</Trap>
