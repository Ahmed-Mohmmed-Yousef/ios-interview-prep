## The simple idea

<Analogy>
Imagine hanging posters on a flexible wall.

Instead of nailing them at fixed positions, you connect them with rubber bands.

You attach one band from the poster to the ceiling. You attach another band to the left wall.

When the wall expands or tilts, the rubber bands adjust. The poster stays in the right spot.

Those rubber bands are **constraints**.
</Analogy>

Auto Layout calculates the size and position of every view using mathematical relationships.

Instead of hard-coding frames, you declare rules called constraints.

The system adapts your layout across iPhones, iPads, rotations, and Dynamic Type sizes:

1. **`NSLayoutAnchor`**:
   - Provides type-safe layout rules like `leadingAnchor`, `trailingAnchor`, and `topAnchor`.
   - Groups constraints together for batch activation with `NSLayoutConstraint.activate`.
2. **`safeAreaLayoutGuide`**:
   - Prevents your views from overlapping the notch, Dynamic Island, and home indicator.
3. **Content Hugging & Compression Resistance**:
   - Content hugging resists stretching larger than the view's natural content size.
   - Compression resistance resists shrinking smaller than the content size, preventing text clipping.

## In code

Here is how you position a view in code using layout anchors.

You must set `translatesAutoresizingMaskIntoConstraints = false` and add the view before activating constraints.

<CodeExample title="Configuring programmatic constraints with layout anchors">

```swift
import UIKit

let superview = UIView(frame: CGRect(x: 0, y: 0, width: 300, height: 400))
let box = UIView()
box.translatesAutoresizingMaskIntoConstraints = false
superview.addSubview(box)

NSLayoutConstraint.activate([
    box.topAnchor.constraint(equalTo: superview.topAnchor, constant: 20),
    box.leadingAnchor.constraint(equalTo: superview.leadingAnchor, constant: 10),
    box.widthAnchor.constraint(equalToConstant: 100),
    box.heightAnchor.constraint(equalToConstant: 50)
])

superview.layoutIfNeeded()

print("Box frame: \(box.frame.origin.x), \(box.frame.origin.y), \(box.frame.width), \(box.frame.height)")
```

```output
Box frame: 10.0, 20.0, 100.0, 50.0
```

</CodeExample>

`NSLayoutConstraint.activate` applies all constraints in a single optimized pass.

Next, observe how content hugging priorities resolve layout conflicts.

<CodeExample title="Configuring content hugging priorities">

```swift
import UIKit

let nameLabel = UILabel()
let priceLabel = UILabel()

nameLabel.setContentHuggingPriority(.defaultLow, for: .horizontal)
priceLabel.setContentHuggingPriority(.defaultHigh, for: .horizontal)

let lowPriority = nameLabel.contentHuggingPriority(for: .horizontal).rawValue
let highPriority = priceLabel.contentHuggingPriority(for: .horizontal).rawValue

print("Priorities: low=\(lowPriority), high=\(highPriority)")
```

```output
Priorities: low=250.0, high=750.0
```

</CodeExample>

Because `nameLabel` has the lower hugging priority, it stretches when extra horizontal space exists.

`priceLabel` stays tightly wrapped around its text.

## Interview traps

<Trap title="Activating constraints before addSubview">
Never activate constraints on a view before calling `addSubview`.

UIKit requires both views to share a common ancestor in the view hierarchy.

Activating constraints before adding the view throws a fatal runtime crash.
</Trap>

<Trap title="Forgetting translatesAutoresizingMaskIntoConstraints">
Views created in code set `translatesAutoresizingMaskIntoConstraints = true` by default.

UIKit converts old resizing masks into constraints that collide with your anchors.

Always set `translatesAutoresizingMaskIntoConstraints = false` on every programmatic view.
</Trap>

<Trap title="Confusing hugging with compression resistance">
Content hugging resists stretching larger than the content size.

Compression resistance resists shrinking smaller than the content size.

To prevent label text from clipping with dots, raise its compression resistance priority.
</Trap>

<Trap title="Ignoring the safe area layout guide">
Pinning directly to `view.topAnchor` causes content to overlap the status bar or notch.

Always constrain content to `view.safeAreaLayoutGuide.topAnchor`.

Use the root view edges only for full-bleed background colors.
</Trap>

## How to answer in the interview

<InterviewAnswer level="fresh">
"Auto Layout lets views adapt to different device sizes and orientations. We connect views with anchors like `topAnchor` and `leadingAnchor`. In code, we must set `translatesAutoresizingMaskIntoConstraints = false` and add the view before activating constraints."
</InterviewAnswer>

<InterviewAnswer level="junior">
"We create constraints using `NSLayoutAnchor` and batch activate them with `NSLayoutConstraint.activate`. We use leading and trailing anchors for right-to-left localization, and pin to `safeAreaLayoutGuide` to avoid notches. For views with intrinsic size like labels, lower content hugging stretches, while higher compression resistance prevents text truncation."
</InterviewAnswer>

<InterviewAnswer level="senior">
"Auto Layout uses the Cassowary linear programming solver. We minimize layout thrashing by avoiding constraint churn in scrollable cells and setting priorities below 1000 to resolve ambiguous states. For scalable architectures, we combine `UIStackView` with layout guides and debug conflicts using symbolic breakpoints like `UIViewAlertForUnsatisfiableConstraints`."
</InterviewAnswer>

## Recap

<Recap>
- Auto Layout creates dynamic relationships between views using linear constraints.
- Always set `translatesAutoresizingMaskIntoConstraints = false` on programmatic views.
- Views must be added to a superview before activating constraints.
- Use `leadingAnchor` and `trailingAnchor` to support right-to-left languages.
- Pin interactive views to `safeAreaLayoutGuide` to respect notches and home bars.
- Lower content hugging stretches; higher compression resistance prevents clipping.
</Recap>
