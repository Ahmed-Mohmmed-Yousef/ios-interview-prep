## The simple idea

<Analogy>
Think of a framed painting hanging in an art gallery.

The **frame** describes where the painting hangs on the gallery wall. It records the position relative to the room.

The **bounds** describes the dimensions of the canvas itself. The canvas starts at point zero on its own surface.

The **gallery curator** is the view controller. The curator decides when to hang the painting and organizes the room.
</Analogy>

In UIKit, screen interfaces are built with views and view controllers.

A `UIView` draws content on the screen. It also handles touch events and manages subviews.

A `UIViewController` manages a hierarchy of views. It coordinates screen updates and responds to user actions.

1. **`UIView`**:
   - Manages a rectangular area on the device screen.
   - Organizes elements in a tree with `superview` and `subviews`.
   - Persists in memory as a mutable reference class.
2. **`UIViewController`**:
   - Owns a root view accessible through the `view` property.
   - Loads the view lazily when first accessed.
   - Manages containment hierarchies and system events.

## In code

Here is how a view controller constructs and arranges views in code.

Subviews are added to the root view hierarchy and positioned using frames.

<CodeExample title="Constructing views and comparing frame with bounds">

```swift
import UIKit

let superview = UIView(frame: CGRect(x: 0, y: 0, width: 300, height: 400))
let childView = UIView(frame: CGRect(x: 20, y: 50, width: 100, height: 60))

superview.addSubview(childView)

print("Child frame origin: \(childView.frame.origin.x), \(childView.frame.origin.y)")
print("Child bounds origin: \(childView.bounds.origin.x), \(childView.bounds.origin.y)")
print("Subviews count: \(superview.subviews.count)")
```

```output
Child frame origin: 20.0, 50.0
Child bounds origin: 0.0, 0.0
Subviews count: 1
```

</CodeExample>

Notice that the child frame origin is at `(20, 50)` within the superview.

Its bounds origin remains `(0, 0)` within its own local canvas.

Next, observe how a parent view controller manages child view controller containment.

<CodeExample title="Child view controller containment">

```swift
import UIKit

class ParentViewController: UIViewController {
    var loadedChildren: [String] = []

    func embed(child: UIViewController, named: String) {
        addChild(child)
        view.addSubview(child.view)
        child.didMove(toParent: self)
        loadedChildren.append(named)
    }
}

let parentVC = ParentViewController()
let childVC = UIViewController()

parentVC.embed(child: childVC, named: "ProfileHeader")
print("Children count: \(parentVC.children.count)")
print("Loaded: \(parentVC.loadedChildren.first ?? "none")")
```

```output
Children count: 1
Loaded: ProfileHeader
```

</CodeExample>

Following the three-step containment sequence ensures lifecycle events pass correctly to child controllers.

## Interview traps

<Trap title="Accessing view too early inside init">
Do not access `self.view` inside the view controller initializer.

Reading `self.view` forces UIKit to load the entire view hierarchy before dependencies are ready.

Wait until `viewDidLoad` to configure views and subview properties.
</Trap>

<Trap title="Confusing frame and bounds with rotation">
When you apply a rotation transform to a view, its `frame` changes size to fit the bounding box.

Never use `frame` to measure transformed views.

Use `bounds` for width and height, and use `center` for positioning.
</Trap>

<Trap title="Calling super.loadView() with custom views">
When overriding `loadView` to assign a custom root view, do not call `super.loadView()`.

Calling super creates an unnecessary default blank view.

Assign your custom view directly to `self.view`.
</Trap>

<Trap title="Skipping child containment steps">
Only calling `view.addSubview(childVC.view)` breaks view controller containment.

The child controller will not receive appearance callbacks or rotation events.

Always call `addChild`, `view.addSubview`, and `child.didMove(toParent: self)`.
</Trap>

## Recap

<Recap>
- `UIView` is a mutable class that draws screen content and handles touches.
- `UIViewController` manages a view hierarchy and responds to lifecycle events.
- The `view` property loads lazily when accessed or displayed.
- `frame` is relative to the superview, while `bounds` is in local coordinates.
- Containment requires calling `addChild`, adding the subview, and calling `didMove(toParent:)`.
- Avoid accessing `self.view` during `init` to prevent premature view loading.
</Recap>
