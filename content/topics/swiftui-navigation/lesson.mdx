# Navigation

How do users move from a master list to a detail screen and back again? In SwiftUI, `NavigationStack` manages screen transitions using a stack of data.

  <Guess>
    <Option id="a">NavigationStack renders UIKit storyboards instead of SwiftUI structs.</Option>
    <Option id="b" correct>NavigationStack separates data values from destination views so screens load only when tapped.</Option>
    <Option id="c">NavigationStack loads all destination screens into memory when the list opens.</Option>
  </Guess>

## The simple idea

Mobile apps often organize screens in a hierarchy. You start at a home screen, tap an item to push a detail screen, and tap back to return.

In SwiftUI, `NavigationStack` holds your root view:
1. **The Navigation Stack**:
   - `NavigationStack` manages a stack of screens.
   - When a user taps a navigation link, SwiftUI pushes a new screen on top.
   - When the user taps the back button or swipes from the left, SwiftUI pops the top screen off.
2. **Data-Driven Navigation**:
   - Modern SwiftUI uses data values to drive navigation.
   - `NavigationLink(value:)` sends a data item to the stack.
   - The `.navigationDestination(for:destination:)` modifier defines what view to display for that data type.
3. **Lazy Creation**:
   - Destination views are created only when the user taps a row.
   - This prevents loading dozens of detail views into memory upfront.

<Analogy>
  Think of a stack of cafeteria trays.
  The bottom tray is your home screen. When you tap an item, you place a new tray on top. You only see the top tray.
  When you finish, you remove the top tray and reveal the screen underneath.
</Analogy>

## In code

Here is a working `NavigationStack` using `NavigationLink(value:)` and `.navigationDestination(for:)`.

<CodeExample title="Value-based navigation with NavigationStack">

```swift
import SwiftUI

struct FruitList: View {
    let fruits = ["Apple", "Banana", "Orange"]

    var body: some View {
        NavigationStack {
            List(fruits, id: \.self) { fruit in
                NavigationLink(fruit, value: fruit)
            }
            .navigationTitle("Fruit Market")
            .navigationDestination(for: String.self) { fruit in
                Text("Selected: \(fruit)")
            }
        }
    }
}

let list = FruitList()
print("Fruits count: \(list.fruits.count)")
```

```output
Fruits count: 3
```

</CodeExample>

You can also control navigation programmatically using a `NavigationPath`. A `NavigationPath` stores the navigation state as an array of items.

<CodeExample title="Programmatic navigation with NavigationPath">

```swift
import SwiftUI

struct ProgrammaticFlow: View {
    @State private var path = NavigationPath()

    var body: some View {
        NavigationStack(path: $path) {
            VStack {
                Button("Open Settings") {
                    path.append("SettingsScreen")
                }
            }
            .navigationTitle("Home")
            .navigationDestination(for: String.self) { screen in
                VStack {
                    Text("Current: \(screen)")
                    Button("Pop to Root") {
                        path = NavigationPath()
                    }
                }
            }
        }
    }
}

var testPath = NavigationPath()
testPath.append("SettingsScreen")
print("Path depth: \(testPath.count)")
```

```output
Path depth: 1
```

</CodeExample>

## Interview traps

<Trap title="Using deprecated NavigationView">
  `NavigationView` was deprecated in iOS 16. It had navigation bugs and poor performance. In modern Swift interviews, always use `NavigationStack` for single-column layouts or `NavigationSplitView` for multi-column layouts.
</Trap>
<Trap title="Eager loading with NavigationLink(destination:)">
  Passing a view directly into `NavigationLink(destination: DetailView())` creates `DetailView` structs immediately for every row in your list. Always use `NavigationLink(value:)` paired with `.navigationDestination(for:)` to load screens lazily.
</Trap>
<Trap title="Placing .navigationTitle on NavigationStack">
  Attaching `.navigationTitle("Home")` directly to `NavigationStack` does not display a title. Always attach `.navigationTitle()` to the root child view inside the stack.
</Trap>
<Trap title="Missing Hashable conformance on values">
  `NavigationLink(value:)` requires data values to conform to `Hashable`. If your custom model struct does not conform to `Hashable`, the compiler will report an error.
</Trap>

<InterviewAnswer level="senior">

</InterviewAnswer>

## Recap

<Recap>
  - Use `NavigationStack` to present a stack of hierarchical screens.
  - Pair `NavigationLink(value:)` with `.navigationDestination(for:)` for lazy destination loading.
  - Bind a `NavigationPath` to your stack for programmatic navigation and pop-to-root actions.
  - Always place `.navigationTitle()` on the inner child view, not the `NavigationStack`.
  - Values passed to `NavigationLink(value:)` must conform to `Hashable`.
</Recap>
