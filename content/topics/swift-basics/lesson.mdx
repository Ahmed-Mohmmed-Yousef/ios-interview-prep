## The simple idea

<Analogy>
Think of a let constant as writing on a storage box with a permanent marker. You write the label once, and you cannot erase it. A var variable is like writing on a whiteboard. You can wipe away the old value and write a new value at any time.
</Analogy>

Every app stores information, such as user names, scores, and settings. In Swift, you store information using **constants** and **variables**.

A **constant** is a value that you set once and never change. You declare a constant with the `let` keyword. A **variable** is a value that can change while your app runs. You declare a variable with the `var` keyword.

Every value in Swift also has a **type**. A type tells Swift what kind of data a value is. Common types include whole numbers (`Int`), decimal numbers (`Double`), text (`String`), and flags (`Bool`).

Swift is a **type-safe** language. This means Swift checks all types when you compile your code. If you try to pass text where a number is expected, Swift stops with an error before your app can run.

When you create a constant or variable with an initial value, you do not have to write the type name. Swift uses **type inference** to inspect your value and pick the matching type automatically.

## In code

<CodeExample title="Declaring constants and variables">

```swift
let appName = "Prep Stops"
let maxAttempts = 3
var currentAttempts = 1
let isAllowed = true

print(appName)
print("Attempts: \(currentAttempts) of \(maxAttempts)")
print("Allowed: \(isAllowed)")
```

```output
Prep Stops
Attempts: 1 of 3
Allowed: true
```

</CodeExample>

In this example, `appName`, `maxAttempts`, and `isAllowed` never need to change. Declaring them with `let` protects them from accidental edits. `currentAttempts` uses `var` because the counter increases as the user tries again.

Notice that we did not write `: String` or `: Int`. Swift inferred `String` for `appName`, `Int` for `maxAttempts`, and `Bool` for `isAllowed`.

<CodeExample title="Type annotations and explicit conversion">

```swift
let wholeNumber: Int = 5
let decimalNumber: Double = 2.5

// Swift does not convert types automatically.
// We convert wholeNumber to Double explicitly before adding.
let total = Double(wholeNumber) + decimalNumber
print("Total: \(total)")
```

```output
Total: 7.5
```

</CodeExample>

When you need an explicit type, add a colon and the type name. This is called a **type annotation**.

Swift never converts numbers between different types on its own. If you try to add an `Int` and a `Double` directly, the compiler stops with an error. You must write `Double(wholeNumber)` to convert the integer explicitly.

## Interview traps

<Trap title="Assuming Swift converts numbers automatically">
In languages like JavaScript or C, you can add an integer and a decimal number directly. Swift refuses to do this because silent conversions can lose precision. Always write an explicit type conversion like `Double(myInteger)` or `Int(myDouble)`.
</Trap>

<Trap title="Thinking let values must be known before compiling">
A `let` constant is not restricted to values you know while writing code. A `let` constant can store the result of a network call, a user tap, or a calculation. The only rule is that once you give it a value, you cannot change that value.
</Trap>

<Trap title="Single-letter text is not a Character by default">
When you write `let symbol = "A"`, Swift infers the `String` type, not `Character`. If an API requires a `Character`, you must use an explicit type annotation: `let symbol: Character = "A"`.
</Trap>

## How to answer in the interview

<InterviewAnswer level="fresh">
In Swift, `let` declares a constant whose value cannot change after you assign it, while `var` declares a variable that can change. Apple recommends using `let` by default because it prevents accidental edits and makes code intent clear. Swift is also type-safe and uses type inference, so the compiler picks the correct type automatically from your initial value.
</InterviewAnswer>

<InterviewAnswer level="junior">
Using `let` by default makes code predictable and easier to reason about. It prevents unintentional mutations and avoids data races in concurrent code. The Swift compiler can also apply performance optimizations to constant values. Because Swift is strictly type-safe, it does not allow implicit type conversion; operations between different types, such as `Int` and `Double`, require explicit conversion.
</InterviewAnswer>

## Recap

<Recap>
- Use `let` by default for all values. Use `var` only when a value must mutate.
- Swift is type-safe. It validates all data types before compiling your application.
- Swift uses type inference to determine types like `Int`, `Double`, `String`, and `Bool` from initial values.
- Swift never converts number types automatically. Convert values explicitly with `Double(...)` or `Int(...)`.
- Single-letter text in quotes infers `String`. Add `: Character` if you need a character type.
</Recap>
