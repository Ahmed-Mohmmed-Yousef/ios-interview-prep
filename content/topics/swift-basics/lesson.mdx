## The simple idea

<Analogy>
Think of a let constant as writing on a storage box with a permanent marker. You write the label once, and you cannot erase it. A var variable is like writing on a whiteboard. You can wipe away the old value and write a new value at any time.
</Analogy>

Every app stores information, such as user names, scores, and settings. In Swift, you store information using **constants** and **variables**.

A **constant** is a value that you set once and never change. You declare a constant with the `let` keyword. A **variable** is a value that can change while your app runs. You declare a variable with the `var` keyword.

The Swift book says: if a value will not change, always declare it with `let`. Use `var` only for values that change. Constants help in three ways:

1. You cannot change a constant by mistake. The compiler stops you.
2. A reader of your code knows at once that the value stays the same.
3. Code that runs at the same time can read a constant safely, because nobody can change it while it is read.

Every value in Swift also has a **type**. A type tells Swift what kind of data a value is. Common types are whole numbers (`Int`), decimal numbers (`Double`), text (`String`), and true or false values (`Bool`).

Swift has two main decimal types. `Double` uses 64 bits, and `Float` uses only 32 bits, so it is less precise. When you do not name a type, Swift always picks `Double`, never `Float`.

Swift is a **type-safe** language. This means Swift checks all types when you compile your code. If you try to pass text where a number is expected, Swift stops with an error before your app can run.

When you create a constant or variable with a first value, you do not have to write the type name. Swift uses **type inference**: it looks at your value and picks the matching type for you. The code is still type-safe, because the type is fixed when you compile.

## In code

<CodeExample title="Declaring constants and variables">

```swift
let appName = "Prep Stops"
let maxAttempts = 3
var currentAttempts = 1
let isAllowed = true

currentAttempts = 2
print(appName)
print("Attempts: \(currentAttempts) of \(maxAttempts)")
print("Allowed: \(isAllowed)")
```

```output
Prep Stops
Attempts: 2 of 3
Allowed: true
```

</CodeExample>

In this example, `appName`, `maxAttempts`, and `isAllowed` never need to change. Declaring them with `let` protects them from accidental edits. `currentAttempts` uses `var` because the counter goes up when the user tries again.

Notice that we did not write `: String` or `: Int`. Swift inferred `String` for `appName`, `Int` for `maxAttempts`, and `Bool` for `isAllowed`.

The compiler also helps you choose. When a `var` inside a function never changes, it shows a warning: "variable was never mutated; consider changing to 'let' constant".

<CodeExample title="Choosing a type with a type annotation">

```swift
let size: Float = 1.5        // Float, not Double
let letter: Character = "A"  // Character, not String
let price: Double = 5        // the number 5 becomes a Double
print(size, letter, price)
```

```output
1.5 A 5.0
```

</CodeExample>

When you want a type that Swift would not pick, add a colon and the type name. This is called a **type annotation**. A `Double` with a whole value prints with `.0`, like `5.0`.

Why does `let price: Double = 5` work? The number `5` is a **literal**: a value written directly in your code. A number literal has no fixed type by itself. Swift gives it a type from where you use it, so here `5` becomes a `Double`.

<CodeExample title="Explicit conversion">

```swift
let wholeNumber: Int = 5
let decimalNumber: Double = 2.5

// Swift does not convert number types for you.
// We convert wholeNumber to Double before adding.
let total = Double(wholeNumber) + decimalNumber
print("Total: \(total)")
```

```output
Total: 7.5
```

</CodeExample>

Swift does not convert a constant or variable from one number type to another on its own. If you add an `Int` and a `Double` directly, the compiler stops with an error. You must write `Double(wholeNumber)` to make a new `Double` from the integer.

Literals follow a different rule. `let ratio = 3 + 0.5` works, because the literals `3` and `0.5` have no fixed type yet. Swift makes them both `Double`.

<CodeExample title="Giving a constant its value later">

```swift
let isMember = true
let discount: Int   // no value yet

if isMember {
    discount = 10
} else {
    discount = 0
}
print("Discount: \(discount)")
```

```output
Discount: 10
```

</CodeExample>

A constant does not need its value on the same line. An `if`/`else` statement runs one of two blocks of code, so here `discount` gets 10 or 0. The compiler checks three rules:

1. You must write the type, because there is no first value to infer it from.
2. The constant gets a value exactly once on every path through the code.
3. Code cannot read the constant before it has a value. If the `else` block were missing, the compiler would say "constant 'discount' used before being initialized".

## Interview traps

<Trap title="Assuming Swift converts numbers automatically">
In languages like C or Java, you can add an integer and a decimal number directly. Swift refuses to do this. Hidden conversions can cause errors that you do not see, so Swift makes every conversion visible. Write an explicit conversion like `Double(myInteger)` or `Int(myDouble)`. One exception exists: Swift converts between `Double` and `CGFloat`, a number type used in drawing code, for you.
</Trap>

<Trap title="Thinking let values must be known before compiling">
A `let` constant is not restricted to values you know while writing code. A `let` constant can store the result of a network call, a user tap, or a calculation. The only rule is that once you give it a value, you cannot change that value.
</Trap>

<Trap title="Single-letter text is not a Character by default">
When you write `let symbol = "A"`, Swift infers the `String` type, not `Character`. If an API requires a `Character`, you must use an explicit type annotation: `let symbol: Character = "A"`. To turn a `Character` back into a `String`, write `String(symbol)`.
</Trap>

## How to answer in the interview

<InterviewAnswer level="fresh">
In Swift, `let` declares a constant whose value cannot change after you assign it, while `var` declares a variable that can change. Apple recommends using `let` by default because it prevents accidental edits and makes code intent clear. Swift is also type-safe and uses type inference, so the compiler picks the correct type automatically from your initial value.
</InterviewAnswer>

<InterviewAnswer level="junior">
Using `let` by default makes code predictable and easier to reason about. It prevents changes by mistake, and the compiler even warns when a local `var` never changes. Constants are also safe to read from concurrent code, because no other code can change them at the same time. Swift does not convert number types for you, so `Int` and `Double` values need an explicit conversion. Number literals are different, because they get their type from the context.
</InterviewAnswer>

## Recap

<Recap>
- Use `let` by default for all values. Use `var` only when a value must change.
- Swift is type-safe. The compiler checks all types when it builds your code.
- Swift infers `Int`, `Double` (never `Float`), `String` (even for one letter) and `Bool`. Add a type annotation like `: Character` to choose another type.
- Swift does not convert number variables for you. Convert values explicitly with `Double(...)` or `Int(...)`.
- A `let` constant can get its value later, but exactly once, and before any code reads it.
</Recap>
