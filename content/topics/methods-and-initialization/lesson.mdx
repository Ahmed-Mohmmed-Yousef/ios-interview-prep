## The simple idea

<Analogy>
Think of a digital watch. The buttons on the side are methods. Pressing a button to view the date reads data. Pressing a button to adjust the time changes the watch state. When you insert a new battery, the watch runs its startup steps so all numbers start at a valid time.
</Analogy>

In Swift, a **method** is a function that belongs to a type. An **initializer** is a special method that sets up a new instance before you use it.

Swift types have two kinds of methods:
1. **Instance methods**: Functions called on an instance of a class, structure, or enumeration. They read and change that instance's own data.
2. **Type methods**: Functions called directly on the type itself. Use `static func` on any type, or `class func` on a class when subclasses should be able to override the method. Inside a type method, `self` refers to the type itself rather than an instance.

Because structures and enumerations are **value types**, an instance method cannot change their properties by default. Add **`mutating`** before `func` to allow changes, or even to assign a brand-new instance to `self`. Classes do not need `mutating` because classes are reference types.

**Initialization** makes sure every stored property has a valid value before an instance is used, preventing uninitialized memory access:
- Initializers use **`init`** and cannot return a value. A plain `return` can exit early once every property is set.
- If a struct or class gives default values to all properties and writes no custom `init`, Swift creates a default **`init()`** with no parameters.
- If a struct writes no custom `init` in its main body, Swift creates a **memberwise initializer** with labeled parameters for stored properties that need values. Properties with default values can be omitted, and a `let` constant that already has a value is left out. Classes do not get a memberwise initializer.
- A **failable initializer** (`init?`) returns an optional instance and writes `return nil` when setup fails.

## In code

<CodeExample title="Using mutating methods and memberwise initializers">

```swift
struct Point {
    var x: Double
    var y: Double

    mutating func moveBy(deltaX: Double, deltaY: Double) {
        x += deltaX
        y += deltaY
    }
}

// Automatic memberwise initializer
var location = Point(x: 2.0, y: 3.0)
location.moveBy(deltaX: 5.0, deltaY: 7.0)

print("Updated location: (\(location.x), \(location.y))")
```

```output
Updated location: (7.0, 10.0)
```

</CodeExample>

This example shows two key Swift behaviors:
- **Memberwise initializer**: `Point` automatically gets `init(x:y:)` without writing extra code.
- **`mutating` keyword**: `moveBy` modifies `x` and `y` (or could assign a new `Point` to `self`). Without `mutating`, the Swift compiler gives an error.

<CodeExample title="Custom initializers in extensions and failable initializers">

```swift
struct Size {
    var width: Double
    var height: Double
}

// Custom initializer declared in extension to preserve memberwise init
extension Size {
    init(square: Double) {
        self.init(width: square, height: square)
    }
}

let customSquare = Size(square: 12.0)
let memberwiseBox = Size(width: 8.0, height: 16.0)
print("Square: \(customSquare.width)x\(customSquare.height)")
print("Box: \(memberwiseBox.width)x\(memberwiseBox.height)")

struct Temperature {
    let celsius: Double

    init?(fahrenheit: Double) {
        if fahrenheit < -459.67 {
            return nil
        }
        self.celsius = (fahrenheit - 32.0) / 1.8
    }
}

let validTemp = Temperature(fahrenheit: 32.0)
let invalidTemp = Temperature(fahrenheit: -500.0)
print("Freezing: \(validTemp?.celsius ?? 0.0) C")
print("Invalid is nil: \(invalidTemp == nil)")
```

```output
Square: 12.0x12.0
Box: 8.0x16.0
Freezing: 0.0 C
Invalid is nil: true
```

</CodeExample>

This example shows how initializers provide flexibility:
- **Initializer delegation**: `init(square:)` calls `self.init(width:height:)` to avoid duplicating assignment logic.
- **Extensions**: Putting custom initializers in an `extension` preserves the automatic memberwise initializer.
- **Failable initializer**: `init?(fahrenheit:)` returns an optional instance, returning `nil` when the temperature falls below absolute zero.

## Interview traps

<Trap title="Calling a mutating method on a let struct instance">
Even if a struct method is marked `mutating`, you cannot call it on a struct declared with `let`. Because structs are value types, a constant instance freezes all properties completely. You must declare the instance with `var`.
</Trap>

<Trap title="Losing the memberwise initializer by defining custom inits in the struct body">
If you define a custom initializer inside the struct declaration, Swift removes the automatic memberwise initializer. To retain both initializers, declare your custom initializer inside an `extension`.
</Trap>

<Trap title="Expecting classes to require the mutating keyword">
The `mutating` keyword is only for value types (structures and enumerations). Classes are reference types. A class method can change variable properties without `mutating`, even when the instance is stored in a `let` constant.
</Trap>

## How to answer in the interview

<InterviewAnswer level="fresh">
Methods in Swift are functions that belong to a type. Struct methods that change properties need the mutating keyword because structs are value types. Swift structs automatically get a memberwise initializer for their stored properties when no custom init is in the struct body. Initializers set up an instance, and failable initializers return nil when input data is invalid.
</InterviewAnswer>

<InterviewAnswer level="junior">
Structs and enums are value types, so methods cannot change properties without mutating, and changes write back when the method ends. A mutating method can also replace self, and it requires a var instance. Structs automatically get a memberwise initializer, and putting custom initializers in an extension keeps both available. Failable initializers use init? and return an optional, so callers can check for nil instead of handling thrown errors.
</InterviewAnswer>

## Recap

<Recap>
- Instance methods run on an instance; type methods run on the type using `static` (or `class` in a class to allow overrides).
- On structs and enums, methods that change properties or reassign `self` need `mutating` and require a `var` instance.
- Classes are reference types, so their methods can change `var` properties without `mutating`, even on a `let` constant.
- Structs get a memberwise `init` unless you write a custom `init` in the struct body; put custom inits in an `extension` to keep it.
- Failable initializers (`init?`) return an Optional and use `return nil` when setup fails.
</Recap>
