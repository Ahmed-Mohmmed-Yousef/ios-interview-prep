## The simple idea

<Analogy>
Think of a digital bus timetable billboard at a street corner.
The transit agency does not pay a person to stand by the billboard and shout updates every minute.
Instead, the agency generates a schedule for the entire morning and loads it onto the billboard.
When the clock strikes eight, the billboard shows the eight-o'clock departure.
When a commuter taps the request button, a message sends to the dispatch center to update the bus schedule.
WidgetKit works like this timetable billboard by rendering pre-scheduled entries along a timeline.
</Analogy>

A **widget** gives users glanceable, timely information on their Home Screen, Lock Screen, or Mac desktop.
Widgets run in a separate extension process rather than inside your main application.
They do not stay alive continuously in device memory.
Instead, WidgetKit asks your widget extension for a **timeline** of entries.
Each entry contains a timestamp and the data model required to render a SwiftUI view.

### Timeline reload policies

When providing a timeline, your provider specifies a reload policy:
- `.atEnd`: iOS asks for a new timeline after the date of the last entry passes.
- `.after(Date)`: iOS schedules a timeline reload at or after a specific future date.
- `.never`: iOS does not automatically refresh the timeline. The widget updates only when your app or a push notification triggers a reload.

### The reload budget

iOS manages a daily **reload budget** for each widget to protect battery health.
Typically, iOS allows forty to seventy background updates each day.
Tapping interactive buttons or using the main app recharges this budget.

### App Intents for configuration and interactivity

Before iOS 17, widgets were read-only displays.
Tapping a widget opened the main app through a URL link.
With **App Intents**, you define Swift structs that represent user actions.
In iOS 17 and later, widgets support interactive buttons and toggles using `Button(intent:)`.
When tapped, the system runs the intent in the background without bringing your app to the foreground.
Users can also configure widget settings by selecting an intent that conforms to `WidgetConfigurationIntent`.

**Widgets display pre-rendered timelines, and App Intents allow users to configure data and trigger instant actions.**

## In code

### Creating a timeline of entries

In your timeline provider, generate a collection of `TimelineEntry` objects across future intervals.

```swift
import Foundation

struct WeatherEntry {
    let date: Date
    let temperature: Int
}

struct WeatherTimeline {
    static func generateHourlyEntries(startDate: Date, temperatures: [Int]) -> [WeatherEntry] {
        var entries: [WeatherEntry] = []
        for (index, temp) in temperatures.enumerated() {
            let entryDate = startDate.addingTimeInterval(Double(index * 3600))
            entries.append(WeatherEntry(date: entryDate, temperature: temp))
        }
        return entries
    }
}

let base = Date(timeIntervalSince1970: 1700000000)
let timeline = WeatherTimeline.generateHourlyEntries(startDate: base, temperatures: [68, 72, 70])

for entry in timeline {
    print("Temp: \(entry.temperature)")
}
```

```output
Temp: 68
Temp: 72
Temp: 70
```

iOS renders each entry automatically when its scheduled date arrives.

### Handling interactive buttons with AppIntent

Define an `AppIntent` to perform an action when the user taps a button in your widget.

```swift
import Foundation

struct CounterIntent {
    static func perform(currentCount: Int, step: Int) -> Int {
        let updated = currentCount + step
        print("Updated count: \(updated)")
        return updated
    }
}

let initialCount = 5
let newCount = CounterIntent.perform(currentCount: initialCount, step: 1)
print("Finished: \(newCount)")
```

```output
Updated count: 6
Finished: 6
```

In your widget view, attach this intent using `Button(intent:)`.
After changing shared data, call `WidgetCenter.shared.reloadTimelines(ofKind:)` to refresh the interface.

## Interview traps

<Trap title="Treating widgets like mini-apps">
Widgets do not support continuous loops, video playback, or touch gesture recognizers.
A `List` in a widget does not scroll like a normal iOS list.
If you need a live countdown timer, do not run a timer in code.
Instead, use `Text(date, style: .timer)`, which renders countdowns client-side in the system process.
</Trap>

<Trap title="Using UserDefaults.standard across extension boundaries">
Your widget extension runs in a separate sandbox container from your main app.
Reading `UserDefaults.standard` inside a widget returns empty values because it accesses a different storage file.
To share data between your main app and widget, configure an App Group in Xcode.
Then access your shared storage using `UserDefaults(suiteName: "group.com.example")`.
</Trap>

<Trap title="Exhausting the daily reload budget">
Requesting timeline reloads every minute quickly drains your daily budget.
Once the budget runs out, iOS ignores further background reload requests until the next day.
Always generate future timeline entries ahead of time instead of repeatedly requesting immediate reloads.
</Trap>
