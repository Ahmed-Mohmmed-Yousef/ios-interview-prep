## The simple idea

<Analogy>
Think of a traffic light. At any moment, the light is red, yellow, or green. It can never be purple. It cannot be red and green at the same time. An enumeration lets your code list those exact valid choices. If you pass an invalid choice, the compiler stops you right away.
</Analogy>

In Swift, an **enumeration** (usually called an **enum**) is a type that defines a fixed list of related choices.

Unlike enums in C or Objective-C, Swift enum cases do not get integer numbers by default. Each case is its own distinct value of that enum type.

Swift enums give you several helpful tools:
- **Type safety**: You cannot pass an invalid value by mistake.
- **Dot syntax**: When Swift already knows the enum type, you can write short names like `.north` or `.red`.
- **Exhaustive switch matching**: A `switch` statement must cover every case, so no case is missed.
- **Equality checks**: Simple enums work with `==` right away without extra code.
- **Associated values**: Each case instance can carry its own custom data at runtime.
- **Raw values**: Cases can share a fixed default value of the same type, like `Int` or `String`.

**Enums in Swift are value types.** When you assign an enum to a new variable or pass it to a function, Swift copies it.

## In code

<CodeExample title="Defining an enum, matching cases, and using CaseIterable">

```swift
enum CompassPoint: CaseIterable {
    case north
    case south
    case east
    case west
}

func describeDirection(_ direction: CompassPoint) -> String {
    switch direction {
    case .north:
        return "Heading toward the Arctic."
    case .south:
        return "Heading toward Antarctica."
    case .east:
        return "Heading toward the sunrise."
    case .west:
        return "Heading toward the sunset."
    }
}

let travelDirection: CompassPoint = .east
print(describeDirection(travelDirection))
print("Same direction: \(travelDirection == .east)")
print("Total directions: \(CompassPoint.allCases.count)")
```

```output
Heading toward the sunrise.
Same direction: true
Total directions: 4
```

</CodeExample>

This example shows the basics of a Swift enum:
- **Cases**: The `enum` keyword defines `CompassPoint`. You can write cases on separate lines or join them with commas on one line.
- **Dot syntax**: Because `travelDirection` has type `CompassPoint`, you can assign `.east` without repeating the type name.
- **Exhaustive switch**: The `switch` handles all four cases. If you leave one out without a `default` branch, the code will not compile.
- **Equality with `==`**: Enums without associated values support `==` automatically. Enums with associated values also support `==` if you add `Equatable` and all their inner types are `Equatable`.
- **`CaseIterable` and `allCases`**: Adding `: CaseIterable` to an enum without associated values gives you `allCases`, a collection of all its cases.

<CodeExample title="Associated values, raw values, properties, and methods">

```swift
enum Barcode {
    case upc(Int, Int, Int, Int)
    case qrCode(String)
}

func inspectBarcode(_ barcode: Barcode) -> String {
    switch barcode {
    case .upc(let numberSystem, let manufacturer, let product, let check):
        return "UPC: \(numberSystem)-\(manufacturer)-\(product)-\(check)"
    case let .qrCode(payload):
        return "QR: \(payload)"
    }
}

let code = Barcode.qrCode("https://apple.com")
print(inspectBarcode(code))

enum Planet: Int {
    case mercury = 1, venus, earth, mars
}

print("Earth position: \(Planet.earth.rawValue)")
let secondPlanet = Planet(rawValue: 2)
print("Second planet: \(secondPlanet == .venus)")

enum Theme: String {
    case light, dark
}
print("Theme raw value: \(Theme.dark.rawValue)")

enum TrafficLight {
    case red, yellow, green

    var waitSeconds: Int {
        switch self {
        case .red: return 30
        case .yellow: return 5
        case .green: return 0
        }
    }

    mutating func advance() {
        switch self {
        case .red: self = .green
        case .green: self = .yellow
        case .yellow: self = .red
        }
    }
}

var light = TrafficLight.red
print("Wait: \(light.waitSeconds)")
light.advance()
print("Next light: \(light)")
```

```output
QR: https://apple.com
Earth position: 3
Second planet: true
Theme raw value: dark
Wait: 30
Next light: green
```

</CodeExample>

This example shows how enums store extra data and add behavior:
- **Associated values**: `Barcode.qrCode` stores a `String`, and `.upc` stores four `Int` values. You extract them with `let` or `var` inside a `case`.
- **Raw values**: `Planet` uses `Int` as its raw-value type (raw types can be `Int`, `Double`, `String`, or `Character`). Swift adds 1 for each next `Int` case, so `earth` gets `3`.
- **Implicit `String` raw values**: In `Theme: String`, each case gets its own name as its raw value, so `Theme.dark.rawValue` is `"dark"`.
- **Failable initializer**: `Planet(rawValue: 2)` returns an optional `Planet?`. If you pass an unknown value like `99`, it returns `nil`.
- **Computed properties and methods**: Enums can have computed properties (like `waitSeconds`), instance methods, and `mutating` methods that change `self`.

## Interview traps

<Trap title="Assuming enums can have stored properties">
Swift enums can have computed properties and methods, but they cannot have stored properties. Writing `var name: String = "Test"` inside an enum causes a compile error. Store per-instance data using associated values instead.
</Trap>

<Trap title="Mixing raw values and associated values on the same enum">
An enum can use raw values, or it can use associated values. It cannot use both in the same enum. If an enum declares a raw type like `String`, none of its cases can have associated values.
</Trap>

<Trap title="Forgetting that init?(rawValue:) returns an Optional">
Developers often write `let planet: Planet = Planet(rawValue: 1)`. This fails to compile. Because a raw value might not match any case, `init?(rawValue:)` always returns an optional `Planet?`. Safely unwrap it with `if let` or `guard let`.
</Trap>

## How to answer in the interview

<InterviewAnswer level="fresh">
An enumeration in Swift defines a type for a fixed group of related choices. Unlike C enums, Swift enum cases do not get integer numbers by default unless you declare a raw-value type. Swift enums are value types. They work with exhaustive switch statements, equality checks, computed properties, methods, and associated values for custom per-instance data.
</InterviewAnswer>

<InterviewAnswer level="junior">
Swift enums model finite states safely with raw values and associated values. Raw values give every case a fixed compile-time value of one shared type, and you look them up with the failable initializer init?(rawValue:). Associated values attach custom runtime data to individual instances. Enums are value types that cannot hold stored properties, but they can define computed properties, instance methods, mutating methods, and conform to protocols like CaseIterable.
</InterviewAnswer>

## Recap

<Recap>
- Swift enums define a fixed set of related choices with strong type safety.
- Cases do not have integer values by default; each case is its own distinct value.
- Switch statements on enums must be exhaustive, which catches missing cases at compile time.
- Associated values let individual instances store custom runtime data.
- Raw values give cases fixed constants of one type (`Int`, `Double`, `String`, or `Character`).
- `init?(rawValue:)` returns an optional that is `nil` when no case matches.
- Enums are value types; they support computed properties, methods, `mutating` methods, and `CaseIterable`, but not stored properties.
</Recap>
