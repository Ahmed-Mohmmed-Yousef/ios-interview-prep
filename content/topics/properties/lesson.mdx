## The simple idea

<Analogy>
Think of your smartphone. The battery capacity is a stored value in hardware. The battery percentage on your screen is a computed value calculated from current voltage. A heavy app download is lazy because it only loads when you open it. A low battery alert is an observer that triggers when the charge drops.
</Analogy>

In Swift, **properties** connect values to a structure, class, or enumeration.

Swift provides three main kinds of properties:

1. **Stored properties**: Store constants (`let`) or variables (`var`) inside an instance. They allocate memory to hold data. Classes and structures support stored properties.
2. **Computed properties**: Do not store values directly. Instead, they provide a getter and an optional setter to calculate values on demand. Classes, structures, and enumerations support computed properties.
3. **Lazy stored properties**: Delay their initial calculation until the first time your code accesses them. This saves time and memory when work is expensive or not always needed.

Swift also provides **property observers**:
- **`willSet`**: Runs right before a stored property changes. It receives the upcoming value in `newValue`.
- **`didSet`**: Runs immediately after a stored property changes. It receives the previous value in `oldValue`.

## In code

<CodeExample title="Using computed properties and lazy stored properties">

```swift
struct Rectangle {
    var width: Double
    var height: Double

    var area: Double {
        width * height
    }
}

class Document {
    lazy var content: String = {
        print("Loading heavy content...")
        return "Complete report data"
    }()
}

let box = Rectangle(width: 8.0, height: 5.0)
print("Rectangle area: \(box.area)")

let doc = Document()
print("Document instance created.")
print("Document content: \(doc.content)")
```

```output
Rectangle area: 40.0
Document instance created.
Loading heavy content...
Document content: Complete report data
```

</CodeExample>

This example illustrates two core property patterns:
- **Computed property**: `area` calculates `width * height` dynamically. It does not allocate memory for a stored number. Computed properties must always be declared with `var`.
- **Lazy property**: `content` closure does not execute when `Document()` initializes. It runs only when `doc.content` is read for the first time.

<CodeExample title="Observing value changes with willSet and didSet">

```swift
struct StepTracker {
    var totalSteps: Int = 0 {
        willSet {
            print("About to set steps from \(totalSteps) to \(newValue)")
        }
        didSet {
            let difference = totalSteps - oldValue
            print("Added \(difference) new steps.")
        }
    }
}

var tracker = StepTracker()
tracker.totalSteps = 150
tracker.totalSteps = 400
```

```output
About to set steps from 0 to 150
Added 150 new steps.
About to set steps from 150 to 400
Added 250 new steps.
```

</CodeExample>

This example highlights how observers work:
- **`willSet`**: Runs before the new value is stored. `newValue` provides the incoming value.
- **`didSet`**: Runs after the assignment finishes. `oldValue` provides the previous value.
- **Initializers**: Property observers do not run when an instance is initially created.

## Interview traps

<Trap title="Declaring a lazy property with let">
A lazy property cannot be declared with `let`. The compiler produces an error. Because the value is assigned after the instance finishes initialization, a lazy property must always be declared with `var`.
</Trap>

<Trap title="Declaring a read-only computed property with let">
Candidates often think that a read-only computed property is a constant, so they write `let area: Double { ... }`. This triggers a compile error. Computed properties must always be declared with `var` because their value is evaluated dynamically.
</Trap>

<Trap title="Expecting observers to fire during initializers">
Property observers (`willSet` and `didSet`) do not execute when a property receives its initial value inside an `init` method. Swift suppresses observers during initialization to prevent accessing incomplete state.
</Trap>

## How to answer in the interview

<InterviewAnswer level="fresh">
In Swift, stored properties hold values directly in memory for classes and structs, while computed properties calculate values dynamically using getters and setters. Lazy properties defer their initialization until first access and must always use var. Property observers like willSet and didSet let you respond to value changes, but they do not run during initialization.
</InterviewAnswer>

<InterviewAnswer level="junior">
Swift properties separate storage from computation. Stored properties allocate instance memory, while computed properties execute code on demand and can be read-only or read-write. Lazy properties optimize memory and startup time by executing initializers on first access. Property observers provide clean hooks for state updates using implicit newValue and oldValue parameters without triggering during init.
</InterviewAnswer>

## Recap

<Recap>
- Stored properties save values in memory; provided by classes and structs.
- Computed properties calculate values on demand; provided by classes, structs, and enums.
- Read-only computed properties omit set and must always be declared with `var`.
- Lazy properties calculate their value only when first accessed; must always use `lazy var`.
- Property observers (`willSet` and `didSet`) observe changes on stored properties.
- `newValue` contains the upcoming value in `willSet`; `oldValue` contains the previous value in `didSet`.
- Property observers do not run during `init`.
</Recap>
