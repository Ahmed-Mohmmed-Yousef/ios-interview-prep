## The simple idea

<Analogy>
Think of control flow like train tracks and railroad switches. Most tracks run straight ahead in a loop. Some tracks reach a switch where the train is routed to a specific station based on its cargo. A guard rail acts like an emergency brake: if the track ahead is broken, the train stops immediately and diverts safely.
</Analogy>

In Swift, **control flow** structures determine the order in which code executes.

Swift provides three main categories of control flow:
- **Loops**: Repeat blocks of code using `for-in`, `while`, or `repeat-while`.
- **Conditional branching**: Choose branches using `if`, `if-else`, and `guard`.
- **Pattern matching**: Route complex values using `switch`.

Swift introduces powerful safety improvements over older languages:
1. **No integer booleans**: Conditions in `if` and `while` must evaluate to real `Bool` values. Writing `if count` fails to compile if `count` is an `Int`.
2. **Exhaustive switch**: Every possible value must be matched by a case, or a `default` case must be provided.
3. **No automatic fallthrough**: When a matching `switch` case finishes, execution ends immediately. You do not need to write `break` at the end of each case.

The **`guard`** statement requires a condition to be true to continue. If the condition is false, the `else` block must exit the current function or loop immediately using `return`, `throw`, or `break`. Any values unwrapped inside a `guard` remain available for the rest of the function scope.

## In code

<CodeExample title="Looping with for-in and repeat-while">

```swift
let items = ["Apples", "Pears", "Oranges"]
for (index, item) in items.enumerated() {
    print("\(index): \(item)")
}

var countdown = 3
repeat {
    print("Tick: \(countdown)")
    countdown -= 1
} while countdown > 0
```

```output
0: Apples
1: Pears
2: Oranges
Tick: 3
Tick: 2
Tick: 1
```

</CodeExample>

This example shows two common looping patterns:
- **`for-in` with `.enumerated()`**: Iterates through collections, producing a tuple of `(index, item)` for each element.
- **`repeat-while`**: Evaluates its condition after running the block. The block is guaranteed to execute at least once.

<CodeExample title="Pattern matching and where clauses in switch">

```swift
func describePoint(_ point: (Int, Int)) {
    switch point {
    case let (x, y) where x == y:
        print("Diagonal: (\(x), \(y))")
    case (let x, 0):
        print("X-axis: \(x)")
    default:
        print("Point: \(point)")
    }
}
describePoint((4, 4))
describePoint((2, 0))
```

```output
Diagonal: (4, 4)
X-axis: 2
```

</CodeExample>

Swift `switch` statements support advanced pattern matching:
- **Value binding (`let x`)**: Extracts inner components of tuples or values for use inside the case.
- **`where` clause**: Adds an extra boolean filter to check relationships between bound variables.
- **No fallthrough**: When a case matches, Swift executes that case and exits the switch automatically.

## Interview traps

<Trap title="Expecting automatic fallthrough in switch statements">
In C and JavaScript, switch cases fall through unless you write `break`. In Swift, cases never fall through automatically. If you want fallthrough behavior, you must explicitly write the `fallthrough` keyword.
</Trap>

<Trap title="Using integer values directly in if conditions">
In C-based languages, non-zero integers evaluate as true. In Swift, conditionals strictly require `Bool` expressions. Writing `if count` causes a compile error. Write `if count > 0` instead.
</Trap>

<Trap title="Creating deep pyramid indentation instead of guard let">
Nesting multiple `if let` statements creates deep indentation that makes code hard to read. Use `guard let` to handle missing data early and keep the happy path flat.
</Trap>

</InterviewAnswer>

## Recap

<Recap>
- Swift loops include `for-in`, `while`, and `repeat-while`.
- `repeat-while` always executes its block at least once.
- Conditionals strictly require `Bool` expressions; integers are not booleans.
- Swift switch statements are exhaustive; all cases must be covered or default used.
- Switch cases do not fall through automatically.
- Every switch case must contain at least one executable statement.
- The `guard` statement enforces early exit, keeping bound constants available in scope.
</Recap>
