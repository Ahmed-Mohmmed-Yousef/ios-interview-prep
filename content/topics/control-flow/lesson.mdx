## The simple idea

<Analogy>
Think of your code as a train on a track. A loop is a circle of track: the train goes round until a signal tells it to leave. A switch is a junction: it sends the train to exactly one station. A guard is a gate: if a check fails, the train cannot go past it.
</Analogy>

**Control flow** is the order in which your code runs. Swift gives you three groups of tools:
- **Loops** repeat code: `for-in`, `while` and `repeat-while`.
- **Conditions** choose a branch: `if`, `else` and `guard`.
- **Switch** compares one value with many patterns and runs one matching case.

Swift adds safety rules that C does not have:
1. **Conditions must be `Bool`.** Writing `if count` does not compile when `count` is an `Int`. Write `if count > 0`.
2. **A switch must be exhaustive.** Exhaustive means every possible value matches a case. If your cases do not cover every value, add a `default` case. A switch on a `Bool` with `true` and `false` cases needs no `default`.
3. **No automatic fallthrough.** When the matching case finishes, the whole switch ends. The program goes on after the switch. You do not write `break` at the end of each case.

A **`guard`** statement needs its condition to be true for the code after it to run. If the condition is false, the `else` block runs. That block must leave the current scope. It can use `return`, `break`, `continue` or `throw`, or call a function that never returns, like `fatalError`. A value that `guard let` unwraps stays available for the rest of the code block that contains the guard.

## In code

<CodeExample title="Loops with for-in, while and repeat-while">

```swift
let items = ["Apples", "Pears", "Oranges"]
for (index, item) in items.enumerated() {
    print("\(index): \(item)")
}

var stock = 2
while stock > 0 {
    print("Stock: \(stock)")
    stock -= 1
}

var countdown = 0
repeat {
    print("Tick: \(countdown)")
    countdown -= 1
} while countdown > 0
```

```output
0: Apples
1: Pears
2: Oranges
Stock: 2
Stock: 1
Tick: 0
```

</CodeExample>

- **`for-in`** goes through a sequence, such as an array, a range like `1...5`, or a string. `enumerated()` gives you each index with its item.
- **`while`** checks its condition **before** each pass. If the condition is false at the start, the body never runs.
- **`repeat-while`** checks its condition **after** each pass, so the body always runs at least once. Above, `countdown > 0` is false, but "Tick: 0" still prints.

<CodeExample title="break, continue and a labeled loop">

```swift
for n in 1...6 {
    if n == 2 { continue }   // skip the rest of this pass
    if n == 5 { break }      // leave the loop now
    print(n)
}

for score in [80, -1, 95] {
    guard score >= 0 else { continue }
    print("Score: \(score)")
}

grid: for row in 1...3 {
    for col in 1...3 {
        if col == 2 { continue grid }
        print("(\(row), \(col))")
    }
}
```

```output
1
3
4
Score: 80
Score: 95
(1, 1)
(2, 1)
(3, 1)
```

</CodeExample>

- **`continue`** stops the current pass and starts the next pass of the loop.
- **`break`** ends the loop at once. The program goes on after the loop's closing brace.
- A **labeled statement** gives a loop a name, like `grid:`. Without a label, `break` and `continue` only affect the inner loop. With `continue grid` or `break grid`, they affect the outer loop. You do not need an extra `Bool` flag to stop the outer loop.

<CodeExample title="Patterns in switch">

```swift
func describe(_ point: (Int, Int)) {
    switch point {
    case let (x, y) where x == y:
        print("Diagonal: \(x)")
    case (let x, 0):
        print("On the x-axis: \(x)")
    default:
        print("Other: \(point)")
    }
}
describe((4, 4))
describe((2, 0))

let letter: Character = "e"
switch letter {
case "a", "e", "i", "o", "u":
    print("Vowel")
default:
    break
}

let speed = 45
switch speed {
case 0..<30:
    print("Slow")
case 30...60:
    print("Normal")
default:
    print("Fast")
}
```

```output
Diagonal: 4
On the x-axis: 2
Vowel
Normal
```

</CodeExample>

- **Value binding (`let x`)** takes parts of a value, like the items of a tuple, so you can use them in the case.
- A **`where` clause** adds an extra `Bool` check. The case matches only when the pattern matches and the `where` check is true.
- A **compound case** like `case "a", "e":` lists several patterns with commas. It matches if any one of them matches. A long list can go over several lines.
- A **range pattern** like `case 30...60:` matches any value inside the range.
- **Every case needs at least one statement.** An empty case, or a case with only a comment, does not compile. To ignore a case on purpose, write `break` as its only statement.

<CodeExample title="if and switch as expressions">

```swift
let temperature = 25
let advice = if temperature >= 30 { "Stay cool" } else { "Enjoy the day" }
print(advice)

let code = 404
let message = switch code {
case 200..<300: "Success"
case 400..<500: "Client error"
default: "Other"
}
print(message)
```

```output
Enjoy the day
Client error
```

</CodeExample>

Since Swift 5.9, `if` and `switch` can also be **expressions**. An expression gives back a value, so you can assign the result to a constant. Each branch holds one value, and all branches must have the same type. An `if` expression needs an `else`, so that it always gives a value.

## Interview traps

<Trap title="Expecting automatic fallthrough in a switch">
In C, a case falls through to the next case unless you write `break`. In Swift, cases never fall through on their own. If you want this, write the `fallthrough` keyword at the end of the case. It moves into the next case **without checking that case's pattern**.
</Trap>

<Trap title="Using a number as a condition">
In C, an `if` accepts a number, and any value that is not zero counts as true. Swift requires a `Bool`. Writing `if count` with an `Int` is a compile error. Write `if count > 0` instead.
</Trap>

<Trap title="Thinking guard can only use return">
Many people think the `else` block of a `guard` must use `return`. Inside a loop, `continue` and `break` also work. You can also use `throw`, or call `fatalError`. The only rule is that the code must leave the scope.
</Trap>

<Trap title="Nesting many if let statements">
Putting `if let` inside `if let` pushes your main code far to the right and makes it hard to read. Use `guard let` to handle missing data first. Then your main code stays flat and easy to follow.
</Trap>

## How to answer in the interview

<InterviewAnswer level="fresh">
Swift has loops (`for-in`, `while` and `repeat-while`), conditions (`if` and `guard`) and `switch`. A Swift switch must cover every value, and its cases do not fall through by default. Conditions must be real `Bool` values. A `guard` exits early when a check fails, and the values it unwraps stay available after it.
</InterviewAnswer>

<InterviewAnswer level="junior">
Swift control flow focuses on safety checked by the compiler. A switch must be exhaustive and has no automatic fallthrough. Its cases can match ranges, tuples, several values and `where` checks. I use `guard` to leave early with `return`, `continue`, `break` or `throw`, so the main path stays flat. In nested loops, a label lets `break` or `continue` target the outer loop. Since Swift 5.9, I can also use `if` and `switch` as expressions to assign a value.
</InterviewAnswer>

## Recap

<Recap>
- Swift loops are `for-in`, `while` and `repeat-while`; `repeat-while` always runs at least once.
- `continue` starts the next pass, `break` ends the loop, and a label lets them target an outer loop.
- Conditions must be `Bool`; numbers do not count as true or false.
- A switch must be exhaustive, its cases do not fall through, and every case needs at least one statement.
- The `else` of a `guard` must leave the scope; values from `guard let` stay available after it.
</Recap>
