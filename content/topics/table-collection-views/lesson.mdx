## The simple idea

<Analogy>
Imagine a sushi restaurant with a conveyor belt.

There are only ten seats at the counter. The chef does not buy ten thousand new plates for every guest.

Instead, when a customer finishes eating, the chef washes the empty plate.

The chef places fresh sushi on that clean plate and serves the next guest.

That washed, reused plate is a **recycled cell**.
</Analogy>

In UIKit, `UITableView` displays single-column lists, while `UICollectionView` displays flexible grids and custom layouts.

Both rely on cell reuse to maintain fast scrolling performance.

Modern UIKit improves list building with two major technologies:

1. **Diffable Data Sources**:
   - Replaces manual index path calculations and batch reload crashes.
   - You apply a snapshot with your data models.
   - UIKit automatically calculates the differences and animates changes.
2. **Compositional Layout**:
   - Organizes layouts into four clear levels: Item, Group, Section, and Layout.
   - Supports multi-column grids and horizontal scrolling carousels without nesting collection views.

## In code

Here is how you populate a list using a diffable data source snapshot.

Items must conform to `Hashable` with unique identifiers.

<CodeExample title="Constructing a diffable data source snapshot">

```swift
import UIKit

enum Section: Hashable {
    case main
}

struct Item: Hashable {
    let id: Int
    let title: String
}

var snapshot = NSDiffableDataSourceSnapshot<Section, Item>()
snapshot.appendSections([.main])
snapshot.appendItems([
    Item(id: 1, title: "SwiftUI"),
    Item(id: 2, title: "UIKit")
])

print("Sections count: \(snapshot.numberOfSections)")
print("Items count: \(snapshot.numberOfItems)")
```

```output
Sections count: 1
Items count: 2
```

</CodeExample>

When you call `dataSource.apply(snapshot, animatingDifferences: true)`, UIKit animates the updates smoothly.

Next, observe how to build a two-column grid using compositional layout.

<CodeExample title="Building a grid with compositional layout">

```swift
import UIKit

let itemSize = NSCollectionLayoutSize(
    widthDimension: .fractionalWidth(0.5),
    heightDimension: .fractionalHeight(1.0)
)
let item = NSCollectionLayoutItem(layoutSize: itemSize)

let groupSize = NSCollectionLayoutSize(
    widthDimension: .fractionalWidth(1.0),
    heightDimension: .absolute(100)
)
let group = NSCollectionLayoutGroup.horizontal(
    layoutSize: groupSize,
    repeatingSubitem: item,
    count: 2
)
let section = NSCollectionLayoutSection(group: group)
let layout = UICollectionViewCompositionalLayout(section: section)

print("Fractional width: \(itemSize.widthDimension.isFractionalWidth)")
print("Group absolute height: \(groupSize.heightDimension.isAbsolute)")
```

```output
Fractional width: true
Group absolute height: true
```

</CodeExample>

Fractional dimensions adapt automatically to screen size changes.

## Interview traps

<Trap title="Non-unique items in diffable snapshots">
Appending two items with the same identifier to a snapshot causes an assertion crash.

Diffable data sources rely on unique hashes to calculate animations.

Always provide unique identifiers for every item in the snapshot.
</Trap>

<Trap title="Missing prepareForReuse cleanup">
If you do not cancel image downloads in `prepareForReuse`, fast scrolling shows wrong images.

A delayed network task can complete and overwrite newly assigned content on a recycled cell.

Cancel background tasks and clear image views inside `prepareForReuse`.
</Trap>

<Trap title="Heavy computation in cell provider closures">
Parsing JSON or calculating expensive data inside cell providers drops the scrolling frame rate.

Cell configuration must run fast on the main thread.

Prepare your data models before applying the snapshot.
</Trap>

<Trap title="Nesting collection views for carousels">
Embedding a collection view inside a table cell creates complex gesture and memory bugs.

Use `UICollectionViewCompositionalLayout` instead.

Set `section.orthogonalScrollingBehavior = .continuous` to add horizontal scrolling rows easily.
</Trap>

## Recap

<Recap>
- Cell reuse recycles off-screen views to maintain high scrolling performance.
- Clean up previous cell state and cancel pending downloads in `prepareForReuse`.
- Diffable data sources replace index path math with type-safe `Hashable` snapshots.
- `NSDiffableDataSourceSnapshot` computes insertions, deletions, and moves automatically.
- Compositional layout organizes screens into Items, Groups, Sections, and Layouts.
- Orthogonal scrolling creates horizontal carousels without nesting collection views.
</Recap>
