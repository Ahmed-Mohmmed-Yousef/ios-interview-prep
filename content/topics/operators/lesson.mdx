## The simple idea

<Analogy>
Think of operators like tools in a toolbox. Some tools work on a single item, like flipping a light switch on or off. Other tools combine two items, like a scale comparing two weights. Identity comparison is like checking national passport numbers. Two passports might contain the same name, but only identical passport numbers prove they belong to the exact same person.
</Analogy>

In Swift, an **operator** is a special symbol or phrase that checks, changes, or combines values.

Swift groups operators by how many values they target:
- **Unary operators** work on a single target, such as `-count` or `!isReady`.
- **Binary operators** work on two targets, such as `a + b` or `x == y`.
- **Ternary operators** work on three targets. Swift has only one ternary operator: `condition ? answer1 : answer2`.

In older languages like C, writing `if x = y` accidentally assigns a new value instead of checking equality. Swift prevents this entire category of bugs. In Swift, the assignment operator `=` **does not return a value**. If you write `if x = y`, the compiler stops you with an immediate error.

Swift also protects you from arithmetic overflow. If a math calculation exceeds the maximum allowed integer size, Swift stops the application safely rather than producing corrupt numbers.

## In code

<CodeExample title="Closed and half-open range operators">

```swift
let closedRange = 1...3
print("Closed contains 3: \(closedRange.contains(3))")

let halfOpenRange = 1..<3
print("Half-open contains 3: \(halfOpenRange.contains(3))")

let countdown = (1...3).reversed()
for number in countdown {
    print(number)
}
```

```output
Closed contains 3: true
Half-open contains 3: false
3
2
1
```

</CodeExample>

Swift provides two primary range operators:
- **Closed range operator (`a...b`)**: Runs from `a` up to and including `b`. The lower bound must be less than or equal to the upper bound.
- **Half-open range operator (`a..<b`)**: Runs from `a` up to but not including `b`. This range is useful for zero-indexed collections.

To count backwards, reverse a valid range using `.reversed()`.

<CodeExample title="Ternary conditional and nil-coalescing">

```swift
let score = 85
let message = score >= 70 ? "Passed" : "Try again"
print("Status: \(message)")

let customName: String? = nil
let defaultName = "Guest"
let activeUser = customName ?? defaultName
print("User: \(activeUser)")
```

```output
Status: Passed
User: Guest
```

</CodeExample>

This example shows two common expressive operators:
- **Ternary conditional operator (`condition ? a : b`)**: Evaluates a boolean condition. It returns `a` when true, or `b` when false.
- **Nil-coalescing operator (`??`)**: Unwraps an optional value if it contains a value. If the optional is `nil`, it evaluates and returns the right-hand default value.

The nil-coalescing operator uses **short-circuit evaluation**. If the optional contains a value, Swift never evaluates the right-hand side.

## Interview traps

<Trap title="Assuming closed ranges can count backwards directly">
Writing `5...1` causes a fatal runtime crash. In Swift, range bounds must satisfy `lowerBound <= upperBound`. To count down from 5 to 1, write `(1...5).reversed()`.
</Trap>

<Trap title="Confusing value equality == with reference identity ===">
The `==` operator checks whether two values are equal according to their data. The `===` operator checks whether two references point to the exact same class object in memory. Value types like structs do not support `===`.
</Trap>

<Trap title="Expecting assignment to return the assigned value">
In languages like C or JavaScript, assignment expressions return the assigned value. In Swift, assignment returns `Void`. Writing `if let x = y` is valid optional binding, but `if x = y` fails to compile.
</Trap>

## How to answer in the interview

Operators in Swift are symbols that check, modify, or combine values. Swift provides standard arithmetic, comparison, and logical operators, along with helpful range and nil-coalescing operators. A key safety feature is that assignment does not return a value, preventing accidental assignment errors in conditional statements. We use `==` for value equality and `===` for reference identity.
</InterviewAnswer>

<InterviewAnswer level="junior">
Swift operators emphasize safety and expressive clarity. The compiler prevents integer overflow crashes by default and rejects assignment in boolean conditions. Swift offers the closed range `a...b` and the half-open range `a..<b`, both requiring the lower bound to precede the upper bound. The nil-coalescing operator `??` unwraps optionals with short-circuit evaluation, ensuring the fallback expression only runs when the optional is nil.
</InterviewAnswer>

## Recap

<Recap>
- Swift categorizes operators into unary, binary, and ternary types.
- The assignment operator `=` returns `Void` to eliminate accidental assignments inside conditions.
- Arithmetic operators check for overflow by default and prevent silent data corruption.
- Closed ranges `a...b` include both ends, while half-open ranges `a..<b` exclude the upper end.
- Closed ranges require the lower bound to be less than or equal to the upper bound.
- The `==` operator tests value equality, while `===` tests whether references point to the same object instance.
- The nil-coalescing operator `??` unwraps an optional or provides a fallback using short-circuit evaluation.
</Recap>
