## The simple idea

<Analogy>
Think of a string like a beaded necklace. Some beads are small and round. Other beads are large and made of several parts joined together. You cannot find the fourth bead with a ruler because beads have different sizes. To reach the fourth bead, you must slide your fingers along the necklace bead by bead from the start.
</Analogy>

In Swift, a **`String`** is a value type (a struct) that holds an ordered group of **`Character`** values. Because it is a value type, assigning or passing a string gives each variable its own independent text. Behind the scenes, Swift uses **Copy-on-Write (COW)**: copies share the same memory buffer until one of them changes, which avoids unneeded memory copies.

In older languages, each character often takes a fixed number of bytes. In modern Unicode text, characters vary in size:
- An English letter like `"A"` needs 1 byte in UTF-8.
- An accented letter like `"é"` can be made of `"e"` plus a combining accent mark.
- A flag emoji like `"🇺🇸"` joins two regional indicator symbols.
- A family emoji like `"👨‍👩‍👧‍👦"` joins four people with invisible joiner characters and takes 25 bytes in UTF-8.

Swift measures text using **extended grapheme clusters**. An extended grapheme cluster is one or more Unicode scalars that form one human-readable character.

When you compare strings with `==`, Swift checks **canonical equivalence**. Two strings match if their visual characters have the same meaning, even when built from different Unicode scalars. For example, `"cafe\u{301}"` (decomposed `e` plus accent) equals `"café"` (precomposed `é`).

Because characters take different byte sizes, Swift cannot jump to the nth character without walking from the start. So Swift blocks `text[0]` at compile time and uses **`String.Index`** instead.

You can also write **multi-line string literals** inside three quotes (`"""`). The spaces before the closing `"""` set the base margin, so matching leading spaces are stripped from every line. Add a backslash `\` at the end of a line to join lines without adding a line break.

## In code

<CodeExample title="Inspecting characters and using String.Index">

```swift
let greeting = "Café ☕️"
print("Empty: \(greeting.isEmpty), count: \(greeting.count)")

let firstIndex = greeting.startIndex
let secondIndex = greeting.index(after: firstIndex)
let lastIndex = greeting.index(before: greeting.endIndex)
print("First: \(greeting[firstIndex]), second: \(greeting[secondIndex]), last: \(greeting[lastIndex])")

let thirdIndex = greeting.index(firstIndex, offsetBy: 2)
print("Third: \(greeting[thirdIndex])")
```

```output
Empty: false, count: 6
First: C, second: a, last: ☕️
Third: f
```

</CodeExample>

This example shows how to check and move through characters:
- **`isEmpty`**: Checks if a string has zero characters in fast `O(1)` time. Use `isEmpty` instead of `count == 0`, because `count` must walk every character in `O(n)` time.
- **`startIndex`**: Points to the first character in a non-empty string.
- **`endIndex`**: Points to the position **after** the last character. Reading `greeting[greeting.endIndex]` crashes at runtime, so use `greeting.index(before: greeting.endIndex)` for the last character.
- **`index(after:)` and `index(_:offsetBy:)`**: Safely move a `String.Index` forward across characters of any byte size.

<CodeExample title="Multi-line strings, interpolation, and canonical equivalence">

```swift
let level = 5
let note = """
    Level: \(level * 2), \
    ready!
    """
print(note)
print("cafe\u{301}" == "café")
```

```output
Level: 10, ready!
true
```

</CodeExample>

This example shows three everyday string tools:
- **String interpolation (`\(...)`)**: Runs an expression like `level * 2` and inserts its text right inside the string.
- **Multi-line strings (`"""`)**: Strips the four leading spaces that match the closing `"""`. The trailing `\` removes the line break between the two lines.
- **Canonical equivalence**: `"cafe\u{301}"` and `"café"` compare as `true` with `==` because they represent the same visual characters.

<CodeExample title="Slicing strings and managing Substring memory">

```swift
let logEntry = "ERROR: Network timed out"
if let colonIndex = logEntry.firstIndex(of: ":") {
    let tagSubstring = logEntry[..<colonIndex]
    let afterColon = logEntry.index(after: colonIndex)
    let messageSubstring = logEntry[afterColon...]
    print("Tag: \(String(tagSubstring))")
    print("Message:\(String(messageSubstring))")
}
```

```output
Tag: ERROR
Message: Network timed out
```

</CodeExample>

When you slice a string with a range, Swift returns a **`Substring`** instead of a new `String`:
- A `Substring` shares the memory buffer of the original string, so slicing is fast.
- If you keep a `Substring` for a long time, the whole original string stays in memory.
- Convert a slice into a standalone `String` with `String(tagSubstring)` before saving it long-term, so the original buffer can be freed.

## Interview traps

<Trap title="Subscripting strings with integers or endIndex">
Writing `text[0]` fails to compile because characters have variable byte lengths. Writing `text[text.endIndex]` compiles, then crashes at runtime because `endIndex` points past the last character. Use `text.startIndex`, `text.index(after:)`, or `text.index(before: text.endIndex)`.
</Trap>

<Trap title="Holding Substrings in long-lived data models">
Slicing a 5-character word from a 10-megabyte text file keeps all 10 megabytes in memory. Always convert the slice with `String(slice)` before storing it in a long-lived property.
</Trap>

<Trap title="Assuming string count equals byte count">
A single emoji can take 25 bytes or more in UTF-8 memory, while `string.count` returns `1`. Never assume character count equals byte length when reading files or network data.
</Trap>

<InterviewAnswer level="junior">
Swift strings focus on Unicode correctness. Length is measured in extended grapheme clusters rather than raw UTF-8 bytes, so `count` takes `O(n)` time and `isEmpty` is the fast `O(1)` check. Integer indexing is blocked at compile time to prevent hidden `O(n)` loops, and `String.Index` makes traversal explicit. Strings are value types optimized with Copy-on-Write, so copies share buffers until mutated. Slicing returns a `Substring` to avoid extra copying, and long-lived slices should be converted with `String(...)` so the large parent buffer can be freed.
</InterviewAnswer>

## Recap

<Recap>
- Swift strings are value types that use Copy-on-Write (COW) to share memory until mutated.
- A `Character` is an extended grapheme cluster of one or more Unicode scalars, and `==` checks canonical equivalence.
- `count` measures visual characters in `O(n)` time; use `isEmpty` for a fast `O(1)` empty check.
- Integer indexing `text[0]` does not compile, and `text[text.endIndex]` crashes because `endIndex` is past the last character.
- Navigate strings with `startIndex`, `endIndex`, `index(after:)`, `index(before:)`, and `index(_:offsetBy:)`.
- Multi-line strings `"""` strip indentation matching the closing `"""`, and trailing `\` joins lines.
- Slicing returns a `Substring` sharing the parent buffer; convert to `String(...)` for long-term storage.
</Recap>
