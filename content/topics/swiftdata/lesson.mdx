## The simple idea

<Analogy>
Imagine a busy office warehouse.
The **ModelContainer** is the heavy steel building with shelves and filing cabinets where records rest safely on disk.
The **ModelContext** is the desk where a clerk works on open files.
The clerk takes documents out of the cabinets, edits numbers on paper, or adds new folders.
None of those edits reach the permanent cabinets until the clerk files them away into storage.
In SwiftUI, **@Query** is a window on the office wall: whenever files in the cabinet change, the view on the wall updates at once.
</Analogy>

**SwiftData** is Apple modern framework for saving data permanently on Apple devices.
It replaces complex XML configuration files with native Swift code and Swift macros.
Underneath, SwiftData uses the proven SQLite storage engine from Core Data.

The framework is built around four primary parts:

1. **`@Model`**: A macro that decorates a standard Swift class. It turns the class into a stored entity. It tracks changes to properties and provides identity.
2. **`ModelContainer`**: The manager for your database storage. It handles the database schema, migration rules, and the storage file on disk.
3. **`ModelContext`**: The in-memory scratchpad. You insert new models, delete unwanted models, and save updates through this context.
4. **`@Query`**: A SwiftUI property wrapper that fetches models directly into views. It watches the context and refreshes the view when data changes.

### Modeling data and relationships

You define your data schema with standard Swift types:

- **Attributes**: Properties store simple types like `String`, `Int`, or `Date`. You can add `@Attribute(.unique)` to require unique values across all rows.
- **Relationships**: A model can link to another model. You can write `@Relationship(deleteRule: .cascade)` so deleting a parent also deletes child items.
- **Predicates**: You write search filters with the `#Predicate` macro. The Swift compiler checks these filters at compile time.

### Concurrency and actors

Persistent models are reference types and do not conform to `Sendable`.
You must never pass a model instance across different threads or actors.
To do work in the background, use a **`ModelActor`** or pass the model's **`PersistentIdentifier`**.
The background task uses the identifier to fetch its own copy inside its isolated context.

**SwiftData combines the power of Core Data with the safety and simplicity of modern Swift.**

## In code

### Creating a model and saving data in memory

Set up an in-memory `ModelContainer`, create a `ModelContext`, insert an item, and fetch it with `FetchDescriptor`.

```swift
import Foundation
import SwiftData

@Model
final class TaskItem {
    var title: String
    var isDone: Bool

    init(title: String, isDone: Bool = false) {
        self.title = title
        self.isDone = isDone
    }
}

let configuration = ModelConfiguration(isStoredInMemoryOnly: true)
let container = try ModelContainer(for: TaskItem.self, configurations: configuration)
let context = ModelContext(container)

let task = TaskItem(title: "Build app", isDone: true)
context.insert(task)
try context.save()

let descriptor = FetchDescriptor<TaskItem>()
let items = try context.fetch(descriptor)
print("Saved count: \(items.count)")
```

```output
Saved count: 1
```

Setting `isStoredInMemoryOnly` to `true` is helpful for unit tests and SwiftUI previews because it creates no disk files.

### Filtering records with compile-time predicates

Use the `#Predicate` macro to create type-safe search filters.

```swift
import Foundation
import SwiftData

@Model
final class TaskItem {
    var title: String
    var isDone: Bool

    init(title: String, isDone: Bool = false) {
        self.title = title
        self.isDone = isDone
    }
}

let configuration = ModelConfiguration(isStoredInMemoryOnly: true)
let container = try ModelContainer(for: TaskItem.self, configurations: configuration)
let context = ModelContext(container)

context.insert(TaskItem(title: "Write tests", isDone: true))
context.insert(TaskItem(title: "Ship build", isDone: false))
try context.save()

let predicate = #Predicate<TaskItem> { item in
    item.isDone == true
}
let descriptor = FetchDescriptor<TaskItem>(predicate: predicate)
let completedTasks = try context.fetch(descriptor)

for item in completedTasks {
    print("Done: \(item.title)")
}
```

```output
Done: Write tests
```

The `#Predicate` macro checks property names and types when building, stopping syntax errors before your app runs.

## Interview traps

<Trap title="Passing @Model instances across actors or threads">
SwiftData models are classes and do not conform to `Sendable`.
If you pass a model instance from the main thread into a background task, you create a data race.
This pattern can crash your app or corrupt your database.
Instead, pass the `PersistentIdentifier` of the model to the background actor, and fetch the object inside the actor's context.
</Trap>

<Trap title="Declaring SwiftData models as structs">
SwiftData requires reference identity so the context can track changes to properties.
If you attach `@Model` to a struct, the Swift compiler emits an error.
Always declare your persistent models as classes.
</Trap>

<Trap title="Confusing ModelContainer with ModelContext">
Developers often confuse the store manager with the working scratchpad.
The `ModelContainer` configures the database on disk and handles migrations.
The `ModelContext` performs day-to-day work like inserting, deleting, and saving objects.
You can have multiple contexts backed by a single container.
</Trap>

For schema management, SwiftData provides `@Attribute(.unique)` and `@Relationship(deleteRule:)`, with automatic migrations backed by SQLite.
