## The simple idea

<Analogy>
Imagine having an expert editor who sits directly at your desk.
You do not need to put your secret letters into envelopes, pay courier postage, or wait for the mail truck.
Your editor reads your drafts right in your office and suggests improvements without anyone else seeing your notes.
If you need an answer that requires an entire library, your editor consults a private locked vault.
The vault answers the single question and destroys all scratch paper immediately.
Apple on-device AI acts like this editor, keeping your personal notes private while delivering fast answers.
</Analogy>

**On-device foundation models** run directly on Apple Silicon using the Apple Neural Engine.
Traditional cloud AI models require sending text, images, and user prompts across the internet to remote servers.
In contrast, on-device models offer distinct advantages:
1. **Complete Privacy**: Personal text and sensitive user data never leave the user's iPhone or Mac.
2. **Zero Network Latency**: Models process prompts locally even when the device is completely offline.
3. **No Per-Request Costs**: Running on-device models does not incur cloud server or token subscription fees.

### Private Cloud Compute

When a complex task requires a larger model than fits on a phone, Apple uses **Private Cloud Compute**.
Private Cloud Compute runs larger models on dedicated Apple Silicon servers.
These servers never store user data and allow independent security researchers to inspect their software.

### System Writing Tools

In iOS 18 and later, Apple integrates on-device models into standard UI text controls.
Users can proofread, rewrite, and summarize text using built-in Writing Tools in `UITextView` and `WKWebView`.
Developers can control this behavior using the `writingToolsBehavior` property.

**On-device foundation models deliver fast, private, and offline intelligence powered by Apple Silicon hardware.**

## In code

### Classifying emotional tone with on-device sentiment analysis

Use the `NaturalLanguage` framework to analyze text sentiment on-device without cloud API dependencies.

```swift
import Foundation
import NaturalLanguage

func analyzeTone(text: String) -> String {
    let tagger = NLTagger(tagSchemes: [.sentimentScore])
    tagger.string = text
    let range = text.startIndex..<text.endIndex
    var scoreValue: Double = 0.0

    tagger.enumerateTags(in: range, unit: .paragraph, scheme: .sentimentScore, options: [.omitWhitespace]) { tag, _ in
        if let tag = tag, let score = Double(tag.rawValue) {
            scoreValue = score
        }
        return true
    }

    if scoreValue > 0.2 {
        return "Positive"
    } else if scoreValue < -0.2 {
        return "Negative"
    }
    return "Neutral"
}

let feedback = "This application is wonderfully fast and delightful to use!"
let tone = analyzeTone(text: feedback)
print("Feedback tone: \(tone)")
```

```output
Feedback tone: Positive
```

The tagger scores text from `-1.0` (very negative) to `1.0` (very positive).

### Detecting languages and routing prompts with async tasks

Always run machine learning inference and language detection asynchronously to keep the main thread responsive.

```swift
import Foundation
import NaturalLanguage

func identifyLanguage(input: String) async -> String {
    let recognizer = NLLanguageRecognizer()
    recognizer.processString(input)
    if let language = recognizer.dominantLanguage {
        return language.rawValue
    }
    return "unknown"
}

let sampleText = "Swift concurrency makes asynchronous code clean and safe."
let detected = await identifyLanguage(input: sampleText)
print("Language code: \(detected)")
```

```output
Language code: en
```

Using `async` functions ensures heavy text analysis does not cause frame drops during animations.

## Interview traps

<Trap title="Running model inference on the main thread">
Machine learning inference requires significant processing from the Neural Engine and GPU.
Executing inference synchronously on the main thread causes hitching and freezes the user interface.
Always run model inference inside asynchronous tasks using Swift concurrency.
</Trap>

<Trap title="Forgetting to pause cloud sync during Writing Tools sessions">
When a user activates Writing Tools, the system rewrites text directly inside the text container.
If your app performs active background sync (like CloudKit or Core Data synchronization), incoming updates can collide with the active rewrite.
Implement `textViewWritingToolsWillBegin` in your delegate to pause sync until `textViewWritingToolsDidEnd` fires.
</Trap>

<Trap title="Allowing Writing Tools on sensitive or code fields">
Not all text inputs should be rewritten by foundation models.
Fields containing passwords, credit card numbers, or markdown code blocks should disable Writing Tools.
Set `writingToolsBehavior = .none` on these fields to protect user security and prevent corrupted code syntax.
</Trap>
